# CI 流水线与代码质量

> 一句话定位：把格式、静态检查、测试、构建、安全扫描和镜像发布固化成 GitHub Actions 流水线，用分支保护让「能合并」严格等价于「质量达标」。

## 本篇目标

- 设计 lint → test → build → security → docker → release 六段式流水线
- 配好 golangci-lint（errcheck/govet/staticcheck/gosec/revive/misspell）与 `govulncheck`
- 建立覆盖率门槛、语义化版本、PR 门禁与分支保护

## 前置知识

- [07-工程化与测试/03-单元测试与集成测试](03-单元测试与集成测试.md)：build tag 与测试分层；[08-部署与运维/02-Docker镜像与多阶段构建](../08-部署与运维/02-Docker镜像与多阶段构建.md)：镜像构建

## 一、阶段设计

```text
fmt/vet/lint ─┐
test(-race)   ├─→ build(矩阵) ─→ security(govulncheck+镜像扫描) ─→ docker ─→ release(仅 tag)
contract      ┘
```

- lint 与 test 并行；build 依赖两者成功，失败不产出任何制品
- security 在构建后跑，因为 `govulncheck` 要基于真实依赖图与编译结果
- release 只允许受保护分支上的 tag 触发；缓存依赖与构建缓存，但绝不缓存测试结果

## 二、本地基线

本地与 CI 共用 [工程工具链全景](../06-Gin进阶/01-工程工具链全景.md) 的 Makefile（`make fmt vet lint test build`），CI 直接调用同一组命令，避免「本地绿、CI 红」。格式检查只列不改（CI 里执行 `gofmt -w` 会让脏格式永远进主干）：

```bash
test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }
```

```powershell
$files = gofmt -l .
if ($files) { $files; exit 1 }
```

## 三、golangci-lint 配置

项目根目录 `.golangci.yml`（v2 语法；工具版本必须锁死，否则新规则会让历史代码突然全红）：

```yaml
version: "2"
run:
    timeout: 5m
linters:
    default: standard          # 含 errcheck、govet、staticcheck、ineffassign、unused
    enable: [gosec, revive, misspell, bodyclose, errorlint, gocritic]
    settings:
        gosec:
            excludes: [G404]   # 允许非安全场景使用 math/rand
        revive:
            rules:
                - {name: exported, disabled: true}
    exclusions:
        rules:
            - {path: _test\.go, linters: [errcheck, gosec]}
formatters:
    enable: [gofmt, goimports]
```

只对新增代码报错可避免历史债务阻塞 PR：`golangci-lint run --new-from-rev=origin/main ./...`。

## 四、GitHub Actions 全流程

```yaml
# .github/workflows/ci.yml
name: ci
on:
    push: {branches: [main], tags: ["v*"]}
    pull_request:
permissions: {contents: read}
concurrency: {group: "ci-${{ github.ref }}", cancel-in-progress: true}
env:
    GOLANGCI_LINT_VERSION: v2.5.0

jobs:
    lint:
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v4
            - uses: actions/setup-go@v5
              with: {go-version-file: go.mod, cache: true}
            - run: go vet ./...
            - uses: golangci/golangci-lint-action@v7
              with: {version: "${{ env.GOLANGCI_LINT_VERSION }}"}
    test:
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v4
            - uses: actions/setup-go@v5
              with: {go-version-file: go.mod, cache: true}
            - run: go test -race -shuffle=on -covermode=atomic -coverprofile=coverage.out ./...
            - run: bash scripts/check-coverage.sh 70
            - uses: actions/upload-artifact@v4
              with: {name: coverage, path: coverage.out}
    build:
        needs: [lint, test]
        strategy:
            matrix:
                include:
                    - {goos: linux, goarch: amd64}
                    - {goos: linux, goarch: arm64}
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v4
            - uses: actions/setup-go@v5
              with: {go-version-file: go.mod, cache: true}
            - run: |
                  CGO_ENABLED=0 GOOS=${{ matrix.goos }} GOARCH=${{ matrix.goarch }} \
                    go build -trimpath -ldflags "-s -w" -o bin/gateway-${{ matrix.goarch }} ./app/gateway/cmd
            - uses: actions/upload-artifact@v4
              with: {name: "bin-${{ matrix.goarch }}", path: bin/}
    security:
        needs: build
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v4
            - uses: actions/setup-go@v5
              with: {go-version-file: go.mod, cache: true}
            - run: go install golang.org/x/vuln/cmd/govulncheck@latest && govulncheck ./...
            - uses: aquasecurity/trivy-action@0.28.0
              with: {scan-type: fs, severity: "CRITICAL,HIGH", exit-code: "1"}
```

## 五、覆盖率门槛脚本

不设门槛的覆盖率只是装饰。脚本读 `total:` 行并用 `awk` 比较，低于阈值直接非零退出：

```bash
#!/usr/bin/env bash
# scripts/check-coverage.sh
set -euo pipefail
threshold="${1:-70}"
total=$(go tool cover -func=coverage.out | awk '/^total:/ {gsub("%", "", $3); print $3}')
awk -v t="$total" -v m="$threshold" 'BEGIN { if (t + 0 < m + 0) { printf "coverage %s%% < %s%%\n", t, m; exit 1 } }'
```

## 六、Docker 与发布制品

```yaml
    docker:
        needs: [security]
        if: github.event_name == 'push'
        runs-on: ubuntu-latest
        steps:
            - uses: actions/checkout@v4
            - uses: docker/setup-buildx-action@v3
            - uses: docker/login-action@v3
              with: {registry: ghcr.io, username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}"}
            - uses: docker/build-push-action@v6
              with:
                  push: true
                  tags: "ghcr.io/mall-lite/gateway:${{ github.ref_name }}"
                  labels: {org.opencontainers.image.version: "${{ github.ref_name }}", org.opencontainers.image.revision: "${{ github.sha }}"}
```

```yaml
    release: # tag 触发，只发已通过 security 的产物
        needs: [docker]
        if: startsWith(github.ref, 'refs/tags/v')
        steps:
            - uses: softprops/action-gh-release@v2
              with: {files: "bin/*"}
```

版本规则：`feat` → minor，`fix/perf` → patch，`BREAKING CHANGE` → major；提交信息用约定式 `feat(order): add aggregate API`。打 tag 后由 `git-chglog` 生成 CHANGELOG，Release 页附上 `linux/amd64`、`linux/arm64` 两个二进制与校验和。

## 七、PR 门禁与分支保护

PR 模板里放可勾选清单，GitHub 会渲染成复选框：

```text
- [ ] 通过 make fmt vet lint test，新增逻辑有单测，覆盖率不低于 70%
- [ ] proto 变更已重新生成并通过 buf breaking
- [ ] 无明文密钥、无调试日志，已确认回滚方案
```

`main` 的分支保护必须开启：禁止直推与 force push、要求 PR + 至少 1 个 approve、要求 `lint`/`test`/`build`/`security` 四个检查通过、要求分支与主干同步、开启线性历史（squash 合并）、用 `CODEOWNERS` 指定 `api/`、`deploy/` 的必审人。

## 常见坑

1. **CI 里执行 `gofmt -w`**：工作区被改但检查仍通过，格式问题永远进主干；只检查不修改。
2. **缓存 key 不含 `go.sum`**：依赖升级后仍命中旧缓存，出现「本地能跑 CI 不能跑」；用 `setup-go` 的 `cache: true` 并确保 lock 文件纳入哈希。
3. **工具版本漂移**：golangci-lint 一升级新增规则，历史代码全红；版本号固定在 env 与 Makefile。
4. **覆盖率没加 `-covermode=atomic`**：与 `-race` 同用时统计不准；二者必须成对出现。
5. **只构建默认架构**：上线才发现 arm64 节点跑不起来；矩阵至少覆盖 amd64 + arm64。
6. **`govulncheck` 只在本地跑，或测试通过就发布**：把已知漏洞推上生产；security 必须进 `needs` 链并对 `CRITICAL/HIGH` 阻断。
7. **凭据写进 workflow**：`secrets` 也会被 fork PR 打印；只在受保护事件注入，且不在 `run` 里 echo。

## 小结

- 流水线固定：fmt/vet/lint 与 test 并行 → 矩阵 build → security → docker → tag 触发 release
- 覆盖率硬门槛 + `-race/atomic` + 分支保护 + PR 清单，才是门禁而不是建议

## 练习

1. 给示例仓库加 `.golangci.yml` 与 Makefile，确保 `make lint test` 本地全绿。
2. 把 build job 改成仅在 `v*` tag 上运行，产物命名为 `gateway-<tag>-<arch>`。
