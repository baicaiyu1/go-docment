# 单元测试与集成测试

> 一句话定位：用「大量毫秒级单测 + 少量真实依赖集成测试 + 一条 proto 兼容性检查」组成的测试金字塔，给 Gin 网关与 Kratos 服务建回归防线：单测证明逻辑对，集成测试证明装配对，契约测试证明上下游还能通信。

## 本篇目标

- 用 `httptest` + 表驱动 + `t.Parallel` 测 Gin handler，不占端口
- 用 gomock 替换 Kratos 仓储接口，用 bufconn 在进程内测 gRPC
- 用 testcontainers 测 GORM 真实方言，把 `-race -cover` 与 `buf breaking` 固化到分层 CI

## 一、金字塔与分层责任

```text
E2E（个位数）      APISIX + 网关 + 全部服务，最慢
集成测试（数十）   真实 MySQL/Redis + 真实 gRPC 装配
单元测试（数百）   纯内存、毫秒级、可并行
```

命名写清行为：`TestUserUsecase_Get_NotFound`。一条用例一个断言主题；能 fake 就别连库；连库的用例必须能用 `-short` 或构建标签跳过。

## 二、Gin handler：httptest 表驱动

```go
// app/gateway/internal/handler/user_test.go
package handler_test

func TestUserHandler_Get(t *testing.T) {
    gin.SetMode(gin.TestMode)
    cases := []struct {
        name, path        string
        wantStatus, wantCode int
    }{
        {"ok", "/users/1", http.StatusOK, 0},
        {"non-numeric id", "/users/abc", http.StatusBadRequest, 40001},
        {"zero id", "/users/0", http.StatusBadRequest, 40001},
    }
    for _, tc := range cases {
        tc := tc
        t.Run(tc.name, func(t *testing.T) {
            t.Parallel()
            r := gin.New()
            r.Use(func(c *gin.Context) { // 替身：与正式 ErrorHandler 语义一致
                c.Next()
                if len(c.Errors) > 0 {
                    c.JSON(http.StatusBadRequest, gin.H{"code": 40001, "message": "bad request"})
                }
            })
            r.GET("/users/:id", handler.NewUserHandler(fakeUserClient{}).Get)
            w := httptest.NewRecorder()
            r.ServeHTTP(w, httptest.NewRequest(http.MethodGet, tc.path, nil))
            require.Equal(t, tc.wantStatus, w.Code)
            require.Contains(t, w.Body.String(), fmt.Sprintf(`"code":%d`, tc.wantCode))
        })
    }
}
```

`fakeUserClient` 嵌入 `userv1.UserServiceClient`，只实现 `GetUser`，其余方法保持 nil——比手写全量 mock 更省事。

## 三、biz：gomock 只替接口

```bash
go install go.uber.org/mock/mockgen@latest
mockgen -source=app/user-service/internal/biz/user.go \
    -destination=app/user-service/internal/mocks/user_mock.go -package=mocks
```

```go
// app/user-service/internal/biz/user_test.go
func TestUserUsecase_Get(t *testing.T) {
    tests := []struct {
        name    string
        ret     *biz.User
        retErr  error
        wantErr error
    }{
        {"found", &biz.User{ID: 1, Name: "alice"}, nil, nil},
        {"not found", nil, nil, biz.ErrUserNotFound},
        {"db error", nil, errors.New("timeout"), nil}, // 原样上抛，不吞
    }
    for _, tt := range tests {
        tt := tt
        t.Run(tt.name, func(t *testing.T) {
            t.Parallel()
            ctrl := gomock.NewController(t) // 结束时自动校验 EXPECT 次数
            repo := mocks.NewMockUserRepo(ctrl)
            repo.EXPECT().FindByID(gomock.Any(), int64(1)).Return(tt.ret, tt.retErr).Times(1)
            _, err := biz.NewUserUsecase(repo).Get(context.Background(), 1)
            if tt.wantErr != nil {
                require.ErrorIs(t, err, tt.wantErr)
            }
        })
    }
}
```

## 四、Kratos gRPC：bufconn 进程内联调

```go
// app/user-service/internal/service/user_test.go
func TestUserService_GetUser(t *testing.T) {
    lis := bufconn.Listen(1 << 20)
    srv := grpc.NewServer()
    v1.RegisterUserServiceServer(srv, NewUserService(biz.NewUserUsecase(fakeRepo{})))
    go func() { _ = srv.Serve(lis) }()
    t.Cleanup(srv.Stop)

    conn, err := grpc.NewClient("passthrough:///bufconn",
        grpc.WithContextDialer(func(ctx context.Context, _ string) (net.Conn, error) { return lis.DialContext(ctx) }),
        grpc.WithTransportCredentials(insecure.NewCredentials()))
    require.NoError(t, err)
    t.Cleanup(func() { _ = conn.Close() })

    reply, err := v1.NewUserServiceClient(conn).GetUser(context.Background(), &v1.GetUserRequest{Id: 1})
    require.NoError(t, err)
    require.Equal(t, "alice", reply.GetName())
}
```

bufconn 走真实 protobuf 编解码与 gRPC 状态码，能在单测里验证「NotFound 是否被正确映射」，不起端口、不进网络。

## 五、data：真实 MySQL（testcontainers）

GORM 方言、唯一索引、`ErrRecordNotFound` 翻译只有真实库能证明；纯 SQL 拼接可用 sqlmock，但别用它断言 ORM 行为。用构建标签隔离：

```go
//go:build integration

// app/user-service/internal/data/user_repo_test.go
func TestUserRepo_FindByID(t *testing.T) {
    ctx := context.Background()
    ctr, err := tcMysql.Run(ctx, "mysql:8.4",
        tcMysql.WithDatabase("mall"), tcMysql.WithUsername("root"), tcMysql.WithPassword("root"))
    require.NoError(t, err)
    t.Cleanup(func() { _ = ctr.Terminate(context.Background()) })

    dsn, err := ctr.ConnectionString(ctx, "charset=utf8mb4&parseTime=True&loc=Local")
    require.NoError(t, err)
    db, err := gorm.Open(gormmysql.Open(dsn), &gorm.Config{})
    require.NoError(t, err)
    require.NoError(t, db.AutoMigrate(&data.UserPO{}))

    // 每个用例自建数据、自清数据，禁止共享脏库
    require.NoError(t, db.Create(&data.UserPO{ID: 1, Name: "alice", Email: "a@example.com"}).Error)
    t.Cleanup(func() { db.Exec("DELETE FROM users WHERE id = ?", 1) })

    u, err := data.NewUserRepo(data.NewData(db)).FindByID(ctx, 1)
    require.NoError(t, err)
    require.Equal(t, "alice", u.Name)
}
```

CI 里也可用 compose 起 `mysql:8.4` + `redis:7.4`，比 testcontainers 更省启动时间；下文 CI 示例直接用 GitHub Actions 的 `services` 达到同样效果。

## 六、契约测试：proto 不允许破坏性变更

`api/` 是唯一契约来源，字段删改必须由机器拦截，而不是等联调：

```bash
buf breaking --against '.git#branch=main'
```

规则：字段只增不改号、不复用已删字段号（用 `reserved`）、不改类型与 `go_package`。破坏性变更必须走新 `v2` 包并保留旧版本一个发布周期。

## 七、本地命令与分层 CI

```bash
go test ./... -race -shuffle=on -covermode=atomic -coverprofile=coverage.out
go test -tags=integration ./app/user-service/internal/data/...
go tool cover -func=coverage.out | tail -1            # PowerShell: | Select-Object -Last 1
```

```yaml
# .github/workflows/test.yml（节选）
jobs:
    unit:
        steps: [{run: "go test -short -race -shuffle=on -coverprofile=coverage.out ./..."}]
    integration:
        needs: unit
        services:
            mysql: {image: "mysql:8.4", env: {MYSQL_ROOT_PASSWORD: root, MYSQL_DATABASE: mall}, ports: ["3306:3306"]}
        steps: [{run: "go test -tags=integration ./... -race"}]
    contract:
        steps: [{run: "buf breaking --against '.git#branch=main'"}]
```

## 常见坑

1. **只测 happy path**：缺错误码、空结果、非法参数，线上第一个异常就翻车；表驱动把分支列全。
2. **忘了 `gin.SetMode(gin.TestMode)`**：调试日志污染输出，还容易误判 500。
3. **mock 期望与实际调用不符**：`EXPECT` 没命中仍显示绿灯；用 `Times(1)` 并确保 `gomock.NewController(t)` 由 `t` 管理。
4. **集成测试塞进默认 `./...`**：没装 Docker 的同事本地全红；构建标签 + `-short` 双保险。
5. **共享库表不做清理**：用例顺序一变就互相污染；每用例自建自清或独立 schema。
6. **`time.Sleep` 等异步或覆盖率造假**：前者用 `require.Eventually`；后者别把 `main.go` 与生成代码算进去。

## 小结

- 单测覆盖逻辑（httptest / gomock / bufconn），集成测试覆盖装配（testcontainers / compose）
- 测试金字塔的边界是「失败定位成本」：能在内存里定位的，不要拖到容器里
- proto 兼容性用 `buf breaking` 卡在 CI，CI 分三层：unit → integration → contract

## 练习

1. 给 `UserHandler.Get` 补下游 gRPC 返回 `NotFound` 的用例，断言 HTTP 404 与业务码 `40401`。
2. 用 gomock 覆盖 `FindByID` 返回 `context.DeadlineExceeded`，验证网关映射为 504 而不是 500。
