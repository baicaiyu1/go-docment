# 项目分层与目录规范

> 一句话定位：mall-lite 用「api 定契约、app 放进程、pkg 放通用库、configs 放配置、deploy 放部署物」的五段式单仓布局，把 Gin 网关与 Kratos 服务装进同一个 module，依赖方向永远单向。

## 本篇目标

- 画出五段式目录树，说清每个顶层目录的准入标准
- 掌握 Gin 网关 `cmd + internal/{router,handler,middleware,client}` 的边界
- 掌握 Kratos 服务 `service/biz/data/server/conf` 的分层与依赖方向

## 一、五段式布局

```text
mall-lite/
├── api/{user,product,order}/v1/        # ① proto 契约，唯一事实来源
├── app/gateway/                        # ② Gin BFF：cmd + internal/{router,handler,middleware,client}
├── app/{user,product,order}-service/   # ③ Kratos：cmd + internal/{server,service,biz,data,conf}
├── pkg/{config,logger,errs,tracing,sentinel,discovery}/
├── configs/  deploy/{apisix,docker,k8s,prometheus,grafana,otel}/
└── go.mod
```

| 目录 | 准入标准 | 禁止 |
| --- | --- | --- |
| `api/` | 只放 `.proto` 与生成代码 | 手写业务逻辑 |
| `app/<服务>/` | 可独立部署的进程 | import 其他服务的 `internal` |
| `pkg/` | 两个以上服务用，且不 import `app/` | 业务模型、全局 DB 句柄 |
| `configs/` `deploy/` | 配置与部署物，不参与编译 | 放业务代码 |

## 二、Gin 网关：cmd 装配，internal 分四块

`cmd/main.go` 只装配与启停；`router` 管路由与中间件顺序（Recovery → RequestID → AccessLog → Auth，顺序即语义）；`handler` 管绑定、校验、DTO、错误映射；`middleware` 管鉴权与日志；`client` 启动时 Dial 一次并复用，禁止每请求建连。

```go
// app/gateway/internal/handler/user.go
package handler

import (
    "net/http"
    "strconv"

    "github.com/gin-gonic/gin"

    userv1 "mall-lite/api/user/v1"
    "mall-lite/pkg/errs"
)

type UserHandler struct{ cli userv1.UserServiceClient }

func NewUserHandler(cli userv1.UserServiceClient) *UserHandler { return &UserHandler{cli: cli} }

func (h *UserHandler) Get(c *gin.Context) {
    id, err := strconv.ParseInt(c.Param("id"), 10, 64)
    if err != nil || id <= 0 {
        c.Error(errs.New(errs.CodeInvalidParam, "invalid id")) // 交 ErrorHandler 统一输出
        c.Abort()
        return
    }
    r, err := h.cli.GetUser(c.Request.Context(), &userv1.GetUserRequest{Id: id})
    if err != nil {
        c.Error(err)
        c.Abort()
        return
    }
    // DTO（如 UserDTO）只在本层定义，与 proto 解耦
    c.JSON(http.StatusOK, gin.H{"code": 0, "message": "ok", "data": gin.H{"id": r.GetId(), "name": r.GetName()}})
}
```

## 三、Kratos 服务：DDD 五层

`server` 配 gRPC 与中间件；`service` 把 proto 请求翻译成 biz 调用（不写 SQL）；`biz` 放领域规则与仓储接口；`data` 实现仓储与 GORM；`conf` 只被 server/data 依赖。

```go
// app/user-service/internal/biz/user.go
package biz

import (
    "context"

    "github.com/go-kratos/kratos/v2/errors"
)

var ErrUserNotFound = errors.NotFound("USER_NOT_FOUND", "user not found")

type User struct{ ID int64; Name, Email string }

// 接口定义在消费方（biz），data 实现它，依赖才永远指向 biz。
type UserRepo interface{ FindByID(ctx context.Context, id int64) (*User, error) }

type UserUsecase struct{ repo UserRepo }

func NewUserUsecase(repo UserRepo) *UserUsecase { return &UserUsecase{repo: repo} }

func (uc *UserUsecase) Get(ctx context.Context, id int64) (*User, error) {
    u, err := uc.repo.FindByID(ctx, id)
    if err != nil {
        return nil, err
    }
    if u == nil {
        return nil, ErrUserNotFound
    }
    return u, nil
}
```

```go
// app/user-service/internal/data/user.go
package data

import (
    "context"
    "errors"

    "gorm.io/gorm"

    "mall-lite/app/user-service/internal/biz"
)

// UserPO 承载 gorm tag，领域模型不沾存储细节。
type UserPO struct {
    ID    int64 `gorm:"primaryKey"`
    Name  string
    Email string `gorm:"uniqueIndex"`
}

type userRepo struct{ db *gorm.DB }

func (r *userRepo) FindByID(ctx context.Context, id int64) (*biz.User, error) {
    var po UserPO
    err := r.db.WithContext(ctx).First(&po, id).Error
    if errors.Is(err, gorm.ErrRecordNotFound) {
        return nil, nil // 找不到不是错误，语义由 biz 决定
    }
    if err != nil {
        return nil, err
    }
    return &biz.User{ID: po.ID, Name: po.Name, Email: po.Email}, nil
}
```

## 四、依赖方向、命名与分层约定

```text
gateway: cmd → router → handler → client(gRPC)     禁止 handler → gorm
kratos : server → service → biz ← data 实现接口     禁止 biz → data
pkg    : 被所有人 import，只依赖标准库与第三方       禁止 pkg → app
```

- `internal/` 是编译器强制的边界：其他服务无法 import `app/gateway/internal/...`，共享只能上移 `pkg/` 或 `api/`；包名用短小单数名词，禁止 `utils`/`common`/`base`

| 关注点 | 放哪里 | 规则 |
| --- | --- | --- |
| 接口定义 | 消费方（biz） | data 只 import biz，不得反向 |
| 错误 | Kratos `errors.New(code, reason, msg)` + `pkg/errs` | reason 大写下划线；网关映射 `400xx/401xx/5xxxx` 与状态码，禁止透传堆栈 |
| DTO | 仅 handler 层 | JSON tag 只出现在这里，与 proto 解耦 |
| 校验 | 入口 `binding` / proto validate | 业务规则必须在 biz，handler 拦不住服务间调用 |

## 五、一次请求的完整调用链

```text
APISIX :9080（jwt-auth / limit-req）
  → Gin 网关 :8080（Recovery → RequestID → AccessLog → Auth）→ handler.Get → client
    → Kratos :9001（recovery / logging / tracing / sentinel）
      → service.GetUser（proto → biz 翻译）
        → biz.UserUsecase.Get → biz.UserRepo → data.userRepo.FindByID（GORM，PO → User）
```

## 完整示例

```go
// app/gateway/internal/router/router.go（import 省略）
package router

// New 只做装配：中间件顺序 = 恢复 → request_id → 访问日志 → 鉴权。
func New(h *handler.UserHandler, mw *middleware.Set) *gin.Engine {
    r := gin.New()
    r.SetTrustedProxies(nil)
    r.Use(gin.Recovery(), mw.RequestID(), mw.AccessLog(), mw.Auth())
    v1 := r.Group("/api/v1")
    v1.GET("/users/:id", h.Get)
    return r
}
```

## 常见坑

1. **handler 直接查库**：单测被迫连 MySQL，换存储要改协议层；数据访问只出现在 `data`。
2. **`pkg/` import `app/`**：报 `import cycle not allowed`；通用能力下沉或留在调用方 `internal`。
3. **biz 结构体当 GORM 模型**：加索引就改领域字段；用 `UserPO` + 转换函数隔离。
4. **接口定义在实现方**：biz 反向 import data，依赖立刻反向；接口永远写在消费方。
5. **目录超前拆分**：200 行代码拆 8 个包，读一次请求跳十次；按真实变化点拆。

## 评审 checklist

- [ ] handler 无 SQL，biz 无 `gorm.`，data 无 HTTP 语义
- [ ] 接口定义在消费方，实现方没有反向 import
- [ ] proto 变更同 PR 重新生成，`go build ./...` 通过
- [ ] 错误码在区间内，出口统一 `{code,message,data,request_id}`，无堆栈外泄
- [ ] `client` 启动时建连并复用，新目录满足准入标准，`pkg/` 未引入业务模型

## 小结

- 五段式布局：`api` 契约、`app` 进程、`pkg` 通用库、`configs` 配置、`deploy` 部署物
- Gin 走 `router → handler → client`，Kratos 走 `server → service → biz → data`
- `internal` 是编译器强制的边界，`pkg` 只进不出（不 import `app/`）
