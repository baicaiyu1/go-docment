# 01-官方文档索引

> 一句话定位：把 Gin + Kratos 技术栈的 18 个组件按「框架 → 契约 → 数据 → 治理 → 可观测 → 部署」排成一张导航表，只放真实可访问的官方地址，并标出该读教程哪一章。

## 本篇目标

- 一页找到 Gin、Kratos、gRPC/Protobuf、GORM、Viper、zap、go-redis、Sentinel Go、APISIX、etcd、Consul、Kafka、OpenTelemetry、Jaeger、Prometheus、Grafana、Docker、Kubernetes 的官方入口。
- 分清「官方文档」与「源码仓库」：文档看用法，仓库看版本与 Issue，API 签名查 pkg.go.dev。
- 用一段可运行脚本探测链接可达性，换网络或代理后能自己复验。

- 已读 [Gin 是什么-架构与性能](../02-Gin入门/01-Gin是什么-架构与性能.md)，并了解 Go Modules（[Go Module 与国内代理](../00-开始之前/03-Go-Module与国内代理.md)）；内网受限时优先读仓库 README。

## 完整示例：批量探测链接可达性

```go
// cmd/linkcheck/main.go
package main

import (
	"fmt"
	"net/http"
	"time"
)

var docs = []string{
	"https://gin-gonic.com/zh-cn/docs/",
	"https://go-kratos.dev/docs/",
	"https://gorm.io/zh_CN/docs/",
	"https://apisix.apache.org/zh/docs/apisix/getting-started/",
}

func main() {
	client := &http.Client{Timeout: 10 * time.Second}
	for _, u := range docs {
		resp, err := client.Get(u)
		if err != nil {
			fmt.Println("FAIL", u, err)
			continue
		}
		resp.Body.Close()
		fmt.Println(resp.StatusCode, u)
	}
}
```

正常网络下每个地址输出一行 `200 <url>`；出现 `FAIL` 时先换网络或设 `User-Agent` 复测，再判断是否为死链。

## 常见坑

1. **拿博客当文档**：博客版本常年滞后，`gin.H` 与中间件语义最容易被写错，以 pkg.go.dev 签名为准。
2. **只看仓库不看文档**：README 只给最小示例，配置项与边界条件在文档站，两边对照看。
3. **忽略 contrib 版本耦合**：Kratos 的 etcd/consul/zap 适配在 contrib 子模块，升级主框架要同步升 contrib。
4. **用 `@latest` 装代码生成器**：团队生成物必须一致，`protoc-gen-go`、`buf`、`kratos` CLI 都要锁版本。
5. **中文文档缺页就猜路径**：直接回英文原站或仓库，不要按目录名拼 URL。

## 小结

- 18 个组件只需记住两类入口：文档看用法、仓库看版本；签名核对去 pkg.go.dev。
- Gin/Kratos/APISIX 三处文档读透，本教程 80% 的问题都能自己定位。
- 链接会随版本调整，换环境后重跑本篇脚本，失败就回站点根目录找；与教程不一致时以官方最新稳定版为准。
