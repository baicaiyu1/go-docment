# 快速开始：第一个 Gin 服务

> 一句话定位：从空目录到可验证的 Gin 服务只需四步——建模块、写 handler、注册路由、启动；本篇一次跑通，并加上统一响应与请求日志，优雅退出的完整写法在 05 篇。

## 本篇目标

- 完成 `go mod init` → `go get` → 运行 → `curl` 验证的闭环。
- 掌握 `gin.Default()`、`r.GET`、`*gin.Context`、`c.JSON` 的最小组合。
- 写出统一的 `{code,message,data}` 响应与请求日志中间件。
- 用 `http.Server` 承载 Engine，知道超时与优雅退出的完整写法在 05 篇。
- 会排查端口占用、ReleaseMode、`ShouldBindJSON` 错误处理等高频问题。

## 前置知识

- 已安装 Go 并配置代理，见 [Go Module 与国内代理](../00-开始之前/03-Go-Module与国内代理.md)。
- 知道 HTTP 方法、状态码与 JSON；读过 [Gin 是什么：架构与性能](./01-Gin是什么-架构与性能.md)。

## 一、初始化模块

```text
mkdir gin-quickstart; cd gin-quickstart
go mod init example.com/gin-quickstart
go get github.com/gin-gonic/gin@v1.10.0
```

## 二、最小可运行服务

```go
// main.go
package main

import (
    "log"
    "net/http"

    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.Default() // = gin.New() + Logger + Recovery
    r.GET("/ping", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"message": "pong"})
    })

    // Run 内部是 http.ListenAndServe(":8080", r)，生产用法见第四节
    if err := r.Run(":8080"); err != nil {
        log.Fatalf("server exited: %v", err)
    }
}
```

handler 签名固定为 `func(c *gin.Context)`，没有 `error` 返回值；`gin.H` 是 `map[string]any` 的别名；`c.Param` 取路径参数，`c.Query` 取 URL 参数，`c.PostForm` 取表单字段。

## 三、统一响应与请求日志

```go
// internal/response/response.go
package response

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

type Body struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    any    `json:"data,omitempty"`
}

func OK(c *gin.Context, data any) { c.JSON(http.StatusOK, Body{0, "ok", data}) }
func Fail(c *gin.Context, status, code int, msg string) { c.JSON(status, Body{code, msg, nil}) }
```

```go
// internal/middleware/logging.go
package middleware

import (
    "log/slog"
    "time"

    "github.com/gin-gonic/gin"
)

func Logging() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        c.Next() // 先放行后续 handler，返回后再记录状态码与耗时
        slog.Info("http request", "method", c.Request.Method, "path", c.Request.URL.Path,
            "status", c.Writer.Status(), "latency_ms", time.Since(start).Milliseconds())
    }
}
```

装配时用 `gin.New()` 显式挂载，避免与 `gin.Default()` 的 Logger 重复打印；`/healthz` 的注册见第四节。

验证（一个终端 `go run .`，另一个终端执行 curl）：

```powershell
go mod tidy; go run .
curl.exe -i http://127.0.0.1:8080/ping
curl.exe -i http://127.0.0.1:8080/healthz
```

预期：`/ping` 返回 `{"message":"pong"}`，`/healthz` 返回 `{"code":0,"message":"ok",...}`，不存在的路径返回 `404 page not found`（改 JSON 见 05 篇）。PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，必须写 `curl.exe`。

## 四、用 http.Server 承载 Engine

`r.Run()` 不能配置超时、也不做优雅退出，生产用 `http.Server` 承载：

```go
// cmd/server/main.go 的核心片段（完整 main 见 05 篇）
gin.SetMode(gin.ReleaseMode)
r := gin.New()
r.Use(gin.Recovery(), middleware.Logging())
_ = r.SetTrustedProxies(nil)
r.GET("/healthz", func(c *gin.Context) { response.OK(c, gin.H{"status": "ok"}) })

srv := &http.Server{Addr: ":8080", Handler: r, ReadHeaderTimeout: 5 * time.Second}
if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
    slog.Error("listen failed", "err", err)
}
```

上面只示范启动；信号监听（`signal.NotifyContext`）、`Shutdown` 与四个超时字段的完整写法见 [05-Engine详解与启动参数](./05-Engine详解与启动参数.md)。后台 goroutine 要用 `WaitGroup` 收尾，`Shutdown` 不管它们。

## 五、ShouldBindJSON 的错误要自己处理

`ShouldBind*` 不会自动写响应；`Bind*` 会自动写 400 且响应体不可控，生产别用。

```go
// internal/handler/user.go
func CreateUser(c *gin.Context) {
    var req struct {
        Name string `json:"name" binding:"required,min=2,max=32"`
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        var ve validator.ValidationErrors
        if errors.As(err, &ve) { // 校验失败，只暴露字段名
            response.Fail(c, 400, 40001, "invalid field: "+ve[0].Field())
            return
        }
        response.Fail(c, 400, 40001, "invalid json body") // 含 io.EOF
        return
    }
    response.OK(c, req)
}
```

三类错误必须分开：空 body 是 `io.EOF`、语法错误是 `*json.SyntaxError`、校验失败是 `validator.ValidationErrors`。完整写法见[参数绑定与校验](../03-基本特性/03-参数绑定与校验.md)。

```

```

## 常见坑

1. **生产还是 Debug 模式**：会打印路由表并有额外断言，启动第一行 `gin.SetMode(gin.ReleaseMode)`。
2. **端口被占用**：Windows 用 `netstat -ano | findstr :8080` + `taskkill /PID <pid> /F`；macOS/Linux 用 `lsof -i :8080` + `kill -9 <pid>`。
3. **`ShouldBindJSON` 报错却不返回**：它不写状态码，忘记 `return` 会继续执行并写两次响应。
4. **用 `c.BindJSON` 图省事**：自动写 400 且响应体不可控，无法统一成 `{code,message}`。
5. **`gin.Default()` 与自定义 Logger 叠加**：一次请求两条日志，用 `gin.New()`。
6. **改了代码没生效**：`go run .` 不会热重载，需要重启或用 air（见 03 篇）。
7. **`/hello/` 返回 404**：`:name` 不匹配空段，是设计行为。

## 小结

- 最小 Gin 服务四步：建模块、写 handler、注册路由、启动。
- 生产启动换成 `http.Server`，超时四件套与优雅退出见 05 篇。
- 统一响应与请求日志第一天就定下来，后面所有接口复用。
- `ShouldBind*` 的错误必须显式分支处理，否则“参数错误”无法定位。

## 练习

1. 新增 `POST /echo` 原样返回请求体，用 PowerShell 与 bash 各测试一次（注意引号转义）。
2. 给 `Logging` 加 `request_id`：优先读 `X-Request-ID`，没有就生成并回写响应头。
3. 用被占用的 `:8080` 启动，用系统命令定位并结束进程后重启。
