# 路由

> 一句话定位：Gin 的路由是「按 HTTP Method 拆分的 radix 树」，静态段优先于参数段、参数段优先于通配段；冲突在注册时直接 panic，越早暴露越好。

## 本篇目标

- 会注册静态、`:param`、`*catchall` 三类路由，并说清匹配优先级。
- 用 `Group` 做 API 版本化，并给路由组挂中间件。
- 理解路由冲突为什么 panic，以及 `NoRoute`、`NoMethod`、`HandleMethodNotAllowed` 怎么配。
- 掌握 `Any`、`Handle`、尾斜杠重定向的行为边界。
- 会按模块拆分 `router` 包，让 `main.go` 只负责装配。

## 前置知识

- 读过 [Engine 详解与启动参数](../02-Gin入门/05-Engine详解与启动参数.md)，知道 `gin.New()` 与 `gin.Default()` 的差别。
- 了解 HTTP Method，以及 URL 中 path 与 query 的分工；用过一次 `c.Param()`。

## 一、路由树与注册方法

`Engine` 内部是 `trees MethodTrees`：每个 Method 一棵 radix 树，匹配开销只与路径长度相关，与路由条数无关。这是 Gin 在高 QPS 下稳定的根本原因。

| 方法 | 说明 |
| --- | --- |
| `GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS` | 注册单个 Method |
| `Any(path, handlers...)` | 为 9 个内置方法注册同一 handler |
| `Handle(method, path, handlers...)` | 指定 Method，可注册自定义方法 |
| `Static/StaticFS/StaticFile` | 静态文件，见 [08 篇](./08-静态资源与文件上传.md) |

```go
// app/gateway/cmd/main.go
r := gin.New()

r.GET("/ping", func(c *gin.Context) { c.JSON(http.StatusOK, gin.H{"ok": true}) })
r.POST("/users", createUser)
r.PUT("/users/:id", updateUser)
r.DELETE("/users/:id", deleteUser)
r.Any("/health", healthHandler)          // 9 个内置方法都命中
r.Handle("PROPFIND", "/dav", davHandler) // WebDAV 这类非标准方法
```

`Any` 覆盖 GET、POST、PUT、PATCH、HEAD、OPTIONS、DELETE、CONNECT、TRACE，但不含自定义的 `PROPFIND`，后者必须单独 `Handle`。

## 二、三种路径模式

```go
r.GET("/users/me", meHandler)        // 静态：完全固定
r.GET("/users/:id", getUser)         // 参数：单个非空段
r.GET("/files/*filepath", serveFile) // 通配：剩余全部，含 /
```

| 请求路径 | 命中 | `c.Param` |
| --- | --- | --- |
| `/users/me` | 静态 | 空 |
| `/users/123` | 参数 | `id=123` |
| `/users/` | 无（参数不能为空）→ 404 | 空 |
| `/files/a.txt` | 通配 | `filepath=/a.txt` |
| `/files/dir/a.txt` | 通配 | `filepath=/dir/a.txt` |

`/files` 在 `RedirectTrailingSlash` 开启时会 301 到 `/files/`，落到通配且值为 `/`。

两个细节必须记住：

- 通配值**以 `/` 开头**，拼本地路径前要 `strings.TrimPrefix(p, "/")`，否则会拼出绝对路径。
- 优先级由树结构决定，与注册顺序无关：`/users/me` 永远不会被 `:id` 抢走。

## 三、路由组与版本化

```go
api := r.Group("/api/v1")
api.GET("/users", listUsers)
api.GET("/users/:id", getUser)

admin := r.Group("/admin", gin.BasicAuth(gin.Accounts{"root": "secret"}))
admin.GET("/stats", statsHandler) // 只对组内路由生效
```

- `Group` 的第二个参数起是中间件，等价于随后 `admin.Use(...)`；组前缀会被 `path.Join` 规范化，`//`、`..` 会被清理，但团队应统一写成 `/api/v1`。
- 版本升级用 `/api/v1`、`/api/v2` 两个并列组，不在 v1 里偷偷改语义；灰度期两个版本同时在线，由 APISIX 分流。
- 路由必须在 `r.Run()` 之前注册完。运行期增删路由会并发写 `trees`，属于反模式。

## 四、冲突规则：注册期 panic

Gin 在 `addRoute` 阶段校验树结构，冲突直接 panic，服务起不来。总比线上 404 好。

```go
r.GET("/users/:id", h1)
r.GET("/users/:name", h2) // panic：同一位置只能有一个参数名
```

```text
panic: ':name' in new path '/users/:name' conflicts with existing wildcard ':id' in existing prefix '/users/:id'
```

| 写法 | 结果 |
| --- | --- |
| `/users/:id` + `/users/me` | 合法，静态优先（v1.7+ 支持） |
| `/users/:id` + `/users/:name` | panic，参数名冲突 |
| `/files/*path/edit` | panic，`catch-all routes are only allowed at the end of the path` |
| `/files/*path` + `/files/:name` | panic，通配与参数抢占同一层 |
| 同方法同路径注册两次 | panic，`handlers are already registered for path` |

## 五、404 / 405 与尾斜杠

```go
r := gin.New()
r.HandleMethodNotAllowed = true // 默认 false，必须手动打开
r.POST("/users", createUser)

r.NoRoute(func(c *gin.Context) { c.JSON(http.StatusNotFound, gin.H{"code": 40400}) })
r.NoMethod(func(c *gin.Context) { c.JSON(http.StatusMethodNotAllowed, gin.H{"code": 40500}) })
```

- 只注册 `NoRoute` 时，方法不匹配也返回 404；打开 `HandleMethodNotAllowed` 才区分 405 并执行 `NoMethod`。
- Gin 不自动写 `Allow` 头。需要时用 `r.Routes()` 反查该路径的可用方法，再 `c.Header("Allow", "GET, POST")`。
- 尾斜杠三开关：`RedirectTrailingSlash` 默认 `true`（GET 301 / 其它 307）；`RedirectFixedPath` 默认 `false`，开启后纠正大小写与多余斜杠再重定向；`RemoveExtraSlash` 默认 `false`，开启后 `//foo` 直接按 `/foo` 匹配。对外 API 建议关闭 `RedirectTrailingSlash`，避免客户端缓存 301 后行为漂移。
- Gin 没有 Rails 式命名路由。生产上用 `c.FullPath()`（注册模板，如 `/api/v1/users/:id`）作为稳定标识，做 Prometheus label 与限流资源名；`c.Request.URL.Path` 带 ID，会把 label 打爆。

## 六、企业级路由组织

`main.go` 只做装配，路由按模块拆文件，新增模块不动老代码：

```go
// app/gateway/internal/router/router.go
package router

import "github.com/gin-gonic/gin"

func New(user *handler.UserHandler, order *handler.OrderHandler) *gin.Engine {
    r := gin.New()
    r.Use(gin.Recovery(), RequestID(), AccessLog())
    r.HandleMethodNotAllowed = true
    r.NoRoute(notFound)
    r.NoMethod(methodNotAllowed)

    v1 := r.Group("/api/v1")
    registerUser(v1, user)
    registerOrder(v1, order)
    return r
}
```

```go
// app/gateway/internal/router/user.go
package router

func registerUser(g *gin.RouterGroup, h *handler.UserHandler) {
    u := g.Group("/users")
    u.GET("", h.List)
    u.POST("", h.Create)
    u.GET("/:id", h.Get)
    u.PUT("/:id", h.Update)
    u.DELETE("/:id", h.Delete)
}
```

## 完整示例

```go
// app/gateway/cmd/main.go
package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.New()
    r.Use(gin.Logger(), gin.Recovery())
    r.HandleMethodNotAllowed = true

    v1 := r.Group("/api/v1")
    ok := func(c *gin.Context, data any) { c.JSON(http.StatusOK, gin.H{"code": 0, "data": data}) }
    v1.GET("/users/me", func(c *gin.Context) { ok(c, "me") })
    v1.GET("/users/:id", func(c *gin.Context) { ok(c, c.Param("id")) })
    v1.GET("/files/*filepath", func(c *gin.Context) { ok(c, c.Param("filepath")) })

    r.NoRoute(func(c *gin.Context) { c.JSON(http.StatusNotFound, gin.H{"code": 40400}) })
    r.NoMethod(func(c *gin.Context) { c.JSON(http.StatusMethodNotAllowed, gin.H{"code": 40500}) })

    if err := r.Run("127.0.0.1:8080"); err != nil {
        panic(err)
    }
}
```

## 常见坑

1. **同一层写两个参数名**：`/users/:id` 与 `/users/:name` 会 panic，全项目统一叫 `:id`。
2. **把通配放中间**：`/files/*path/edit` 直接 panic，通配只能在末尾。
3. **以为方法不匹配会 405**：不打开 `HandleMethodNotAllowed` 一律 404。
4. **尾斜杠重定向与签名校验冲突**：301 让客户端改路径重放，签名对不上，严格 API 建议关掉。
5. **在 handler 里新增路由**：并发写 `trees` 会数据竞争，动态分发改成查表。
6. **用真实路径做指标 label**：`/users/123` 会导致 label 爆炸，必须用 `c.FullPath()`。

## 小结

- 路由是 per-method 的 radix 树，优先级静态 > 参数 > 通配，与注册顺序无关。
- 冲突在注册期 panic，参数名统一、通配放末尾是两条铁律。
- 路由组承载版本前缀与中间件，是分层的基础单元。
- 404/405 要显式配置；监控与限流用 `c.FullPath()`，不要用真实路径。
