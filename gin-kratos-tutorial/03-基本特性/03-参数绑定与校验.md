# 参数绑定与校验

> 一句话定位：Gin 用 tag 描述参数来源、用 `ShouldBind` 系列完成反序列化、用 validator v10 执行 `binding` 规则；而 `Bind` 会偷偷写 400，生产环境应当禁用。

本篇默认你已完成 [02-请求上下文Context](./02-请求上下文Context.md)，并了解 Go 结构体 tag 与反射。

## 本篇目标

- 区分 `ShouldBind` 家族与 `Bind`，掌握 `json`、`form`、`uri`、`header` 四种 tag 与对应入口。
- 用 validator v10 写规则、注册自定义校验器、把错误翻译成中文。
- 处理「文件 + JSON」混合请求，并按 Request/Response 与领域模型分层。

## 一、ShouldBind 家族

| 方法 | 数据来源 | 使用的 tag |
| --- | --- | --- |
| `ShouldBind` | 按 Method + `Content-Type` 自动选一种 | 多种 |
| `ShouldBindJSON/XML/YAML` | Body | `json`/`xml`/`yaml` |
| `ShouldBindQuery` | Query String | `form` |
| `ShouldBindUri` | 路径参数 | `uri` |
| `ShouldBindHeader` | 请求头 | `header` |

最容易错的一条：**Gin 没有 `query` tag**，`ShouldBindQuery` 读的是 `form` tag。

```go
// app/gateway/internal/handler/order.go
type GetOrderReq struct {
    ID     int64  `uri:"id" binding:"required,gt=0"`
    Fields string `form:"fields"` // ?fields=items
    XTrace string `header:"X-Trace-Id"`
}

func (h *OrderHandler) Get(c *gin.Context) {
    var req GetOrderReq
    err := errors.Join(c.ShouldBindUri(&req), c.ShouldBindQuery(&req), c.ShouldBindHeader(&req))
    if err != nil { respondBindErr(c, err); return }
    c.JSON(http.StatusOK, gin.H{"code": 0, "data": req})
}
```

`ShouldBind` 只按 `Content-Type` 选**一种**来源，path + query 混合必须分次绑定。

## 二、Bind 的坑：它会自己写 400

`Bind` 是 `MustBindWith` 的别名：失败时直接 `AbortWithError(400, err)`，响应体是纯文本 `text/plain`。代价是：与统一响应 `{"code","message","data"}` 冲突、响应已开始写导致错误中间件无法改写、错误串是英文且无法翻译。所以只用 `ShouldBind*` 自己判断错误。

## 三、validator v10 规则

Gin 把 `binding` tag 直接交给 go-playground/validator v10：

| 规则 | 含义 | 示例 |
| --- | --- | --- |
| `required` | 非零值 | `binding:"required"` |
| `min/max` | 字符串/切片长度、数值大小 | `min=2,max=20` |
| `gte/lte/gt/lt` | 数值比较 | `gte=0,lte=130` |
| `email/url/numeric` | 格式 | `email` |
| `oneof` | 枚举 | `oneof=admin user` |
| `dive` | 继续校验切片元素 | `max=5,dive,min=1` |
| `eqfield` | 跨字段相等 | `eqfield=Password` |

`required` 判断的是**零值**，不是「字段存在」：`age=0`、`agree=false` 都会被判缺失，要区分「没传」与「传了零值」就用指针。

```go
// app/gateway/internal/dto/user.go
type CreateUserReq struct {
    Name  string   `json:"name" binding:"required,min=2,max=20"`
    Age   *int     `json:"age" binding:"required,gte=0,lte=130"` // nil=没传，0 合法
    Email string   `json:"email" binding:"required,email"`
    Role  string   `json:"role" binding:"omitempty,oneof=admin user"`
    Tags  []string `json:"tags" binding:"max=5,dive,min=1"`
}
```

`dive` 之后的规则作用在切片元素上，跳过校验写 `binding:"-"`。

## 四、自定义校验器与中文错误

`binding.Validator` 是全局单例，在启动阶段改一次，注册 `username` 规则；想让错误里显示 json 字段名，可再调 `RegisterTagNameFunc` 返回 `json` tag 名。

```go
// app/gateway/internal/validator/validator.go
var usernameRE = regexp.MustCompile(`^[a-z0-9_]{3,16}$`)

func Init() error {
    v := binding.Validator.Engine().(*validator.Validate)
    return v.RegisterValidation("username", func(fl validator.FieldLevel) bool {
        return usernameRE.MatchString(fl.Field().String())
    })
}

func respondBindErr(c *gin.Context, err error) {
    var ve validator.ValidationErrors
    if !errors.As(err, &ve) {
        c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"code": 40000, "message": "参数格式错误"})
        return
    }
    fields := make(map[string]string, len(ve))
    for _, fe := range ve {
        switch fe.Tag() {
        case "required":
            fields[fe.Field()] = fe.Field() + " 不能为空"
        case "min", "max", "gte", "lte":
            fields[fe.Field()] = fe.Field() + " 超出范围 " + fe.Param()
        case "email":
            fields[fe.Field()] = fe.Field() + " 不是合法邮箱"
        default:
            fields[fe.Field()] = fe.Field() + " 校验失败：" + fe.Tag()
        }
    }
    c.AbortWithStatusJSON(http.StatusUnprocessableEntity, gin.H{"code": 42200, "message": "参数校验失败", "fields": fields})
}
```

## 五、文件 + JSON 混合

「一个 JSON 字段 + 一个文件」最清晰的做法是分开处理：JSON 放在 `meta` 表单字段，文件用 `FormFile`。

```go
// app/gateway/internal/handler/upload.go
func (h *UploadHandler) Avatar(c *gin.Context) {
    var meta AvatarMeta // 字段带 binding tag
    if err := json.Unmarshal([]byte(c.PostForm("meta")), &meta); err != nil || binding.Validator.ValidateStruct(&meta) != nil {
        c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"code": 40000, "message": "meta 不合法"})
        return
    }
    fh, err := c.FormFile("file")
    if err != nil || fh.Size > 2<<20 { // 2MB，必须服务端校验
        c.AbortWithStatusJSON(http.StatusRequestEntityTooLarge, gin.H{"code": 41300, "message": "文件缺失或超过 2MB"})
        return
    }
    name := uuid.NewString() + strings.ToLower(filepath.Ext(fh.Filename)) // 重命名，绝不拼接用户文件名
    if err := c.SaveUploadedFile(fh, filepath.Join("uploads", name)); err != nil {
        c.AbortWithStatusJSON(500, gin.H{"code": 50000, "message": "保存失败"}); return
    }
    c.JSON(http.StatusOK, gin.H{"code": 0, "data": gin.H{"name": name}})
}
```

`r.MaxMultipartMemory` 只控制内存缓冲阈值，超出部分落临时文件，**不是**上传大小上限。完整流程见 [08 篇](./08-静态资源与文件上传.md)。

## 六、DTO 分层

```go
// app/gateway/internal/dto/user.go
type UserResponse struct { // 只包含允许暴露的字段
    ID    int64  `json:"id"`
    Name  string `json:"name"`
    Email string `json:"email"`
}
```

- Handler 只碰 Request/Response，不把 `model.User` 直接 `c.JSON`（否则 `PasswordHash` 会泄漏）；Service 只接受领域模型或显式参数，不依赖 `gin.Context`；模型与 DTO 的转换集中在一个文件。

## 完整示例

```go
// app/gateway/cmd/main.go
package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

type CreateUserReq struct {
    Name  string `json:"name" binding:"required,min=2,max=20"`
    Email string `json:"email" binding:"required,email"`
}

func main() {
    r := gin.New()
    r.POST("/api/v1/users", func(c *gin.Context) {
        var req CreateUserReq
        if err := c.ShouldBindJSON(&req); err != nil {
            respondBindErr(c, err) // 同包，见第四节
            return
        }
        c.JSON(http.StatusCreated, gin.H{"code": 0, "data": req})
    })
    _ = r.Run("127.0.0.1:8080")
}
```

```powershell

```

## 常见坑

1. **用 `Bind` 图省事**：它已写出 400 纯文本，统一响应与错误中间件都失效。
2. **给 query 写 `query:"page"`**：Gin 没有这个 tag，`ShouldBindQuery` 只认 `form`。
3. **`required` 当「字段存在」**：`int` 的 0、`bool` 的 false 被判缺失，用指针或范围规则。
4. **忘记 `Content-Type: application/json`**：`ShouldBindJSON` 直接报错，`ShouldBind` 会走错分支。
5. **先 `GetRawData` 再绑定**：Body 被消费，得到空对象；多次读用 `ShouldBindBodyWith`。
6. **以为 `MaxMultipartMemory` 限制上传大小**：它只管内存缓冲，大小必须自己判断。

## 小结

- 只用 `ShouldBind*`，`Bind` 会破坏统一响应。
- tag 决定来源：`json`、`form`（query 也用它）、`uri`、`header`，混合来源分次绑定。
- validator v10 靠 `binding` tag 工作，`required` 判零值，自定义规则在启动期注册；响应只输出 DTO。

## 练习

1. 实现 `GET /api/v1/users/:id?fields=name`，用一次结构体、三次绑定，验证三个来源都生效。
2. 给 `CreateUserReq` 加 `ConfirmPassword`，用 `eqfield` 校验两次密码一致并输出中文错误。
3. 实现 `POST /api/v1/avatar`，限制 2MB、只允许 jpg/png/webp，并说明还缺哪些安全检查。
