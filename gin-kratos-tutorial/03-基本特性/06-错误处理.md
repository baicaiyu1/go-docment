# 错误处理

> 一句话定位：Gin 不替你输出错误，`c.Error(err)` 只是把错误挂到 `c.Errors`；统一响应靠「业务错误类型 + ErrorHandler 中间件 + 自定义 Recovery」三件套。

## 本篇目标

- 掌握 `%w` 包装与 `errors.Is` / `errors.As` 的判定方式。
- 设计带 `Code / Message / HTTPStatus` 的业务错误类型。
- 用 `c.Error(err)` + `c.Abort()` 交棒，由 ErrorHandler 统一写响应。
- 自定义 Recovery 让堆栈只进日志，并预留 gRPC 错误映射与测试断言。

## 一、先定错误码规范

五位数字、前三位对齐 HTTP：`400xx` 参数、`401xx` 鉴权、`403xx` 权限、`404xx` 不存在、`429xx` 限流、`5xxxx` 系统（如 40001、40101、42901、50001）。HTTP 状态码只表达传输语义，业务码表达具体原因，两者不要互相替代。

## 二、业务错误类型与错误包装

```go
// pkg/errs/errs.go
package errs

import "net/http"

type BizError struct {
    HTTPStatus int    // 对外状态码
    Code       int    // 业务码，如 40401
    Message    string // 对外消息，不含内部细节
}

func (e *BizError) Error() string { return e.Message }

// Is 让 fmt.Errorf("%w") 包装后 errors.Is 仍成立
func (e *BizError) Is(target error) bool {
    t, ok := target.(*BizError)
    return ok && t.Code == e.Code
}

var (
    ErrInvalidParam = &BizError{http.StatusBadRequest, 40001, "invalid parameter"}
    ErrUnauthorized = &BizError{http.StatusUnauthorized, 40101, "unauthorized"}
    ErrNotFound     = &BizError{http.StatusNotFound, 40401, "not found"}
    ErrTooManyReq   = &BizError{http.StatusTooManyRequests, 42901, "too many requests"}
    ErrInternal     = &BizError{http.StatusInternalServerError, 50001, "internal server error"}
)
```

底层错误必须用 `%w` 保留错误链；判定用 `errors.Is`（哨兵错误）或 `errors.As`（具体类型），禁止 `==` 与字符串匹配：

```go
// app/gateway/internal/repo/user.go
if errors.Is(err, gorm.ErrRecordNotFound) {
    return nil, fmt.Errorf("%w: user id=%d", errs.ErrNotFound, id) // 对外可判定
}
return nil, fmt.Errorf("repo.FindByID id=%d: %w", id, err)        // 根因保留，只进日志
```

## 三、handler 交棒：c.Error + c.Abort

`c.Error` 不中断 handler，也不写响应，所以必须 `Abort()` 并 `return`，且绝不再写第二段响应：

```go
// app/gateway/internal/handler/user.go
func (h *UserHandler) Get(c *gin.Context) {
    u, err := h.uc.GetUser(c.Request.Context(), c.Param("id"))
    if err != nil {
        h.log.Error("get user", zap.Error(err)) // 根因进日志
        c.Error(errs.ErrInternal)               // 对外只给统一码
        c.Abort()
        return
    }
    c.JSON(http.StatusOK, gin.H{"code": 0, "data": u})
}
```

## 四、统一 ErrorHandler 中间件

```go
// app/gateway/internal/middleware/error.go
func ErrorHandler(log *zap.Logger) gin.HandlerFunc {
    return func(c *gin.Context) {
        c.Next() // 先跑完后续 handler，再统一结算
        if len(c.Errors) == 0 {
            return
        }
        err := c.Errors.Last().Err
        var biz *errs.BizError
        if errors.As(err, &biz) {
            c.AbortWithStatusJSON(biz.HTTPStatus, gin.H{"code": biz.Code, "message": biz.Message, "request_id": c.GetString("request_id")})
            return
        }
        log.Error("unhandled error", zap.String("path", c.Request.URL.Path), zap.Error(err))
        c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"code": 50001, "message": "internal server error", "request_id": c.GetString("request_id")})
    }
}
```

注册顺序：`requestid.New()` → `Recovery(log)` → `ErrorHandler(log)`（`Use` 越靠前越在外层，Recovery 必须包住 ErrorHandler 与业务路由，ErrorHandler 在业务路由之前）。

## 五、自定义 Recovery

`gin.Recovery()` 返回空体、绕开统一格式，改用 `gin.CustomRecovery`：

```go
// app/gateway/internal/middleware/recovery.go
func Recovery(log *zap.Logger) gin.HandlerFunc {
    return gin.CustomRecovery(func(c *gin.Context, recovered any) {
        log.Error("panic recovered",
            zap.String("path", c.Request.URL.Path),
            zap.Any("panic", recovered),
            zap.ByteString("stack", debug.Stack())) // 堆栈只进日志
        c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"code": 50001, "message": "internal server error"})
    })
}
```

## 六、gRPC / Kratos 错误映射（预留）

下游返回的是 gRPC status，必须映射为本地业务码，不能让 `rpc error: code = ...` 泄漏给客户端：

```go
// app/gateway/internal/client/mapper.go
var grpcToBiz = map[codes.Code]*errs.BizError{
    codes.InvalidArgument:   errs.ErrInvalidParam,
    codes.Unauthenticated:   errs.ErrUnauthorized,
    codes.PermissionDenied:  {http.StatusForbidden, 40301, "permission denied"},
    codes.NotFound:          errs.ErrNotFound,
    codes.ResourceExhausted: errs.ErrTooManyReq,
}

func FromGRPC(err error) error {
    if err == nil {
        return nil
    }
    st, ok := status.FromError(err)
    if !ok {
        return errs.ErrInternal
    }
    if biz, hit := grpcToBiz[st.Code()]; hit {
        return biz
    }
    return errs.ErrInternal // DeadlineExceeded/Unavailable 默认降级 50001
}
```

Kratos 侧用 `kerrors.FromError(err)` 取 `Code / Reason / Message` 按同一张表映射；`reason`（如 `USER_NOT_FOUND`）只进日志与指标。

## 七、测试断言示例

```go
func TestGetUser_NotFound(t *testing.T) {
    gin.SetMode(gin.TestMode)
    r := gin.New()
    r.Use(middleware.ErrorHandler(zap.NewNop()))
    r.GET("/users/:id", func(c *gin.Context) {
        c.Error(errs.ErrNotFound)
        c.Abort()
    })

    w := httptest.NewRecorder()
    r.ServeHTTP(w, httptest.NewRequest(http.MethodGet, "/users/0", nil))
    require.Equal(t, http.StatusNotFound, w.Code)

    var body map[string]any
    require.NoError(t, json.Unmarshal(w.Body.Bytes(), &body))
    assert.EqualValues(t, 40401, body["code"])
    assert.NotContains(t, body["message"], "sql") // 不泄漏内部信息
}
```

## 常见坑

1. **`c.Error` 后继续写响应**：错误链不会自动中止，会出现两段 Body；必须 `Abort(); return`。
2. **先 `c.JSON` 再 `c.Error`**：中间件重复写导致 `headers already written`；响应只写一次。
3. **用 `==` 比较包装后的错误**：`%w` 后不是同一实例；用 `errors.Is` / `errors.As`。
4. **把根因拼进 `Message`**：SQL、内网地址、下游服务名会泄漏；根因只进日志字段。
5. **ErrorHandler 注册在路由之后**：前面路由不经过它，错误被静默丢弃。
6. **在 goroutine 里 `c.Error`**：请求已结束，中间件早返回；异步任务只写日志。

## 小结

- `c.Error` 只收集不输出，ErrorHandler 在 `c.Next()` 返回后统一结算。
- 业务错误用 `Code / Message / HTTPStatus` 三段式，根因用 `%w` 保留但不下发。
- 非预期错误统一 50001，堆栈用 `debug.Stack()` 只写日志。
- gRPC / Kratos 错误按表映射，未知错误降级为内部错误。
- 错误路径必须有断言：状态码、业务码、不泄漏。
