# 响应与渲染

> 一句话定位：响应本质是往 `ResponseWriter` 写字节；`c.JSON` 系列负责序列化，`c.HTML/c.File/c.Data` 负责渲染，而统一封装与状态码规范决定了 API 是否可维护。

## 本篇目标

- 掌握 `c.JSON`、`c.PureJSON`、`c.IndentedJSON` 的差异与安全边界。
- 会输出 XML/YAML/HTML 模板，以及 `c.Data/c.String/c.File/c.Redirect`。
- 设计统一响应封装与分页结构，避免每个 handler 各写一套。
- 按 `Accept` 做内容协商，并为场景选对 HTTP 状态码。

## 一、三种 JSON

| 方法 | 特点 | 使用场景 |
| --- | --- | --- |
| `c.JSON` | 标准序列化，转义 `<`、`>`、`&` | 默认选择 |
| `c.PureJSON` | 不转义 HTML 字符 | 返回值本身是 HTML 片段 |
| `c.IndentedJSON` | 带缩进，体积大 | 调试、人工排查 |
| `c.SecureJSON` | 加 `while(1);` 前缀 | 兼容老浏览器防 JSON 劫持 |

```go
type User struct {
    ID   int64  `json:"id"`
    Name string `json:"name"`
}

c.JSON(http.StatusOK, gin.H{"code": 0, "data": User{ID: 1, Name: "tom"}})
c.IndentedJSON(http.StatusOK, User{ID: 1, Name: "tom"})
c.PureJSON(http.StatusOK, gin.H{"snippet": "<b>hi</b>"}) // 输出原样 <b>hi</b>
```

`c.JSON` 会把 `<` 写成 `\u003c`，这层转义能防止有人用 `</script><script>...` 从 JSON 里「逃逸」到 HTML 页面。`PureJSON` 关闭了它，只适合「前端自己处理这段 HTML」的明确场景；**不要**把 `PureJSON` 的结果直接嵌进 HTML。响应一律带 `Content-Type`，Gin 自动加 `application/json; charset=utf-8`。

## 二、统一响应封装与分页

```go
// app/gateway/internal/response/response.go
type Body struct {
    Code      int    `json:"code"`
    Message   string `json:"message"`
    Data      any    `json:"data,omitempty"`
    RequestID string `json:"request_id,omitempty"`
}

func OK(c *gin.Context, data any) {
    c.JSON(http.StatusOK, Body{Code: 0, Message: "ok", Data: data, RequestID: c.GetString("meta.request_id")})
}

func Fail(c *gin.Context, status, code int, msg string) {
    c.AbortWithStatusJSON(status, Body{Code: code, Message: msg, RequestID: c.GetString("meta.request_id")})
}

type Page[T any] struct {
    List     []T   `json:"list"`
    Total    int64 `json:"total"`
    Page     int   `json:"page"`
    PageSize int   `json:"page_size"`
}
```

约定：HTTP 状态码表达「协议层结果」，`code` 表达「业务结果」。成功固定 `code=0`，失败用 `40100`、`42200` 这类五位码，前三位与 HTTP 状态码对齐，排查时不用查表。

## 三、XML / YAML / HTML 模板

```go
// 启动时：r.LoadHTMLGlob("templates/*.tmpl")
c.XML(http.StatusOK, gin.H{"code": 0, "data": user})
c.YAML(http.StatusOK, gin.H{"code": 0, "data": user})
c.HTML(http.StatusOK, "user.tmpl", gin.H{"name": user.Name}) // 模板变量自动转义
```

```html
<!-- templates/user.tmpl -->
<!doctype html>
<html><body><h1>Hello {{ .name }}</h1></body></html>
```

`html/template` 默认对变量做 HTML 转义，能挡住大部分 XSS；只有完全可信的内容才用 `template.HTML` 强转。忘记 `LoadHTMLGlob` 时 `c.HTML` 会 panic，模板名写错则返回 500，两类问题都建议启动时自检一次。

## 四、Data / String / File / Redirect

```go
c.String(http.StatusOK, "pong %s", name)                  // 纯文本，支持格式化
c.Data(http.StatusOK, "application/octet-stream", buf)    // 原始字节
c.File("./static/logo.png")                               // 按扩展名推断 Content-Type，支持 Range
c.FileAttachment("./tmp/report.pdf", "report.pdf")        // 触发下载，带 Content-Disposition
c.Redirect(http.StatusFound, "/login")                    // 302，写 Location
c.Status(http.StatusNoContent)                            // 204，不写 body
```

重定向状态码别乱选：`301/308` 是永久重定向（会被浏览器/网关缓存），`302/307` 是临时；`307/308` 保证方法与方法体不变，`301/302` 在部分客户端会被改成 GET。登录跳转、尾斜杠纠正用 302，域名迁移才用 301。

## 五、内容协商

```go
func (h *UserHandler) Get(c *gin.Context) {
    u := User{ID: 1, Name: "tom"}
    switch c.NegotiateFormat(gin.MIMEJSON, gin.MIMEXML, gin.MIMEYAML) {
    case gin.MIMEXML:
        c.XML(http.StatusOK, u)
    case gin.MIMEYAML:
        c.YAML(http.StatusOK, u)
    default: // 客户端没写 Accept 或都不匹配时回落 JSON
        c.JSON(http.StatusOK, u)
    }
}
```

`NegotiateFormat` 按 `Accept` 的 `q` 值挑选第一个可接受的类型，未命中返回空串。对外的开放 API 才需要协商；内部服务的响应格式固定 JSON 就好，少一层不可控。

## 六、状态码怎么选

| 场景 | 状态码 |
| --- | --- |
| 查询/更新成功返回数据 | `200` |
| 创建成功 | `201` + `Location` 头 |
| 已接受、异步处理 | `202` |
| 删除成功且无返回体 | `204` |
| 参数格式错误（JSON 语法、类型） | `400` |
| 未认证 / 无权限 | `401` / `403` |
| 资源不存在 / 冲突 / 不支持的类型 | `404` / `409` / `415` |
| 参数校验失败 | `422` |
| 限流 / 服务端异常 / 依赖不可用 | `429` / `500` / `503` |

最常见的错误是「一律 200，靠 code 区分成败」：监控、告警、网关重试都会失真。正确做法是两层都用：HTTP 码给基础设施，`code` 给业务方。

## 完整示例

```go
// app/gateway/cmd/main.go（HTML / 文件 / 204 的调用见第三、四节）
package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.New()
    r.GET("/users/:id", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"code": 0, "data": gin.H{"id": 1, "name": "tom"}})
    })
    r.GET("/old", func(c *gin.Context) { c.Redirect(http.StatusFound, "/users/1") })

    if err := r.Run("127.0.0.1:8080"); err != nil { panic(err) }
}
```

Windows PowerShell：

```powershell
go run .
curl.exe -i http://127.0.0.1:8080/users/1
curl.exe -i http://127.0.0.1:8080/old
```

Linux / macOS bash：

```bash
go run .
curl -i http://127.0.0.1:8080/users/1
curl -i http://127.0.0.1:8080/old
```

## 常见坑

1. **`c.JSON` 之后继续写**：响应已提交，Gin 打印 `headers were already written`，后续写入被丢弃。
2. **用 `PureJSON` 输出嵌进页面的数据**：`</script>` 可能逃逸，等于给 XSS 开门。
3. **错误也返回 200**：负载均衡、监控、重试全部失效，`code` 再细也救不回来。
4. **204 还写 body**：协议不允许，部分客户端直接报错。
5. **301 用在临时跳转**：浏览器长期缓存，改不回来。
6. **模板名或路径写错**：`c.HTML` 返回 500，模板变量拼错则静默输出空串。

## 小结

- `c.JSON` 是安全默认值，`PureJSON` 只在明确场景使用，`IndentedJSON` 只用于调试。
- 统一响应把「HTTP 状态码」与「业务 code」分开，分页用泛型结构复用。
- 模板、文件、原始字节各有专用方法，重定向要区分临时与永久。
- 内容协商适合开放 API，内部服务固定 JSON 更省心。
