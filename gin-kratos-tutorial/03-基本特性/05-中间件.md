# 中间件

> 一句话定位：中间件就是同一条 handler 链上的函数；Gin 在引擎最外层只调用一次 `c.Next()`，所以**不写 Next，后面的 handler 照样执行**，`Next` 的唯一用途是「先把后续跑完，再回来做后置逻辑」。

## 本篇目标

- 准确理解中间件签名、洋葱模型与 `Next`/`Abort` 的真实语义。
- 掌握全局、路由组、单路由三种注册方式，以及日志、CORS、JWT、Recovery、超时中间件。
- 用 `c.Set` 传递用户信息，并知道为什么 goroutine 里要用 `c.Copy()`。

## 一、签名与洋葱模型

中间件签名就是 handler 签名：`type HandlerFunc func(*gin.Context)`，一条链是 `[]HandlerFunc`。

引擎的执行逻辑是 `c.handlers = chain; c.Next()`，而 `Next` 内部就是 `index++` 后用 `for` 循环依次调用 `handlers[index]`，直到 `index` 走到链尾。由此可以推出四条结论：

- 中间件**不调用** `Next`，返回后外层循环仍会继续执行下一个 handler，请求不会被截断。
- 想让代码在 handler 之后执行（计时、改响应头），必须调用 `c.Next()`，因为它是「就地展开剩余链」。
- 同一个中间件里 `Next` 调两次，剩余链会跑两遍，这是典型事故。
- `c.Abort()` 把 `index` 设成 `abortIndex`，外层循环立刻结束；它不会中断当前函数，所以后面要 `return`。

```go
func A() gin.HandlerFunc {
    return func(c *gin.Context) {
        log.Println("A before")
        c.Next() // 进入 B 与业务 handler，跑完再回来
        log.Println("A after")
    }
}

// B 写法相同；r.Use(A(), B()); r.GET("/x", handler)
// 输出：A before → B before → handler → B after → A after
```

只有前置逻辑（如写一个响应头）的中间件可以不写 `Next`，但团队统一写 `Next` 更不容易误解；有后置逻辑则**必须**写。

## 二、注册方式与顺序

```go
r := gin.New()
r.Use(gin.Recovery(), RequestID(), AccessLog()) // 全局，按注册顺序执行

api := r.Group("/api/v1", Auth(secret)) // 组级：该组所有路由生效
api.GET("/profile", h.Profile)
r.GET("/public", h.Public, RateLimit()) // 单路由：排在全局与组之后
```

顺序原则：

- `Recovery` 放最外层（第一个），才能兜住后面所有 panic；`RequestID` 要在 `AccessLog` 之前，日志里才有 ID。
- 鉴权放在组级，公开接口不要挂；不要在鉴权前做重业务查询。组中间件只对组内路由生效，全局中间件对 `NoRoute` 也生效。

## 三、RequestID 与访问日志

```go
const ctxRequestID = "meta.request_id"

func RequestID() gin.HandlerFunc {
    return func(c *gin.Context) {
        id := cmp.Or(c.GetHeader("X-Request-Id"), uuid.NewString())
        c.Set(ctxRequestID, id)
        c.Header("X-Request-Id", id)
        c.Next()
    }
}

func AccessLog() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        c.Next() // 先执行后续，才能拿到最终状态码
        log.Printf("method=%s path=%s status=%d cost=%s rid=%s err=%s",
            c.Request.Method, c.FullPath(), c.Writer.Status(),
            time.Since(start), c.GetString(ctxRequestID), c.Errors.String())
    }
}
```

- 用 `c.FullPath()` 而不是 `c.Request.URL.Path`，避免日志被 ID 打散；`c.Writer.Status()` 在 `Next` 返回后才是最终值，提前读只会得到 200。

## 四、CORS、JWT、Recovery、超时

CORS 手写足够用，关键是预检请求要 `Abort` 掉：

```go
func CORS(allowOrigin string) gin.HandlerFunc {
    return func(c *gin.Context) {
        if o := c.GetHeader("Origin"); o == allowOrigin {
            c.Header("Access-Control-Allow-Origin", o)
            c.Header("Vary", "Origin")
            c.Header("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE,OPTIONS")
            c.Header("Access-Control-Allow-Headers", "Authorization,Content-Type,X-Request-Id")
        }
        if c.Request.Method == http.MethodOptions {
            c.AbortWithStatus(http.StatusNoContent) // 预检直接结束，不进业务
            return
        }
        c.Next()
    }
}
```

JWT 鉴权（`github.com/golang-jwt/jwt/v5`）：

```go
func Auth(secret []byte) gin.HandlerFunc {
    return func(c *gin.Context) {
        raw := strings.TrimPrefix(c.GetHeader("Authorization"), "Bearer ")
        token, err := jwt.Parse(raw, func(t *jwt.Token) (any, error) { return secret, nil },
            jwt.WithValidMethods([]string{"HS256"})) // 固定算法，防 alg 混淆
        if err != nil || !token.Valid {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"code": 40100, "message": "未登录"})
            return
        }
        claims, _ := token.Claims.(jwt.MapClaims)
        uid, _ := claims["uid"].(float64) // JWT 数字都是 float64
        c.Set(ctxUserID, int64(uid))
        c.Next()
    }
}
```

Recovery 与超时（`Timeout` 中间件与 [02 篇第五节](02-请求上下文Context.md)相同，不再重复）：

```go
r.Use(gin.CustomRecovery(func(c *gin.Context, recovered any) {
    log.Printf("panic recovered: %v", recovered)
    c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"code": 50000, "message": "服务器内部错误"})
}))
```

生产环境还要用 `http.Server` 的读写超时兜底，见 [07-优雅退出](./07-优雅退出.md)。

## 五、c.Set 与 goroutine

中间件里直接起 goroutine 却引用原 `c`，会在 handler 结束、`c` 被 reset 后读到别的请求数据。异步任务用 `c.Copy()`（它在副本里保留 `Keys`，中间件 `Set` 的值仍可读），或进 goroutine 前把值抽成普通变量，并传 `context.WithoutCancel` 后的 ctx。原理与示例见 [02 篇第四节](02-请求上下文Context.md)。

## 完整示例

```go
// app/gateway/cmd/main.go
package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

func main() {
    r := gin.New()
    r.Use(gin.Recovery(), RequestID(), AccessLog())

    api := r.Group("/api/v1")
    auth := api.Group("", func(c *gin.Context) { // 组内鉴权：示例用静态 token
        if c.GetHeader("Authorization") != "Bearer dev-token" {
            c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"code": 40100, "message": "未登录"})
            return
        }
        c.Set(ctxUserID, int64(1))
        c.Next()
    })
    auth.GET("/profile", func(c *gin.Context) {
        c.JSON(http.StatusOK, gin.H{"code": 0, "data": gin.H{"uid": c.GetInt64(ctxUserID)}})
    })

    if err := r.Run("127.0.0.1:8080"); err != nil { panic(err) }
}
```

## 常见坑

1. **以为不写 `Next` 会中断请求**：不会，后续 handler 照常执行；要中断用 `Abort` 并 `return`，只 `Abort` 不 return 则本函数继续跑。
2. **`Next` 调用两次**：剩余链执行两遍，日志、扣款、写库都会重复。
3. **`Next` 之前读 `c.Writer.Status()`**：永远是 200，日志失真。
4. **中间件里起 goroutine 用原 Context**：数据竞争读到别人请求，必须 `c.Copy()`。
5. **把 `Recovery` 放在链尾**：前面的 panic 兜不住，服务直接退出。

## 小结

- 引擎只调一次 `Next`，中间件不写 `Next` 后续仍执行；`Next` 是「展开剩余链以便做后置」。
- `Abort` 只改执行索引，不终止当前函数，必须配合 `return`。
- 顺序即语义：Recovery 最外层，RequestID 先于日志，鉴权挂组；超时靠 context 传播，异步任务用 `c.Copy()`。
