# 工程工具链全景

> 一句话定位：能长期维护的 Go 服务靠分工明确的工具链——air 管热重载、swag 管 HTTP 文档、buf 管 proto、wire 管依赖注入、golangci-lint 与 govulncheck 管质量与漏洞、kratos CLI 管骨架、dlv 与 pprof 管排障，最后由一份 Makefile 收成唯一入口。

## 本篇目标

- 说清 12 个工具各自解决什么问题、什么时候跑、产物是什么
- 用 `tools.go` + `go.mod` 把工具版本钉死，让本地、同事、CI 三方一致
- 写出一份覆盖 `fmt/vet/lint/test/build/proto/swag` 的 Makefile，新人只需 `make dev`
- 跑通「改 proto → 生成 → 编译 → 热重载 → 校验」的本地闭环
- 会用 pprof 与 dlv 拿数据定位问题，而不是靠改代码打日志

## 前置知识

- 已读 [Go Module 与国内代理](../00-开始之前/03-Go-Module与国内代理.md)，已配置 `GOPROXY`
- 已读 [Gin 工程化脚手架与代码生成](../02-Gin入门/03-Gin工程化脚手架与代码生成.md)，了解 `api/ app/ pkg/ configs/` 约定

## 一、工具分工总表

| 工具 | 解决的问题 | 产物 | 何时运行 |
| --- | --- | --- | --- |
| Go 1.25 | 语言与编译工具链 | 二进制 | 始终 |
| air | 改代码手动重启太慢 | 自动重启的进程 | 本地常驻 |
| swag | HTTP 文档手写、易过期 | `docs/`（OpenAPI） | 改 handler 注解后 |
| wire | 依赖装配手写、启动顺序易错 | `wire_gen.go` | 改 provider 后 |
| mockgen | 接口 mock 手写量大 | `*_mock.go` | 改接口后 |
| golangci-lint | 检查规则分散、标准不一 | 检查报告 | 提交前 / CI |
| govulncheck | 依赖漏洞靠人盯 CVE | 漏洞报告 | 每周 + CI |
| buf | proto 的 lint、兼容性、生成 | `*.pb.go` | 改 `.proto` 后 |
| protoc-gen-go / -go-grpc | proto 编译插件 | 消息体与服务桩 | 由 buf 调用 |
| kratos CLI | 服务骨架、proto 样板重复 | 服务目录 | 新建服务时 |
| dlv | 断点调试靠 `println` | 调试会话 | 排查逻辑错误 |
| pprof | 性能问题靠猜 | profile 文件 | 压测 / 线上排查 |

原则只有一条：**生成物一律不手改**。`docs/`、`*.pb.go`、`wire_gen.go`、`*_mock.go` 出问题，要回到源头（注解、proto、provider、接口定义），否则下一次生成全部丢失。

```powershell
# 安装命令同上；Windows 一律装到 %USERPROFILE%\go\bin，新开终端才生效
```

## 三、tools.go：让版本跟着代码走

```go
// tools/tools.go
//go:build tools

package tools

// 空导入把工具模块写进 go.mod / go.sum，
// 之后在仓库内执行 go install <pkg>（不带 @version）就会用这里的版本。
import (
	_ "github.com/air-verse/air"
	_ "github.com/bufbuild/buf/cmd/buf"
	_ "github.com/go-kratos/kratos/cmd/kratos/v2"
	_ "github.com/golangci/golangci-lint/v2/cmd/golangci-lint"
	_ "github.com/google/wire/cmd/wire"
	_ "github.com/swaggo/swag/cmd/swag"
	_ "go.uber.org/mock/mockgen"
	_ "golang.org/x/vuln/cmd/govulncheck"
)
```

```bash
go mod tidy                 # 把工具版本写进 go.mod
go install github.com/google/wire/cmd/wire   # 不带 @version，取 go.mod 版本
```

好处很直接：升级 golangci-lint 变成一次 `go get` + 一次 commits，review 里看得见；CI 里 `go install` 不再依赖当天下载到的最新版，避免「本地过、CI 挂」。

## 四、Makefile：所有命令一个入口

```text
# Makefile（仓库根；命令前必须是 Tab，不是空格）
GO      := go
LDFLAGS := -s -w -X main.Version=$(shell git describe --tags --always)

.PHONY: fmt vet lint test build proto swag dev ci

fmt:
	$(GO) fmt ./... && swag fmt

vet:
	$(GO) vet ./...

lint:
	golangci-lint run ./...

test:
	$(GO) test -race -coverprofile=coverage.out ./...

build:
	$(GO) build -trimpath -ldflags "$(LDFLAGS)" -o bin/gateway ./app/gateway/cmd

proto:
	buf lint && buf generate && $(GO) build ./...

swag:
	swag init -g app/gateway/cmd/main.go -o docs --parseDependency --parseInternal

dev:
	air

ci: fmt vet lint test build
```

`ci` 目标就是流水线里那条命令：少了任何一步，本地与 CI 就会漂移。Windows 上 `make` 不自带，用 Git Bash / WSL 执行，或改用 `go run mage.go`、`task`，目标集合保持一致。

## 六、pprof 与 dlv：拿数据而不是猜

```go
// app/gateway/cmd/pprof.go
package main

import (
	"net/http"
	_ "net/http/pprof" // 注册 /debug/pprof/* 到 DefaultServeMux
)

// startPprof 独立端口（约定 9101），禁止与业务端口共用。
func startPprof(addr string) {
	go func() { _ = http.ListenAndServe(addr, nil) }()
}
```

```bash
go tool pprof -http=:8081 'http://127.0.0.1:9101/debug/pprof/profile?seconds=30'
dlv debug ./app/gateway/cmd -- -conf ./configs
```

`profile` 采 30 秒有可见 CPU 开销，避开高峰；生产不要把 pprof 挂到公网端口，用 `kubectl port-forward` 或堡垒机。压测方法见 [性能调优与压测](../08-部署与运维/04-性能调优与压测.md)。

## 常见坑

1. **air 重启后端口占用**：进程没处理 SIGTERM，旧进程仍监听 8080；补 `srv.Shutdown`（见 [优雅退出](../03-基本特性/07-优雅退出.md)）或配 `kill_delay`。
2. **把 `docs/`、`*.pb.go`、`wire_gen.go` 当源码改**：下次生成即覆盖，还会掩盖真正的源头问题；只改注解、proto、provider。
3. **wire 报 `multiple bindings`**：两个 provider 返回同一类型；用 `wire.NewSet` 配 `wire.Bind` 或具名类型区分。
4. **工具全装 `@latest`**：昨天生成的代码今天重新生成就变了，review 无法复现；用 `tools.go` 钉版本。
5. **buf 生成多一层目录**：`out` 写成 `api` 又叠加 `paths=source_relative`，得到 `api/api/user/v1`；`out` 用仓库根 `.`。
6. **golangci-lint 本地 v1 配置、CI 装 v2**：配置格式不兼容直接报错；配置文件与二进制版本一起钉。
7. **pprof 挂业务端口且对公网开放**：`/debug/pprof/heap` 泄露内存中的密钥与调用栈，等于递地图。
8. **swag 生成了但不提交**：别人 clone 后编译缺 `docs` 包、`/swagger` 404；生成物入库并由 CI 校验无 diff。

## 小结

- 核心是「源头可改、产物不改」：注解 → docs，proto → pb.go，provider → wire_gen.go，接口 → mock
- air 解决反馈速度，wire 解决启动顺序，buf 解决契约一致性，govulncheck 解决依赖安全
- 版本用 `tools.go` 锁进 go.mod，比文档里写「请安装最新版」可靠得多
- Makefile 只做一件事：让新人一条 `make dev` 就能跑起来，CI 复用同一组目标
