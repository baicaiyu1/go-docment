# 常见坑与最佳实践

> 一句话定位：Gin + Kratos 的线上事故大多不是框架 bug，而是 Context 用错、超时没透传、错误码乱映射、上游依赖每请求重建、配置与密钥进了仓库——本篇按 Gin 侧、Kratos 侧、工程侧三组逐条给出正确做法。

## 本篇目标

- 说清 Gin 里九个高频坑的症状与正确写法（含 `c.Copy()`、`c.Next()` 语义）
- 让超时与 trace 从 HTTP 入口一路透传到 gRPC 下游，不被 `context.Background()` 截断
- 把 gRPC 客户端做成启动期单例，并用 `discovery:///` + Registry 完成服务发现
- 补齐工程侧底线：版本锁定、配置不泄漏、日志脱敏、优雅退出、可观测性

## 一、Gin 侧：九个高频坑

| 坑 | 症状 | 正确做法 |
| --- | --- | --- |
| 路由冲突 | 启动 panic：`'info' in new path conflicts with existing wildcard ':id'` | 同一层级不要混用静态段与通配段，静态路由换前缀（`/search/users`） |
| Context 复用 | goroutine 里读到别的请求参数 | goroutine 内用 `c.Copy()`，并自建超时 |
| 绑定错误 | 参数校验失败返回 500 | `errors.As` 到 `validator.ValidationErrors` 返回 400 |
| 中间件顺序 | 耗时统计恒为 0、CORS 预检 401 | Recovery 最先注册；CORS 在鉴权前并处理 `OPTIONS` |
| CORS | 浏览器报跨域、cookie 不生效 | 用 `gin-contrib/cors`，`AllowCredentials` 不能配 `*` |
| 超时 | 慢连接占满连接、SSE 被截断 | `http.Server` 三个超时 + 业务 ctx 超时；SSE 关 `WriteTimeout` |
| JSON 精度 | 前端 id 末位变 0 | int64 ID 用 `json:"id,string"` 或直接返回 string |
| 上传内存 | 大文件 OOM | `r.MaxMultipartMemory` 限内存 + 校验大小/类型/文件名 |
| 测试模式 | 单测日志刷屏、行为与生产不一致 | `gin.SetMode(gin.TestMode)` + `httptest` |

前两条是最容易误判的语义，先把代码写对：

```go
// app/gateway/internal/handler/notify.go
func (h *Handler) Notify(c *gin.Context) {
	// 错误：请求结束后 c 与 c.Request 会被回收/复用
	// go func() { _ = h.push(c.Request.Context(), c.Param("id")) }()

	// 正确：Copy 出只读快照，再脱离取消链并自建超时
	cc := c.Copy()
	go func() {
		ctx, cancel := context.WithTimeout(context.WithoutCancel(cc.Request.Context()), 3*time.Second)
		defer cancel()
		_ = h.push(ctx, cc.Param("id"))
	}()
	c.JSON(http.StatusAccepted, gin.H{"code": 0, "message": "ok"})
}
```

```go
// app/gateway/internal/middleware/timing.go
func Timing(logger *zap.Logger) gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next() // 显式推进后续 handler，回来才是真实耗时
		logger.Info("http_access",
			zap.String("route", c.FullPath()),
			zap.Int("status", c.Writer.Status()),
			zap.Int64("latency_ms", time.Since(start).Milliseconds()),
		)
	}
}
```

Gin 引擎最外层已经调用过一次 `c.Next()`：中间件不写 `c.Next()`，后续 handler 仍会执行，但会在该中间件返回**之后**执行——你写在后半段的计时、统计会先跑完，数据全失真。要「包住」后续处理必须显式 `c.Next()`；阻止后续 handler 用 `c.Abort()`。

```go
// app/gateway/internal/router/router.go
func New() *gin.Engine {
	r := gin.New()
	_ = r.SetTrustedProxies(nil)                           // 不信任任意 X-Forwarded-For
	r.MaxMultipartMemory = 8 << 20                          // 上传超过 8MB 落临时文件
	r.Use(gin.Recovery(), requestid.New(), middleware.Logger(lg))
	r.Use(cors.New(cors.Config{                             // CORS 必须在鉴权之前
		AllowOrigins:     []string{"https://admin.example.com"}, // 与 AllowCredentials 同用时禁止 *
		AllowMethods:     []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
		AllowHeaders:     []string{"Authorization", "Content-Type", "X-Request-ID"},
		AllowCredentials: true,
		MaxAge:           12 * time.Hour,
	}))
	r.Use(middleware.JWT(cfg.JWT.Secret), middleware.ErrorHandler())
	return r
}
```

上传还要单独校验：`c.FormFile` 拿到文件后检查 `f.Size`，用 `http.DetectContentType` 验真实类型，落盘时 `filepath.Base(f.Filename)` 并重命名，禁止把用户文件名直接拼路径。JSON 精度问题只在跨语言/JS 客户端出现，最省事的解法是**所有 ID 对外都是 string**。

## 二、Kratos 侧：五个高频坑

| 坑 | 症状 | 正确做法 |
| --- | --- | --- |
| 客户端每请求建连 | fd 暴涨、延迟抖动 | 启动时建一次 conn，注入 handler |
| ctx 不透传 | 下游收不到超时/trace | 用 `c.Request.Context()`，禁止 `context.Background()` |
| 注册 TTL 不合理 | 实例抖动被摘 / 宕机后仍收流量 | TTL 10~30s，大于心跳间隔；确认续租成功 |
| proto 不兼容 | 老客户端反序列化错乱 | 字段只增不复用编号，删字段 `reserved` |
| 错误码乱用 | 500 掩盖业务错误 | `errors.New(400, "USER_NOT_FOUND", "...")`，reason 大写下划线 |

```go
// app/gateway/internal/client/user.go
func NewUserClient(reg discovery.Discoverer, logger log.Logger) (v1.UserServiceClient, error) {
	conn, err := grpc.DialInsecure(context.Background(),
		grpc.WithEndpoint("discovery:///user-service"), // 地址来自注册中心，不写 IP
		grpc.WithDiscovery(reg),
		grpc.WithMiddleware(recovery.Recovery(), tracing.Client(), logging.Client(logger)),
	)
	if err != nil {
		return nil, err
	}
	return v1.NewUserServiceClient(conn), nil
}
```

```go
// app/gateway/internal/handler/order.go
func (h *OrderHandler) Get(c *gin.Context) {
	ctx, cancel := context.WithTimeout(c.Request.Context(), 800*time.Millisecond)
	defer cancel()

	reply, err := h.orderCli.GetOrder(ctx, &v1.GetOrderRequest{Id: c.Param("id")}) // ctx 原样透传
	if err != nil {
		_ = c.Error(err) // 交给 ErrorHandler 统一映射，不在这里判断 gRPC code
		c.Abort()
		return
	}
	c.JSON(http.StatusOK, gin.H{"code": 0, "message": "ok", "data": reply})
}
```

服务端构造错误：`errors.BadRequest("USER_NOT_FOUND", "user not found")` 或 `errors.New(404, "ORDER_NOT_FOUND", "...")`。网关只做 `Reason → 业务码` 映射，绝不把 `err.Error()` 原文返回给客户端——里面常有下游地址、SQL 和堆栈。

## 三、工程侧：五条底线

| 项 | 事故形态 | 正确做法 |
| --- | --- | --- |
| 版本锁定 | 重新生成代码 diff 遍地 | go.mod + `tools.go` + CI 固定版本 |
| 配置泄漏 | 仓库里出现生产 DSN/密钥 | 敏感项只从环境变量/Secret 注入 |
| 日志脱敏 | 日志里出现 token、手机号 | 统一 mask 函数，禁止打印 Authorization |
| 优雅退出 | 发版丢请求、端口占用 | `signal.NotifyContext` + `Shutdown`；Kratos 用 `app.Stop` |
| 可观测性缺失 | 出事只能靠用户反馈 | RED 指标 + trace_id + 结构化日志三件套 |

```go
// app/gateway/cmd/main.go
srv := &http.Server{Addr: ":8080", Handler: r, ReadHeaderTimeout: 5 * time.Second}

ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
defer stop()
go func() { _ = srv.ListenAndServe() }()
<-ctx.Done()

shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(shutdownCtx) // 先停止收新请求，再等在途请求结束
```

日志脱敏统一走 `pkg/logger` 的 mask 函数（如 `MaskPhone`），记录时永远不带敏感原文；完整脱敏 Core 见 [日志与中间件扩展](../05-治理与扩展/07-日志与中间件扩展.md)。

## 常见坑

1. **goroutine 里直接用 `c.Param`/`c.Get`**：请求结束后 Context 被放回复用池，偶发读到别的请求参数；必须 `c.Copy()`。
2. **`ShouldBindJSON` 报错一律 500**：校验失败是客户端问题；`errors.As` 到 `validator.ValidationErrors` 返回 400，其它解析错误返回 40002。
3. **handler 里 `context.Background()`**：超时、取消、trace 全断，下游卡死时网关永不放行；用 `c.Request.Context()`。
4. **Viper 只开 `AutomaticEnv` 就 `Unmarshal`**：环境变量不生效，容器里连本地库；关键 key 显式 `BindEnv`。
5. **注册 TTL 设成 3 秒或 5 分钟**：前者网络抖动即摘实例，后者宕机后流量继续打进来；10~30 秒并监控续租。
6. **响应里返回 `err.Error()`**：泄露下游地址、SQL、堆栈；日志记全量，响应只给业务码 + 一句人话。

## 小结

- Gin 两条语义必须记住：goroutine 用 `c.Copy()`，耗时统计显式 `c.Next()`；绑定错误分类出口（客户端 400 / 服务端 500）
- Kratos 客户端是启动期单例，超时预算从入口向下分配，`context.Background()` 是链路与超时的双重杀手
- 工程底线比框架技巧更值钱：密钥不进仓库、日志要脱敏、退出要优雅、指标要能报警

## 练习

1. 写一个 goroutine 里直接读 `c.Param` 的接口，用 `-race` 压测复现，再改成 `c.Copy()` 对比。
2. 给 `Timing` 中间件去掉 `c.Next()`，观察耗时从 20ms 变成 0，并解释原因。
3. 把 `grpc.DialInsecure` 移到 handler 内部，用 `ghz` 压测对比启动期单例的 QPS 与 fd 数量。
