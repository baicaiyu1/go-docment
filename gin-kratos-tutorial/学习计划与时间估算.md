# 学习计划与时间估算

> 一句话定位：按依赖关系给出 96 篇教程的推荐学习顺序、逐篇学时、20 周计划与里程碑验收标准，并明确「学完 = 企业级」的判定口径。

## 本篇目标

- 明确「目录编号」与「推荐学习顺序」的差异，避免学到一半接不上
- 拿到逐篇阅读与动手学时，能排出自己的周计划
- 用里程碑验收代替「看完了」，确保每一步真的会
- 理性判断：学完本教程达到什么水平、还差什么

## 一、推荐学习顺序

大方向是「基础 → 框架 → 数据 → 微服务 → 实战 → 部署」，但有三处需要交叉：

| # | 现象 | 后果 | 修正 |
| --- | --- | --- | --- |
| 1 | 04 可观测性排在 08 部署之前 | 学埋点时还没起 Prometheus/Jaeger | 先在 08/05 或 13/06 起观测栈，再回看 04/03 |
| 2 | 05 治理排在 12 微服务之前 | 没有 RPC 服务时学注册发现只能死记 | 05/01-02 先概念速览，实操放 12/05 |
| 3 | 07 工程化排在 09-11 数据层之前 | 分层示例里没有 MySQL/Redis 可落 | 07 放到 09-11 之后学 |

## 五、企业级达标判定

学完本教程，你应当能独立做到：

- 设计并实现「网关 + BFF + 领域服务」的分层微服务，边界清晰
- 用 Proto 定义契约，gRPC 通信，注册发现与负载均衡，超时预算合理
- 每服务独立 DB，GORM 事务、乐观锁、防超卖、N+1 治理
- Redis 缓存与锁的正确用法，能讲清缓存三问题的解法与代价
- Kafka 可靠投递、幂等消费、Outbox 最终一致
- 结构化日志 + 指标 + 链路三件套用同一 ID 串联
- Sentinel 限流熔断配置化，APISIX 网关做鉴权、限流、灰度
- Docker/K8s 部署、健康检查、优雅退出、HPA 与告警
- 写得出测试（单元/集成/压测），接得上 CI 与质量门禁

**还差什么**：真实高并发调优经验、多活与容灾、服务网格（Istio）、大规模数据分库分表、团队协作与发布流程。这些需要在真实项目中继续积累，教程提供的是可迁移的底座。

## 六、学习建议

1. **先跑通再深挖**：每个示例必须本机跑起来，报错信息比文档更能教会你。
2. **动手不能省**：中间件顺序、绑定失败、优雅退出、超时传播，只看文字学不会。
3. **一个项目贯穿到底**：所有示例尽量落到 `mall-lite`，避免知识点各自为战。
4. **每章做完练习再前进**，卡住时回看前置篇目，而不是跳到下一章。
