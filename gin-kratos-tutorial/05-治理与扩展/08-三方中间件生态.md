# 三方中间件生态

> 一句话定位：Gin 与 Kratos 的生态都分成「框架核心 / 官方 contrib / 社区仓库」三层，能上生产的不是最热门的那个，而是维护活跃、许可证干净、只依赖稳定接口、能被一层薄封装替换掉的那个。

## 本篇目标

- 分清 `gin-contrib/*`、Kratos `contrib/*`、个人仓库三层的边界，并会做 A/B/C 分级。
- 装配一套网关中间件：cors、requestid、JWT、zap 访问日志、Prometheus、otelgin。
- 掌握 Kratos contrib 的 registry / config / log 接入，知道 tracing 属于核心中间件。
- 建立选型评分卡、依赖收敛与升级纪律，并说清 Sentinel 与 APISIX 的分工。

## 前置知识

- 已读 [中间件](../03-基本特性/05-中间件.md)，知道 `c.Next()` 是「先跑后续 handler，再回来做后置逻辑」。
- 已读 [配置管理 Viper](03-配置管理Viper.md)、[etcd 与 Consul 接入](02-etcd与Consul接入.md)、[监控扩展 Prometheus](05-监控扩展Prometheus.md)。

## 一、三层依赖，三种信任级别

| 层 | 例子 | 维护方 | 引入策略 |
| --- | --- | --- | --- |
| 框架核心 | `gin-gonic/gin`、`go-kratos/kratos/v2` | 官方团队 | 直接用，跟次版本升级 |
| 官方 contrib | `gin-contrib/*`、`kratos/contrib/*` | 官方组织下独立仓库 | 评估后引入，锁版本 |
| 社区仓库 | 个人 GitHub 项目 | 个人 / 小团队 | 读源码 + 薄封装，准备 fork |

`contrib` 不等于「官方保证」：独立发版，兼容性只对特定主版本负责。升级框架时 contrib 必须同批升级，否则容易「编译通过、运行时行为变了」。按 A/B/C 分级：官方维护 + 有测试 + 近半年有 release 的是 A，直接用并锁次版本；单人维护但活跃、代码可通读的是 B，锁版本 + 薄封装 + 自建测试；一年无提交、无 LICENSE、无测试的是 C，不进生产。

## 二、网关中间件装配顺序

顺序即正确性：requestid 必须最先（后面所有日志都要用），Recovery 紧随（防 panic 打挂进程），CORS 在鉴权之前（否则预检被 401 拦掉）。

```go
// app/gateway/internal/router/router.go
func New(cfg *config.Config, log *zap.Logger) *gin.Engine {
    r := gin.New()
    r.SetTrustedProxies(nil) // 不信任 X-Forwarded-For，除非前面确实有 APISIX 且配了可信网段
    r.Use(requestid.New(requestid.WithGenerator(func() string { return uuid.NewString() })))
    r.Use(middleware.Recovery(log))
    r.Use(otelgin.Middleware("gateway")) // trace_id 从这里进入，后续日志统一读取
    r.Use(cors.New(cors.Config{
        AllowOrigins:     []string{"https://mall.example.com"}, // 禁止 ["*"] + credentials
        AllowMethods:     []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
        AllowHeaders:     []string{"Origin", "Content-Type", "Authorization", "X-Request-ID"},
        ExposeHeaders:    []string{"X-Request-ID"},
        AllowCredentials: true,
        MaxAge:           12 * time.Hour,
    }))
    r.Use(middleware.AccessLog(log))
    r.Use(middleware.Sentinel())             // 资源名 METHOD:FullPath
    r.Use(middleware.JWTAuth(cfg.JWTSecret)) // 密钥只从环境变量 / Secret 注入
    return r
}
```

`otelgin.Middleware` 依赖启动时注册好的全局 `TracerProvider`；忘了注册不会报错，只是 Span 全是 noop，表现为「接了追踪但没有数据」。

## 三、JWT：用 `golang-jwt/jwt/v5` 自研

```go
// app/gateway/internal/middleware/jwt.go
func JWTAuth(secret []byte) gin.HandlerFunc {
    return func(c *gin.Context) {
        raw := strings.TrimPrefix(c.GetHeader("Authorization"), "Bearer ")
        if raw == "" || raw == c.GetHeader("Authorization") {
            c.AbortWithStatusJSON(http.StatusUnauthorized,
                gin.H{"code": 40101, "message": "missing token", "request_id": requestid.Get(c)})
            return
        }
        token, err := jwt.Parse(raw, func(t *jwt.Token) (any, error) {
            if _, ok := t.Method.(*jwt.SigningMethodHMAC); !ok {
                return nil, fmt.Errorf("unexpected signing method: %v", t.Header["alg"])
            }
            return secret, nil
        }, jwt.WithValidMethods([]string{"HS256"})) // 显式限定算法，防 alg 混淆与 none
        if err != nil || !token.Valid {
            c.AbortWithStatusJSON(http.StatusUnauthorized,
                gin.H{"code": 40102, "message": "invalid token", "request_id": requestid.Get(c)})
            return
        }
        claims, _ := token.Claims.(jwt.MapClaims)
        c.Set("user_id", fmt.Sprint(claims["sub"]))
        c.Next() // 前置逻辑结束，交回引擎执行后续 handler
    }
}
```

## 四、zap 访问日志：串起 request_id 与 trace_id

```go
// app/gateway/internal/middleware/accesslog.go
func AccessLog(log *zap.Logger) gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        c.Next() // 先执行后续 handler，回来再记录后置数据
        path := c.FullPath()
        if path == "" {
            path = "unmatched" // 404 时 FullPath 为空，别用 URL.Path 避免基数爆炸
        }
        log.Info("http access",
            zap.String("request_id", requestid.Get(c)),
            zap.String("trace_id", trace.SpanContextFromContext(c.Request.Context()).TraceID().String()),
            zap.String("http.method", c.Request.Method),
            zap.String("http.path", path),
            zap.Int("http.status", c.Writer.Status()),
            zap.Float64("latency_ms", float64(time.Since(start).Microseconds())/1000),
            zap.String("user_id", c.GetString("user_id")),
        )
    }
}
```

Gin 的语义要点：引擎最外层已调用 `c.Next()`，中间件即使不写 `c.Next()`，后续 handler 也会在其返回后执行；写 `c.Next()` 是为了把 handler 提前到记录耗时之前。被 `c.Abort()` 拦下的请求，本中间件的后置代码仍会执行——访问日志能记录 401 就靠这点。

## 五、Prometheus 与 otelgin 各占一个位置

Prometheus 做计数、延迟直方图与告警，标签只放低基数维度（`method`、`route`、`status`）；otelgin 做链路追踪，依赖全局 `TracerProvider`。`/metrics` 单独起在 `:9101` 由 `promhttp.Handler()` 暴露，不在业务端口挂载，避免泄露内部拓扑。指标命名与分桶见 [监控扩展 Prometheus](05-监控扩展Prometheus.md)。

## 六、Kratos contrib：registry / config / log / tracing

| 仓库 | 用途 | 关键 API |
| --- | --- | --- |
| `contrib/registry/etcd/v2` | 服务注册发现 | `etcdreg.New(clientv3.Config, etcdreg.Namespace(...))` |
| `contrib/registry/consul/v2` | 同上 | `consulreg.New(consulapi.NewClient(...), consulreg.WithHealthCheck(true))` |
| `contrib/config/etcd/v2` | 配置源 | `etcd.New(cli, etcd.WithPath("/mall-lite/user-service.yaml"))` |
| `contrib/log/zap/v2` | 日志适配 | `zapv2.NewLogger(zapLogger)` |
| 核心 `middleware/tracing` | 链路追踪 | **不在 contrib**，用 `tracing.Server()` |

装配顺序固定：`etcdreg.New` / `consulreg.New` → `zapv2.NewLogger` → `grpc.NewServer(grpc.Middleware(recovery.Recovery(), logging.Server(klog), tracing.Server()))` → `kratos.New(..., kratos.Registrar(reg))`；完整代码见 [Kratos 项目生成工作流](../06-Gin进阶/04-Kratos项目生成工作流.md) 与 [etcd 与 Consul 接入](02-etcd与Consul接入.md)。

Kratos 原生 config 走 `config.New(config.WithSource(src))`，适合「配置放 etcd、组件原生消费」；mall-lite 的业务配置统一用 Viper，两者别同时改同一份 key，否则排查时不知道谁覆盖了谁。

## 七、Sentinel Go：服务内，不在边缘

Sentinel 在服务内按资源限流并熔断：`sentinel.InitDefault()` 后加载 `flow.Rule`，HTTP 资源名用 `GET:/api/v1/orders`，gRPC 用 `grpc:/user.v1.UserService/GetUser`，超限返回 429 + `Retry-After`，熔断返回 503 快速失败。APISIX 的 `limit-req` 按 IP / Consumer / Route 在边缘限流，两层都配不是重复——网关被绕过（内网直连、Pod 间调用）时只有服务内规则生效。规则加载、Dashboard 与压测定阈值见 [Sentinel 限流与熔断](04-Sentinel限流与熔断.md)。

## 八、评分卡与依赖收敛

| 维度 | 怎么查 | 红线 |
| --- | --- | --- |
| 维护活跃度 | 近 12 个月 commit / release | 一年无提交 |
| 许可证 | LICENSE 文件 | AGPL、无 license 用于闭源商用 |
| 安全 | `govulncheck ./...`、CVE 记录 | 有未修复高危 |
| 可替换性 | 是否只依赖稳定接口 | 深度侵入业务代码 |
| 依赖体积 | `go mod graph` 的传递依赖数量 | 为一个函数拖进整个 SDK |

每项 1~3 分，总分 < 14 不进生产；B 级必须锁版本 + 在 `pkg/` 写薄封装。

```bash
go list -m -u all | grep -E 'gin-gonic|gin-contrib|go-kratos|gorm'
go get github.com/gin-gonic/gin@v1.10.1 github.com/gin-contrib/cors@v1.7.2
go mod tidy && go vet ./... && go test -race ./... && govulncheck ./...
```

```powershell
go list -m -u all | Select-String -Pattern 'gin-gonic|go-kratos|gorm'
go get github.com/go-kratos/kratos/v2@v2.8.4
go mod tidy; go vet ./...; go test -race ./...
```

三条纪律：`go.mod` 锁定具体版本，`@latest` 不进主干；升级按「框架 → 官方 contrib → 社区」分批，一次只动一层；每个社区库都在 `pkg/` 有一层薄封装，替换时只改一处。

## 九、选型总表

| 需求 | 首选 | 备选 | 备注 |
| --- | --- | --- | --- |
| HTTP 框架 | Gin v1.10 | 标准库 `net/http` | 生态与团队熟悉度优先 |
| 微服务框架 | Kratos v2.8 | — | gRPC + DDD 分层 |
| 跨域 | `gin-contrib/cors` | 自研 20 行 | 白名单 + credentials 冲突要避开 |
| 请求 ID | `gin-contrib/requestid` | 自研中间件 | 必须回写响应头 |
| JWT | `golang-jwt/jwt/v5` | PASETO | 显式限定签名算法 |
| 日志 | zap + `contrib/log/zap/v2` | zerolog | 字段统一，容器输出 JSON |
| 追踪 | otelgin / `tracing.Server()` | — | 共用全局 TracerProvider |
| 注册中心 | Kratos contrib etcd / consul | — | 地址来自配置 |
| 限流熔断 | Sentinel Go v1.0.4 | `x/time/rate` | 边缘再配 APISIX |

## 常见坑

1. **`AllowOrigins: ["*"]` + `AllowCredentials: true`**：浏览器直接拒绝，且是典型安全误配。生产写白名单。
2. **CORS 挂在鉴权之后**：预检 `OPTIONS` 被 401 拦掉，前端报跨域错误却查不到原因。CORS 必须在 JWT 之前。
3. **JWT 不校验算法**：攻击者把 `alg` 改成 `none` 伪造 token。用 `jwt.WithValidMethods` 固定算法。
4. **升级框架不升 contrib**：编译通过但中间件行为变了，线上才发现。同批升级。
5. **为一个小功能引入巨型 SDK**：传递依赖十几个包还带 CVE。能用 50 行自研就别引。
6. **`otelgin` 注册了但没设 TracerProvider**：Span 全 noop，追踪页面空白。启动时先装配 OTel SDK。

## 小结

- 三层依赖三种信任级别：核心直接用、官方 contrib 锁版本（registry / config / log 在 contrib，tracing 在核心）、社区库读源码 + 薄封装。
- 中间件顺序即正确性：requestid → Recovery → otelgin → CORS → 访问日志 → Sentinel → JWT。
- Sentinel 在服务内做资源级限流与熔断，与 APISIX 边缘限流互补。
- 选型靠评分卡而不是热度，升级按层分批，`govulncheck` 与 `go test -race` 是硬门槛。
