# 协议扩展与自定义协议

> 一句话定位：Gin 的协议扩展不是「自己写个 TCP 解析器」，而是围绕 Binding / Render / Validator / 内容协商四个扩展点做文章；真正需要自定义协议的场景很少，先把这四件事用对。

## 本篇目标

- 建立判断标准：什么时候用 JSON、Protobuf、msgpack，什么时候什么都不用改。
- 掌握 `binding.Binding`、`render.Render`、`binding.StructValidator`，并各写一个可用实现。
- 用 `Accept` / `Content-Type` 做内容协商，配合 `/api/v1` 与 proto 包名做版本化；分清 Kratos gRPC 与 HTTP transport 的职责及 WebSocket / SSE 的边界。

## 前置知识

- 已读 [参数绑定与校验](../03-基本特性/03-参数绑定与校验.md)，知道 `ShouldBindJSON` 与 `binding` tag。
- 已读 [响应与渲染](../03-基本特性/04-响应与渲染.md)，知道 `c.JSON` 背后的 `render.Render`。

## 一、先判断：多数场景不需要自定义协议

- 浏览器 / 开放 API 用 JSON：可读、可调试、生态最好。
- 内部服务互调用 gRPC + Protobuf：强类型、HTTP/2 多路复用、支持流式。
- 移动端弱网、体积敏感用 Protobuf 或 msgpack over HTTP：小 30%~60%，但不可读；私有二进制协议对接老系统时，在网关单独进程做协议转换，不要污染业务服务。

## 二、四个扩展点

`binding.Binding` 只有 `Name()` 与 `Bind(*http.Request, any) error`，用 `c.ShouldBindWith(obj, b)` 调用；`render.Render` 只有 `Render(http.ResponseWriter) error` 与 `WriteContentType(http.ResponseWriter)`，用 `c.Render(code, r)` 调用；`binding.StructValidator` 全局挂到 `binding.Validator`；内容协商走 `c.NegotiateFormat`。接口都很小，这是 Gin 好扩展的根本原因。

## 三、自定义 Binding：msgpack 请求体

```go
// app/gateway/internal/binding/msgpack.go
package bindingx

import (
    "io"
    "net/http"

    "github.com/gin-gonic/gin/binding"
    "github.com/vmihailenco/msgpack/v5"
)

const MIMEMsgPack = "application/x-msgpack"

type MsgPack struct{}

func (MsgPack) Name() string { return "msgpack" }

func (MsgPack) Bind(req *http.Request, obj any) error {
    body, err := io.ReadAll(io.LimitReader(req.Body, 8<<20)) // 必须限长，否则大包打满内存
    if err != nil {
        return err
    }
    if err := msgpack.Unmarshal(body, obj); err != nil {
        return err
    }
    if binding.Validator == nil {
        return nil
    }
    return binding.Validator.ValidateStruct(obj)
}

var MsgPackBinding = MsgPack{}
```

handler 里按 `Content-Type` 显式分派：`c.ContentType() == bindingx.MIMEMsgPack` 时走 `c.ShouldBindWith(&req, bindingx.MsgPackBinding)`，否则 `c.ShouldBindJSON`。不自动选择，出问题一眼能看到走了哪条路。

## 四、自定义 Render：msgpack 响应

```go
// app/gateway/internal/render/msgpack.go
package renderx

import (
    "net/http"

    "github.com/vmihailenco/msgpack/v5"
)

type MsgPack struct{ Data any }

func (r MsgPack) Render(w http.ResponseWriter) error {
    r.WriteContentType(w)
    body, err := msgpack.Marshal(r.Data)
    if err != nil {
        return err
    }
    _, err = w.Write(body)
    return err
}

func (r MsgPack) WriteContentType(w http.ResponseWriter) {
    if len(w.Header().Values("Content-Type")) == 0 {
        w.Header().Set("Content-Type", "application/x-msgpack")
    }
}
```

`c.Render` 会先写状态码再调用 `Render`；序列化失败时 header 已发出，只能记日志并断开。关键接口建议先 `msgpack.Marshal` 成功后再 `c.Render`。

## 五、内容协商与版本化

```go
// app/gateway/internal/handler/order.go（片段）：Accept 决定响应格式
if c.NegotiateFormat(binding.MIMEJSON, "application/x-msgpack") == "application/x-msgpack" {
    c.Render(http.StatusOK, renderx.MsgPack{Data: resp})
    return
}
c.JSON(http.StatusOK, resp) // 不匹配按 JSON 兜底，避免 406 打断客户端
```

`NegotiateFormat` 读 `Accept`，请求侧读 `Content-Type`，两条链路分开处理。版本化三层同时到位：URL 用 `/api/v1`、`/api/v2`；proto 用 `package user.v1;` + `option go_package = "mall-lite/api/user/v1;v1";`；文档标 `deprecated`。破坏性变更开 v2，v1 至少保留一个发布周期。

## 六、自定义 validator

```go
// app/gateway/internal/validate/validator.go
package validate

import (
    "reflect"
    "regexp"

    "github.com/go-playground/validator/v10"
)

var mobileRe = regexp.MustCompile(`^1[3-9]\d{9}$`)

type Validator struct{ v *validator.Validate }

func New() *Validator {
    v := validator.New()
    _ = v.RegisterValidation("mobile", func(fl validator.FieldLevel) bool {
        return mobileRe.MatchString(fl.Field().String())
    })
    return &Validator{v: v}
}

func (val *Validator) ValidateStruct(obj any) error {
    if obj == nil {
        return nil
    }
    rv := reflect.ValueOf(obj)
    if rv.Kind() == reflect.Ptr {
        if rv.IsNil() {
            return nil
        }
        rv = rv.Elem()
    }
    if rv.Kind() == reflect.Slice || rv.Kind() == reflect.Array {
        for i := 0; i < rv.Len(); i++ {
            if err := val.v.Struct(rv.Index(i).Interface()); err != nil {
                return err
            }
        }
        return nil
    }
    return val.v.Struct(rv.Interface())
}

func (val *Validator) Engine() any { return val.v }
```

`main` 里 `binding.Validator = validate.New()` 启用。必须处理 nil、指针、切片，否则 `ShouldBindJSON` 遇到批量请求会 panic；错误翻译放中间件，转成 `{"field":"mobile","reason":"invalid format"}`。

## 七、Kratos：gRPC 与 HTTP transport

内部服务互调走 gRPC：`api/user/v1/*.proto` 定义契约，Protobuf 有 schema 约束、支持四种流式，网关直接 `NewUserServiceClient(conn)`。对浏览器和第三方则用 Kratos HTTP transport：同一份 proto 加 `google.api.http` 注解，`khttp.NewServer(khttp.Address(":8001"))` 后调用生成的 `v1.RegisterUserServiceHTTPServer(srv, svc)` 即可暴露 REST，路径与 `v1` 包名天然一致。

HTTP transport 按请求 `Content-Type` 选择 codec（默认 JSON），要加 msgpack 就实现 `encoding.Codec`（`Marshal` / `Unmarshal` / `Name`）并 `encoding.RegisterCodec`。JSON 只是「方便调试的旁路」，内部链路不要用它替代 gRPC。

## 八、WebSocket / SSE 的边界

```go
// app/gateway/internal/handler/stream.go
package handler

import (
    "time"

    "github.com/gin-gonic/gin"
)

// SSE：单向推送，EventSource 自带断线重连
func (h *Handler) OrderEvents(c *gin.Context) {
    c.Header("Content-Type", "text/event-stream")
    c.Header("Cache-Control", "no-cache")
    c.Header("X-Accel-Buffering", "no") // 让 Nginx / APISIX 不缓冲

    ticker := time.NewTicker(2 * time.Second)
    defer ticker.Stop()
    for {
        select {
        case <-c.Request.Context().Done():
            return
        case t := <-ticker.C:
            c.SSEvent("order", gin.H{"ts": t.Unix()})
            c.Writer.Flush()
        }
    }
}
```

WebSocket 用 `gorilla/websocket`：`upgrader.Upgrade(c.Writer, c.Request, nil)` 之后自己跑读写循环与心跳，`CheckOrigin` 按域名白名单校验，适合双向交互（聊天、协同编辑）。

边界一句话：**状态推送用 SSE，双向交互用 WebSocket，服务间流式用 gRPC streaming**。不要把 gRPC 直接暴露给浏览器，需要 grpc-web 代理，多一层就多一个故障点。

## 常见坑

1. **自定义 Binding 不限长**：`io.ReadAll` 读 1GB 的包，OOM 比限流来得更快。
2. **忘写 Content-Type**：`WriteContentType` 不设置，客户端按 `text/plain` 解析，前端乱码。
3. **读完 body 再想 `ShouldBindJSON`**：body 是流，读一次就空；要复用用 `c.ShouldBindBodyWith`。
4. **自定义 validator 不处理切片**：批量接口直接 panic。
5. **`CheckOrigin` 永远 true**：任意站点可连 WebSocket，配合 Cookie 就是 CSRF。
6. **SSE 没关代理缓冲**：本地逐条输出，上 APISIX/Nginx 变成一次性返回。

## 小结

- Gin 的协议扩展只有四件事：Binding、Render、Validator、内容协商，都是小接口。
- msgpack 用 `ShouldBindWith` + 自定义 `Render`，不要动全局默认绑定。
- 请求看 `Content-Type`，响应看 `Accept`，不匹配时给合理兜底而不是 406；内部服务用 gRPC + Protobuf，HTTP transport 是调试旁路，私有协议放网关。
