# 配置中心与动态配置

> 一句话定位：配置按「默认 → 基础文件 → 环境文件 → 远端 → 环境变量」分层，远端只放能热更的非敏感参数，热更新用「整份快照 + 原子替换」，坏配置必须拒绝而不是带病上线。

## 本篇目标

- 定义四层配置来源与优先级，写清哪些参数能热更、哪些必须重启
- 用 Viper + etcd 完成远端读取与 Watch，避开 `AutomaticEnv` 不作用于 `Unmarshal` 的坑
- 用 Kratos config（file / etcd source）做对照，并落地日志级别、Sentinel 规则、功能开关与版本回滚

## 一、配置分层与优先级

| 层 | 例子 | 存放 | 变更方式 |
| --- | --- | --- | --- |
| 内置默认 | 超时、分页大小 | 代码 `Defaults()` | 随版本发布 |
| 基础文件 | 端口、DSN 模板、注册中心 | `configs/base.yaml` | 重启 |
| 环境文件 | dev / prod 差异 | `configs/prod.yaml` | 重启 |
| 远端 | 限流阈值、日志级别、开关 | etcd | 热更新，秒级 |
| 环境变量 | 密钥、紧急覆盖 | K8s Secret / CI | 重启或热更 |

优先级从低到高就是表的顺序：**环境变量最高**。远端被误写时，环境变量是唯一不发版就能把 DSN、密钥改回来的手段；反过来，远端禁止出现密钥，加载器发现 `mysql.dsn`、`redis.password` 之类的 key 直接拒绝整份配置。判断能否热更只有一句：**改了之后进程能否在不重建连接池、不换端口的前提下继续正确工作**。连接池大小、监听端口、消费组都改了无效，标 `requires_restart`；表结构与代码分支也不进配置中心。

## 二、Viper 加载：文件为底，环境变量兜底

```go
// pkg/config/load.go
package config

import (
    "strings"
    "github.com/go-viper/mapstructure/v2"
    "github.com/spf13/viper"
)

var envKeys = []string{"mysql.dsn", "redis.password", "registry.etcd.endpoints",
    "log.level", "rate_limit.order_qps"}

func Load(paths ...string) (*Config, error) {
    v := viper.New()
    v.SetEnvPrefix("MALL")
    v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))
    v.AutomaticEnv() // 只影响 Get，不影响 Unmarshal
    for _, k := range envKeys {
        if err := v.BindEnv(k); err != nil { // Unmarshal 只认识已注册的 key
            return nil, err
        }
    }
    for _, p := range paths { // base.yaml → prod.yaml，后者覆盖前者
        v.SetConfigFile(p)
        if err := v.MergeInConfig(); err != nil {
            return nil, err
        }
    }
    cfg := Defaults()
    if err := v.Unmarshal(cfg, decodeOption()); err != nil {
        return nil, err
    }
    return cfg, cfg.Validate()
}

func decodeOption() viper.DecoderConfigOption {
    return func(dc *mapstructure.DecoderConfig) {
        dc.TagName = "mapstructure"
        dc.DecodeHook = mapstructure.StringToTimeDurationHookFunc() // "3s" → 3s
    }
}
```

`MALL_MYSQL_DSN` 覆盖 `mysql.dsn` 靠前缀加 `.` 换 `_`。但 **`AutomaticEnv()` 对 `Unmarshal` 不生效**：`Unmarshal` 基于 `AllSettings()`，只遍历文件、默认值与 `BindEnv` 注册过的 key，所以必须显式绑定，否则 `Get` 拿得到、结构体还是空值。Viper 1.20 内部用 `github.com/go-viper/mapstructure/v2`，DecodeHook 也从这里导入，混用旧包会类型不匹配。

## 三、etcd 远端读取与 Watch

```go
// pkg/config/remote.go
func WatchEtcd(ctx context.Context, cli *clientv3.Client, key string,
    apply func(revision int64, raw []byte) error) error {
    resp, err := cli.Get(ctx, key)
    if err != nil {
        return err
    }
    rev := resp.Header.Revision
    if len(resp.Kvs) == 1 {
        if err := apply(rev, resp.Kvs[0].Value); err != nil {
            return err // 启动期坏配置直接失败
        }
    }
    // 从 rev+1 开始 Watch，避免 Get 与 Watch 之间的变更丢失
    for wr := range cli.Watch(ctx, key, clientv3.WithRev(rev+1)) {
        for _, ev := range wr.Events {
            if ev.Type == clientv3.EventTypeDelete {
                continue // 删除视为无效操作，继续用最后一份好配置
            }
            if err := apply(ev.Kv.ModRevision, ev.Kv.Value); err != nil {
                log.Errorf("reject remote config rev=%d: %v", ev.Kv.ModRevision, err)
            }
        }
    }
    return ctx.Err()
}
```

三个细节决定可靠性：Watch 从 `rev+1` 开始（漏掉这段会丢事件）、删除事件不生效（避免误删 key 打挂服务）、apply 失败只记日志（旧快照继续服务）。不要用 `viper/remote`：它把 etcd 客户端锁在旧模块上，和 `clientv3` 混用容易打架。

## 四、Kratos config 作为对照

```go
// app/order-service/cmd/main.go（片段）
remote, err := etcdconfig.New(cli, etcdconfig.WithPath("/mall-lite/dev/order-service.yaml"))
if err != nil { return conf.Bootstrap{}, err }
c := kconfig.New(kconfig.WithSource(
    file.NewSource(file.WithPath("configs/order-service.yaml")),
    remote, // 后加载的 Source 覆盖前面的
))
if err := c.Load(); err != nil { return conf.Bootstrap{}, err }
var bc conf.Bootstrap
if err := c.Scan(&bc); err != nil { return conf.Bootstrap{}, err }
// Observer 没有 error 返回值，失败只能自己记日志
_ = c.Watch("log.level", func(key string, v kconfig.Value) {
    _ = zapLevel.UnmarshalText([]byte(v.String()))
})
return bc, nil
```

它适合框架自身（server、data、registry）的启动配置；业务动态参数继续用 Viper 快照，避免两套源各自 Watch、互相对不上。`WithPrefix(true)` 用于把整个目录当一份配置读，单文件别开。

## 五、热更新：整份指针替换

```go
// pkg/config/holder.go
type Holder struct {
    mu  sync.RWMutex  // 串行化写入：防止两次发布乱序，旧版本覆盖新版本
    cur atomic.Value  // *Config，读侧无锁
}

func (h *Holder) Get() *Config { return h.cur.Load().(*Config) }

func (h *Holder) Reload(revision int64, raw []byte) error {
    h.mu.Lock()
    defer h.mu.Unlock()

    v := viper.New()
    v.SetConfigType("yaml")
    if err := v.ReadConfig(bytes.NewReader(raw)); err != nil {
        return err
    }
    next := Defaults()
    if err := v.Unmarshal(next, decodeOption()); err != nil {
        return err
    }
    next.Version = revision
    if err := next.Validate(); err != nil {
        return err
    }
    if err := Apply(next); err != nil { // 先让副作用成功，再替换快照
        return err
    }
    h.cur.Store(next)
    return nil
}
```

发布必须 `Validate` + `Apply` 都成功才替换，失败保留旧快照。逐字段改全局变量会 data race，业务还可能读到「一半新一半旧」；拿到的 `*Config` 视为只读。副作用统一收在 `Apply` 里：

- **日志级别**：全局一个 `zap.AtomicLevel`，`zapLevel.UnmarshalText([]byte(c.Log.Level))` 即可切换。
- **Sentinel 规则**：每次整份 `flow.LoadRules([]*flow.Rule{{Resource: "GET:/api/v1/orders", Threshold: float64(c.RateLimit.OrderQPS), TokenCalculateStrategy: flow.Direct, ControlBehavior: flow.Reject}})`；失败就不动旧规则。
- **功能开关**：`if h.Get().Flags.NewPrice { ... }`，每次请求读同一份快照；默认值永远是旧逻辑，先 0% 验证能开能关，再 1% → 5% → 25% 放量。

## 六、版本、回滚与快照兜底

- 版本就是 etcd 的 `ModRevision`：发布写 key 并记录 revision；回滚用 `etcdctl get <key> --rev=<last-good>` 取回再 put。
- 加载日志必须打印生效 revision 与关键字段摘要，排障先看「当前跑的是哪版」；每次成功加载后用临时文件 + `os.Rename` 原子落盘快照（权限 `0600`），远端不可用时读快照启动，坏了就删掉回落到默认值。

## 常见坑

1. **只开 `AutomaticEnv` 就 `Unmarshal`**：覆盖失效，服务连到默认库；需要覆盖的 key 必须 `BindEnv`。
2. **漏了 Duration Hook**：`3s` 解析成 0，超时形同虚设。
3. **Watch 只轮询或从当前 revision 开始**：事件丢失；必须 `WithRev(rev+1)`。
4. **远端只写局部 YAML 就整份替换**：未出现的字段回到默认值；发布必须是完整文档 + 校验 + 版本号。
5. **回调里逐字段赋值**：读侧 data race、读到半新半旧；整份指针替换。
6. **热更新改了连接池 / 端口**：代码只在启动读一次，改了等于没改；这类参数标 `requires_restart`；密钥写进 etcd 或仓库则一次泄露全线失守。

## 小结

- 分层与优先级固定：默认 < 基础文件 < 环境文件 < 远端 < 环境变量
- `AutomaticEnv` 只管 `Get`，`Unmarshal` 依赖 `BindEnv`；Viper 1.20 用 go-viper/mapstructure/v2
- 远端 Watch 要带 revision，删除不生效，坏配置拒绝；热更新整份替换、副作用收敛到 `Apply`
- 版本用 etcd revision，回滚靠历史版本；密钥走 Secret，远端挂了用本地快照
