# 学习路线图

> 从「没写过一行 Go」到「能独立交付 Gin + Kratos 企业级微服务」的五个阶段，每阶段都有能力清单、验收标准和周计划。

## 本篇目标

- 说清「零基础 → 企业级 Go 微服务」的五个阶段，以及每阶段解决的核心问题
- 给出每阶段的能力清单、验收标准与周计划表，知道某一周该打开哪个文件
- 用「能复述、能改写、能创造」三层标准判断自己是否真的过关
- 提前识别五个阶段各自的高频误区，少走三个月弯路

## 前置知识

- 会安装软件、打开终端（Windows 的 PowerShell，macOS 的 Terminal），磁盘剩余 ≥ 10 GB
- 不需要任何编程基础；有 Python / Java / JavaScript 经验会更快，但要接受 Go 的思维差异
- 唯一硬性要求：**代码自己敲一遍，命令自己跑一遍**

## 一、路线总览

| 阶段 | 主题 | 解决的问题 | 参考周数 |
| --- | --- | --- | --- |
| 一 | 打地基：Go 语言 + net/http | 语言不会写，框架无从谈起 | 4 周 |
| 二 | 会使用：Gin 核心特性 | 能独立写出一个完整业务接口 | 3 周 |
| 三 | 能上生产：可观测性 + 治理 + 工程化 | 代码能部署、能排障、能协作 | 3 周 |
| 四 | 数据与中间件：MySQL / Redis / Kafka | 服务能持久化、能缓存、能异步 | 4 周 |
| 五 | 微服务与实战：Kratos + APISIX + mall-lite | 能交付企业级、可演进的系统 | 6 周 |

总计约 20 周（每周 8~10 小时），你当前在**阶段一第 1 周**。五个阶段单向依赖：后面的每篇示例都建立在前一阶段的语法与工程习惯上，不要跳读。

## 二、阶段一：打地基（约 4 周）

目标：能用 Go 写出带错误处理、并发控制、单元测试的程序，并用标准库 `net/http` 起一个 REST 服务。

1. [02-Go-安装与环境配置](02-Go-安装与环境配置.md) → [03-Go-Module与国内代理](03-Go-Module与国内代理.md) → [04-开发工具链与IDE](04-开发工具链与IDE.md)
2. [01-Go语言概览与第一个程序](../01-Go语言基础/01-Go语言概览与第一个程序.md) 到 [08-包管理与项目结构](../01-Go语言基础/08-包管理与项目结构.md)
3. [09-标准库net-http入门](../01-Go语言基础/09-标准库net-http入门.md)、[10-测试与基准测试](../01-Go语言基础/10-测试与基准测试.md)

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 1 | 环境、模块、工具链 | `go version`、`go mod tidy`、断点调试跑通 |
| 2 | 语法：变量、流程、函数、结构体、接口 | 3 个命令行小工具 |
| 3 | 错误处理、切片 / Map、并发与 context | 带超时取消的并发任务 |
| 4 | 多包项目、net/http、测试 | 标准库 REST 服务 + 表驱动测试 |

**能力与验收**：读懂任意 Go 语法，能解释 `defer` 时机、接口隐式实现、`context` 取消传播；不看教程从零写出「内存版用户 CRUD」的 `net/http` 服务，且 `go vet ./...`、`go test -race ./...` 全绿。

**常见误区**：
- 跳过语言直接抄框架示例——Gin 的 `c.Request.Context()`、中间件链、错误包装全是语言知识。
- 把并发当洪水猛兽——先掌握「`context` 超时 + `WaitGroup`」一种模式，够覆盖大部分 Web 场景。
- 只跑 `go run` 不跑 `go build`——直到部署那天才发现编译不过。

## 三、阶段二：会使用（约 3 周）

目标：从零搭一个 Gin 服务，把路由、上下文、绑定校验、响应、中间件、错误处理、测试全部用一遍。

主链路：[01-Gin是什么-架构与性能](../02-Gin入门/01-Gin是什么-架构与性能.md) → [02-快速开始-第一个服务](../02-Gin入门/02-快速开始-第一个服务.md) → [04-项目结构与分层布局](../02-Gin入门/04-项目结构与分层布局.md) → [05-Engine详解与启动参数](../02-Gin入门/05-Engine详解与启动参数.md)，之后是 `03-基本特性` 的 [01-路由](../03-基本特性/01-路由.md)、[02-请求上下文Context](../03-基本特性/02-请求上下文Context.md)、[03-参数绑定与校验](../03-基本特性/03-参数绑定与校验.md)、[04-响应与渲染](../03-基本特性/04-响应与渲染.md)、[05-中间件](../03-基本特性/05-中间件.md)、[06-错误处理](../03-基本特性/06-错误处理.md)、[13-单测与Mock](../03-基本特性/13-单测与Mock.md)。

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 5 | Gin 入门、项目结构、Engine 参数 | 能启动并响应 `/api/v1/users/:id` |
| 6 | 绑定校验、响应渲染、中间件、错误处理 | 统一响应体 + 集中错误处理 |
| 7 | 单测与 Mock、静态资源、优雅退出 | httptest 用例 + `srv.Shutdown` 平滑退出 |

**能力与验收**：手写 Gin 中间件，用 `binding` tag + validator 校验并翻译错误，输出统一 `{"code":0,...}`，用 `httptest` 测 handler；交付带 CRUD、参数校验、统一错误码的服务，并能说清 `c.Next()` 与 `c.Abort()` 的区别。

**常见误区**：
- 沿用别的框架的中间件思路——Gin 最外层已调用 `c.Next()`，中间件不写 `Next`，后续 handler 也会执行；`Next` 的作用是「先跑后面，再回来做后置逻辑」。
- 在 goroutine 里直接用 `*gin.Context`——必须 `c.Copy()`，否则请求结束后数据被复用串台。
- 用 `fmt.Println` 打业务日志——现在就要养成「日志必须有字段」的意识，阶段三才换得动 zap。

## 四、阶段三：能上生产（约 3 周）

目标：让服务「看得见、管得住、合得作」——结构化日志、链路追踪、指标、限流熔断、配置管理与 CI。

- 可观测性：[01-日志体系zap](../04-可观测性/01-日志体系zap.md)、[02-链路追踪OpenTelemetry与Jaeger](../04-可观测性/02-链路追踪OpenTelemetry与Jaeger.md)、[03-埋点Instrumentation](../04-可观测性/03-埋点Instrumentation.md)
- 治理扩展：[03-配置管理Viper](../05-治理与扩展/03-配置管理Viper.md)、[04-Sentinel限流与熔断](../05-治理与扩展/04-Sentinel限流与熔断.md)、[05-监控扩展Prometheus](../05-治理与扩展/05-监控扩展Prometheus.md)
- 工程化：[01-项目分层与目录规范](../07-工程化与测试/01-项目分层与目录规范.md)、[02-依赖注入Wire与配置分层Viper](../07-工程化与测试/02-依赖注入Wire与配置分层Viper.md)、[04-CI流水线与代码质量](../07-工程化与测试/04-CI流水线与代码质量.md)

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 8 | zap 结构化日志、request_id、脱敏 | 可检索的 JSON 日志 |
| 9 | OTel + Jaeger、Sentinel、Viper | 一次请求在日志 / 指标 / 链路三处串联 |
| 10 | 分层规范、Wire、CI 质量门禁 | 流水线跑通 `vet`/`lint`/`test`/`build` |

**能力与验收**：用同一个 `trace_id` 串起日志、指标、链路，改环境变量即可覆盖配置，限流返回 429、熔断返回 503；生产模式日志为 JSON 且无明文敏感字段，Jaeger 能看到完整调用链，CI 全绿才允许合并。

**常见误区**：
- 配置和密钥写死在代码里——敏感信息只从环境变量 / Secret 注入。
- 只加日志不上追踪——排障时恰好缺了跨服务那一段。
- 限流资源名随手写——统一 `GET:/api/v1/orders` 这类命名，否则规则永远对不上。

## 五、阶段四：数据与中间件（约 4 周）

目标：让服务真正落地数据——GORM 建模与事务、Redis 缓存与锁、Kafka 可靠投递。

- MySQL：[02-GORM核心用法与模型设计](../09-MySQL与ORM/02-GORM核心用法与模型设计.md)、[03-事务-乐观锁-软删除](../09-MySQL与ORM/03-事务-乐观锁-软删除.md)、[04-索引-慢查询-N加1问题](../09-MySQL与ORM/04-索引-慢查询-N加1问题.md)
- Redis：[01-go-redis接入与连接池](../10-Redis/01-go-redis接入与连接池.md)、[02-缓存模式与三大经典问题](../10-Redis/02-缓存模式与三大经典问题.md)、[03-分布式锁与限流实践](../10-Redis/03-分布式锁与限流实践.md)
- Kafka：[01-消息队列选型对比](../11-消息队列/01-消息队列选型对比.md)、[02-Kafka生产与消费实践](../11-消息队列/02-Kafka生产与消费实践.md)、[04-可靠投递-幂等-顺序消息](../11-消息队列/04-可靠投递-幂等-顺序消息.md)

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 11 | GORM 模型、事务、软删除 | 用户 / 商品表 CRUD |
| 12 | 索引、慢查询、N+1、连接池 | 一条查询从 200ms 降到 5ms |
| 13 | 缓存三大问题、分布式锁 | 缓存 + 锁保护的下单接口 |
| 14 | Kafka 生产消费、幂等与积压处理 | 下单事件异步落库 |

**能力与验收**：所有查询带 `WithContext`，事务用 `db.Transaction`，能讲清缓存与锁的失效场景；压测下无 N+1，缓存命中率有指标可看，消费者重启后不丢不重（用幂等键验证）。

**常见误区**：
- 在循环里查关联表——用 `Preload` 或批量 `IN` 一次取回。
- 缓存不设 TTL、先写缓存后写库——一致性策略必须讲清楚。
- 把 Kafka 当 RPC 用——异步链路必须有幂等与重试上限。

目标：把单体 Gin 拆成「APISIX 网关 + Gin BFF + Kratos gRPC 服务」，并用 mall-lite 跑通下单主链路。

- 注册中心：[05-服务注册与发现etcd与Consul实践](../12-微服务与Kratos/05-服务注册与发现etcd与Consul实践.md)
- 实战：[01-项目全景与架构设计](../13-企业级实战/01-项目全景与架构设计.md) 到 [07-复盘与演进](../13-企业级实战/07-复盘与演进.md)
- 部署：[02-Docker镜像与多阶段构建](../08-部署与运维/02-Docker镜像与多阶段构建.md)、[03-Kubernetes部署与健康检查](../08-部署与运维/03-Kubernetes部署与健康检查.md)

| 周 | 内容 | 产出 |
| --- | --- | --- |
| 15 | Kratos 服务端与 Proto 工作流 | 一个可被调用的 gRPC 服务 |
| 16 | 服务发现、客户端负载均衡、配置中心 | Gin 通过 discovery 调用 Kratos |
| 17 | APISIX 路由、JWT 鉴权、限流 | 9080 进、8080 出 |
| 18-19 | mall-lite 用户 / 商品 / 订单主链路 | 下单扣库存 + Kafka 最终一致 |
| 20 | Docker / K8s、可观测、灰度与复盘 | 一键部署 + 看板 + 复盘文档 |

**能力与验收**：写 proto 并生成代码，把 Kratos 服务注册到 etcd / Consul，在网关做鉴权限流，能端到端排障；`docker compose up` 后能走完「登录 → 浏览商品 → 下单 → 查订单」，且杀掉任一实例流量自动切走。

**常见误区**：
- 每个请求都新建 gRPC 连接——客户端启动时建一次并注入 handler。
- 处处 `context.Background()`——超时预算与 trace 链路都会断。
- 网关鉴权后服务内不再校验——内部接口同样要二次校验。

## 七、怎么验证「我真的学会了」

1. **能复述**：合上教程，用自己的话说清这个知识点解决什么问题，例如「为什么 Gin 的 Context 要复用」。
2. **能改写**：换一个需求仍能跑通，例如把 `/users/:id` 改成 `/orders/:id` 并补上错误分支。
3. **能创造**：没有示例时从零写出同类功能，这是唯一算「学会」的标准。

## 常见坑

1. **跳过前四阶段直接看实战**：阶段五的每个报错都指向前面缺的语法或工程习惯，返工比按序学更慢。
2. **环境问题拖两天**：先按 [02](02-Go-安装与环境配置.md) 把 `go version` 跑通，再谈其他。

## 小结

五个阶段、20 周、三层验证法，是你未来半年的导航。现在打开 [02-Go-安装与环境配置](02-Go-安装与环境配置.md)，把 Go 装上——这是整条路线的第一块砖。
