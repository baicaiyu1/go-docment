# 编译与交叉编译

> 一句话定位：用一条参数固定的构建命令，产出带版本信息、体积可控、能在目标平台运行的二进制；构建不可复现，后面所有部署排查都失去基准。

## 本篇目标

- 掌握 `-trimpath`、`-buildvcs`、`-ldflags`、`CGO_ENABLED` 四个关键开关的取舍
- 用 `-X` 注入 version/commit/buildTime，并用 `debug.ReadBuildInfo` 交叉复核
- 完成 Linux/Windows/macOS 交叉编译，理解 CGO 带来的限制
- 用 build tags 做环境裁剪，用 Makefile 收敛多目标构建

## 前置知识

- [07-工程化与测试/01-项目分层与目录规范](../07-工程化与测试/01-项目分层与目录规范.md)：`app/<service>/cmd` 入口约定

## 一、生产构建的最小参数组合

`go build` 默认会把构建机绝对路径、VCS 信息、编译参数写进二进制，可用 `go version -m bin/gateway` 查看。生产构建固定为 `-trimpath -buildvcs=false` + 显式 ldflags。

| 参数 | 作用 | 生产建议 |
| --- | --- | --- |
| `-trimpath` | 去掉源码绝对路径 | 必加 |
| `-buildvcs=false` | 不写 VCS 信息，版本完全由 ldflags 决定 | 必加 |
| `-ldflags "-s -w"` | 去符号表与 DWARF，减小体积 | 必加 |
| `-ldflags "-X pkg.Var=v"` | 注入字符串变量 | 版本信息必加 |
| `CGO_ENABLED=0` | 纯静态二进制，可跑 scratch/distroless | 必加 |

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -buildvcs=false \
  -ldflags "-s -w" -o bin/gateway ./app/gateway/cmd
```

`CGO_ENABLED=0` 时 Go 使用纯 Go 的 DNS 解析与用户查询实现，才能放进 `scratch`/`distroless`；代价是无法链接依赖 libc 的库。gin、kratos、gorm、go-redis、sarama 均为纯 Go，不受影响。

## 二、注入版本信息

`-X` 只能改**字符串变量**，且必须写完整导入路径：

```go
// pkg/version/version.go
package version

import (
    "runtime"
    "runtime/debug"
)

var (
    Version   = "dev"
    Commit    = "none"
    BuildTime = "unknown"
)

func Info() map[string]any {
    info := map[string]any{"version": Version, "commit": Commit, "build_time": BuildTime, "go": runtime.Version()}
    if bi, ok := debug.ReadBuildInfo(); ok {
        for _, s := range bi.Settings {
            if s.Key == "vcs.revision" && Commit == "none" {
                info["commit"] = s.Value
            }
        }
    }
    return info
}
```

```go
// app/gateway/internal/handler/version.go
package handler

import (
    "net/http"

    "github.com/gin-gonic/gin"
    "mall-lite/pkg/version"
)

func Version(c *gin.Context) {
    c.JSON(http.StatusOK, gin.H{"code": 0, "message": "ok", "data": version.Info()})
}
```

```bash
VERSION=$(git describe --tags --always --dirty)
COMMIT=$(git rev-parse --short HEAD)
BUILD_TIME=$(git log -1 --format=%cI)
CGO_ENABLED=0 go build -trimpath -buildvcs=false \
  -ldflags "-s -w -X mall-lite/pkg/version.Version=${VERSION} \
    -X mall-lite/pkg/version.Commit=${COMMIT} \
    -X mall-lite/pkg/version.BuildTime=${BUILD_TIME}" \
  -o bin/gateway ./app/gateway/cmd
```

```powershell
$env:VERSION = git describe --tags --always --dirty
$env:BUILD_TIME = git log -1 --format=%cI
$env:CGO_ENABLED = "0"
go build -trimpath -buildvcs=false `
  -ldflags "-s -w -X mall-lite/pkg/version.Version=$env:VERSION -X mall-lite/pkg/version.Commit=$(git rev-parse --short HEAD) -X mall-lite/pkg/version.BuildTime=$env:BUILD_TIME" `
  -o bin/gateway ./app/gateway/cmd
```

写 `version.Version` 或 `main.version` 都不生效；漏写模块前缀是最高频的「版本一直是 dev」原因。

## 三、交叉编译矩阵

| 目标 | GOOS | GOARCH | 后缀 | 场景 |
| --- | --- | --- | --- | --- |
| Linux x86_64 | `linux` | `amd64` | 无 | K8s 生产主力 |
| Linux ARM64 | `linux` | `arm64` | 无 | 鲲鹏/Ampere 节点 |
| Windows x86_64 | `windows` | `amd64` | `.exe` | 运维本机工具 |
| macOS Apple Silicon | `darwin` | `arm64` | 无 | 本地开发 |

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o bin/gateway-linux-arm64 ./app/gateway/cmd
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -o bin/gateway-windows-amd64.exe ./app/gateway/cmd
```

```powershell
$env:CGO_ENABLED = "0"
$env:GOOS = "linux"; $env:GOARCH = "arm64"
go build -trimpath -o bin/gateway-linux-arm64 ./app/gateway/cmd
$env:GOOS = "windows"; $env:GOARCH = "amd64"
go build -trimpath -o bin/gateway-windows-amd64.exe ./app/gateway/cmd
```

依赖 CGO 的库会让交叉编译直接失败；正确做法是换纯 Go 实现，或在目标架构的容器里构建（下一篇的 buildx 就是这条路）。

## 四、build tags 按环境裁剪

```go
// pkg/config/profile_dev.go
//go:build dev

package config

func Profile() string { return "dev" }

// pkg/config/profile_prod.go
//go:build prod

package config

func Profile() string { return "prod" }
```

```bash
go build -tags dev  -trimpath -o bin/gateway-dev  ./app/gateway/cmd
go build -tags prod -trimpath -o bin/gateway      ./app/gateway/cmd
```

build tags 只做**编译期裁剪**：dev 才编入 pprof、调试路由、mock 客户端。切数据库地址、开关业务开关属于 Viper 的职责，不要塞进 tags，否则同一个二进制无法用配置区分环境。

## 五、可复现构建

四个条件同时成立，同一 commit 才能得到同一 sha256：

- 工具链固定：`go.mod` 写 `go 1.25.0`，CI 设 `GOTOOLCHAIN=local`
- 时间固定：`BUILD_TIME` 取 Git 提交时间，而不是 `date now`
- 参数固定：`-trimpath -buildvcs=false` + 固定 ldflags
- 产物校验：构建后生成 sha256，跨机对比

```bash
BUILD_TIME=$(git show -s --format=%cI HEAD)
CGO_ENABLED=0 go build -trimpath -buildvcs=false \
  -ldflags "-s -w -X mall-lite/pkg/version.BuildTime=${BUILD_TIME}" \
  -o bin/gateway ./app/gateway/cmd
sha256sum bin/gateway
```

## 六、瘦身：strip 与 UPX

| 构建方式 | 体积（示例） | 说明 |
| --- | --- | --- |
| 默认构建 | 约 14 MB | 含符号表、DWARF、本地路径 |
| `-trimpath -s -w` | 约 9 MB | 推荐，panic 栈仍有函数名与行号 |
| 再加 UPX | 约 4 MB | 不建议进镜像 |

`-s -w` 去掉的是符号表与 DWARF，`pclntab` 保留，所以 `panic` 栈、`/debug/pprof` 依然可用，只是不能用 dlv 做源码级调试。UPX 的问题更多：杀软与容器安全策略误报、启动时解压占用 CPU、可执行段被 W^X 策略拦截、镜像层无法跨版本复用。

## 完整示例

`Makefile`（Windows 用户用 Git Bash 或 `choco install make` 执行）：

```text
MODULE     := mall-lite
VERSION    := $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT     := $(shell git rev-parse --short HEAD 2>/dev/null || echo none)
BUILD_TIME := $(shell git show -s --format=%cI HEAD 2>/dev/null || echo unknown)
LDFLAGS    := -s -w -X $(MODULE)/pkg/version.Version=$(VERSION) \
              -X $(MODULE)/pkg/version.Commit=$(COMMIT) \
              -X $(MODULE)/pkg/version.BuildTime=$(BUILD_TIME)
GOBUILD    := CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags "$(LDFLAGS)"

.PHONY: build build-linux build-arm64 build-windows verify

build: ; $(GOBUILD) -o bin/gateway ./app/gateway/cmd
build-linux: ; GOOS=linux GOARCH=amd64 $(GOBUILD) -o bin/gateway-linux-amd64 ./app/gateway/cmd
build-arm64: ; GOOS=linux GOARCH=arm64 $(GOBUILD) -o bin/gateway-linux-arm64 ./app/gateway/cmd
build-windows: ; GOOS=windows GOARCH=amd64 $(GOBUILD) -o bin/gateway.exe ./app/gateway/cmd
verify: ; go version -m bin/gateway && sha256sum bin/gateway
```

## 常见坑

1. **`-X` 路径写错**：必须写 `mall-lite/pkg/version.Version`；`-X` 也只支持字符串变量，int/bool 注入无效。
2. **忘记 `CGO_ENABLED=0`**：产出的二进制动态链接 libc，放进 scratch 直接 `exec format error` 或找不到解释器。
3. **PowerShell 环境污染**：`$env:GOOS` 不清理，后续本地调试产出的是 Linux 二进制。
4. **用 `date now` 做 BuildTime**：同一 commit 每次构建哈希都不同，可复现失效。
5. **生产开 `-race`**：性能下降数倍且依赖 CGO，不能作为发布产物。
6. **版本号带 `-dirty` 直接发布**：CI 应在此处失败，而不是发出一个无法对应 commit 的版本。

## 小结

- 生产构建的基本盘是 `-trimpath -buildvcs=false -ldflags "-s -w"` + `CGO_ENABLED=0`
- 版本、提交号、构建时间用 `-X` 注入到 `pkg/version`，由 `/version` 暴露并可用 BuildInfo 复核
- 交叉编译只需 `GOOS/GOARCH`，前提是所有依赖都是纯 Go

## 练习

1. 给 `/version` 增加 `runtime.GOOS/GOARCH`，交叉编译后分别在 Linux 与 Windows 上验证输出。
2. 用 Git 提交时间连续构建两次，确认 `sha256sum` 完全一致；再把 `BUILD_TIME` 换成当前时间复现失败。
3. 故意把 `-X` 路径写成 `main.version`，观察 `/version` 仍是 `dev` 并解释原因。
