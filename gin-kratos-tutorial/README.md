## 二、技术栈分层（贯穿全教程）

| 层 | 选型 | 只负责这些事 | 关键约束 |
| --- | --- | --- | --- |
| 流量入口层 / 南北向网关 | Apache APISIX 3.11 | 路由转发、JWT 初验、限流、灰度、协议转换、可观测埋点 | 客户端不直连微服务，网关做第一道流量治理 |
| HTTP 接入层 / BFF | Gin v1.10 | 路由、中间件、参数绑定校验、统一 JSON、聚合、SSE | 不放业务规则、不碰数据库 |
| 微服务框架层 | Kratos v2.8 | Protobuf 契约、gRPC/HTTP 双协议、注册发现、负载均衡、中间件链、链路追踪 | 领域逻辑与数据所有权都在这一层 |
| 数据访问层 | GORM v1.25 | 各服务独立访问自己的库：CRUD、事务、关联、连接池 | 每服务独立 DB，禁止跨服务直连 |
| 流量防护层 | Sentinel Go v1.0.4 | 限流、熔断、降级、热点参数、系统自适应保护 | 以中间件嵌入 Gin/Kratos，规则动态下发 |
| 可观测 / 日志层 | zap v1.27 + OpenTelemetry | 结构化日志、指标、链路；`request_id`/`trace_id` 贯穿 | 日志、指标、追踪三者用同一 ID 串联 |
| 配置层 | Viper v1.20 | 多环境 YAML、环境变量、热更新 | 敏感信息只从环境变量/Secret 注入 |

> 一句话记住边界：**APISIX 管入口，Gin 管 HTTP 面，Kratos 管服务骨架，GORM 管本服务数据，Sentinel 管防护，zap/Viper 管可观测与配置。**

## 三、学习路线（五个阶段）

```
阶段一 打地基      Go 环境 → Go 语法 → 标准库 net/http → 第一个 Gin 服务
阶段二 会使用      路由 / Context / 绑定校验 / 响应 / 中间件 / 错误处理 / 测试
阶段三 能上生产    zap 日志 / OTel 追踪 / Sentinel 防护 / Viper 配置 / 工程化 / CI / Docker
阶段四 数据与中间件 MySQL+GORM / Redis 缓存 / Kafka 消息（企业服务的地基）
阶段五 微服务落地  Kratos gRPC + etcd/Consul + APISIX 网关 + 分布式事务 → mall-lite 实战 → K8s
```

## 四、贯穿项目：mall-lite

所有数据层、缓存、消息、微服务章节都围绕同一个项目展开，避免知识点各自为战：

```
客户端 ──HTTP──▶ APISIX 3.11（路由、JWT 初验、限流、灰度）
                     │
                     ▼
              Gin BFF :8080（二次鉴权、聚合、统一响应、SSE）
                     │ gRPC
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
 user-service   product-service  order-service     ← Kratos gRPC :9001/9002/9003
      │              │              │
      └──────┬───────┴──────┬───────┘
             ▼              ▼
          MySQL 8.4       Redis 7.4        Kafka 3.8
        （每服务独立库）   （缓存/锁/排行）   （订单事件/库存异步）
             │
             ▼
     etcd 3.5 / Consul 1.20（注册发现）
     Sentinel Go（限流熔断）· Viper（配置）
     OpenTelemetry + Jaeger + Prometheus + Grafana（可观测）
     Docker + Kubernetes（部署）
```

**下单主链路**：APISIX → Gin BFF → order-service → product-service（预扣库存）→ MySQL 本地事务 + Outbox → Kafka 订单事件 → 异步扣减/通知 → 最终一致。

**查询主链路**：APISIX → Gin BFF → Redis 缓存命中直接返回 → 未命中回源 MySQL 并回填缓存。

## 六、版本基线

- 语言 **Go 1.25**；Web **Gin v1.10.x**；微服务 **Kratos v2.8.x**（gRPC + Protobuf）
- 注册中心 **etcd 3.5 / Consul 1.20**；网关 **APISIX 3.11**；防护 **Sentinel Go v1.0.4**
- 数据 **GORM v1.25 + MySQL 8.4**；缓存 **go-redis v9 + Redis 7.4**；消息 **Kafka 3.8**
- 配置 **Viper v1.20**；日志 **zap v1.27**；可观测 **OpenTelemetry + Jaeger + Prometheus + Grafana**
- 部署 **Docker + Kubernetes 1.31**

> 以上为「教程基线」，示例锁定具体版本；实际项目以各组件官方最新稳定版为准。统一模块名为 `mall-lite`，端口与响应格式见 [学习计划](学习计划与时间估算.md) 与第 13 章。

## 七、学习建议

1. **每篇文章都动手敲一遍**，框架的很多行为（中间件顺序、绑定失败、优雅退出）只看文字学不会。
2. **先跑通再深入**：遇到不会的 API，先看示例跑通，再回头读原理。
3. **每章末尾有练习**，做完再进入下一章；数据层与微服务章节务必用 Docker 起真实依赖。
4. 企业级部分不要跳过工程化、测试与可观测性——这是把「能跑」变成「能长期跑」的分水岭。
