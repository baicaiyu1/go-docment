# 结构体、方法与接口

> Go 没有类和继承，但有结构体、方法和隐式接口；理解这三样，你才能读懂 Hertz 的 Handler、中间件与扩展点。

## 本篇目标

- 会定义结构体、用两种字面量初始化，并理解结构体的零值可用性
- 分清值接收者与指针接收者，掌握方法集规则，知道什么时候必须用指针
- 理解接口的隐式实现，能写出「面向接口编程」的业务代码
- 掌握类型断言与 `type switch`，安全地从接口中取出具体类型
- 用嵌入与组合替代继承，避开 nil 接口等经典陷阱

## 前置知识

- 已完成 [03-流程控制与函数](03-流程控制与函数.md)
- 理解函数、多返回值与指针的基本概念
- 知道 `fmt.Printf` 的 `%v` / `%+v`

## 一、结构体：把相关字段打包

```go
type User struct {
	ID        int64
	Name      string
	Email     string
	CreatedAt time.Time
}

u1 := User{ID: 1, Name: "alice"}     // 具名字段（推荐）
u2 := User{2, "bob", "b@x.com", now} // 按位置（不推荐，易错位）
u3 := &User{ID: 3, Name: "carol"}    // 指针
```

结构体的零值是「每个字段各自取零值」，所以 `var u User` 合法，`u.ID == 0`、`u.Name == ""`。这也是为什么前面强调「让零值可用」：调用方可以不用 `New` 就构造。

构造函数不是语法特性，而是约定：

```go
func NewUser(id int64, name, email string) *User {
	return &User{ID: id, Name: name, Email: email, CreatedAt: time.Now()}
}
```

返回指针还是值：结构体小（≤ 3 个字段、无引用类型）返回值，避免堆分配；需要修改、含 `sync.Mutex` 或字段多时返回指针；作为接口实现时通常返回指针（原因见方法集）。

## 二、方法：给类型挂函数

方法是带接收者的函数：

```go
func (u User) DisplayName() string { return u.Name } // 值接收者

func (u *User) Rename(name string) { u.Name = name } // 指针接收者

func (u User) String() string { // 实现 fmt.Stringer
	return fmt.Sprintf("User(%d, %s)", u.ID, u.Name)
}

u := User{ID: 1, Name: "alice"}
u.Rename("alice2") // 等价于 (&u).Rename("alice2")
fmt.Println(u)     // 自动调用 String()，输出 User(1, alice2)
```

| 维度 | 值接收者 `func (u User)` | 指针接收者 `func (u *User)` |
| --- | --- | --- |
| 是否能修改原对象 | 否（改的是副本） | 是 |
| 大结构体开销 | 每次调用都拷贝 | 只拷贝指针 |
| 方法集（T） | 包含 | **不包含** |
| 方法集（*T） | 包含（自动解引用） | 包含 |

选择原则：需要修改接收者 → 指针；结构体较大或含不可拷贝字段 → 指针；其余情况保持**同一类型的方法接收者一致**。

## 三、接口：隐式实现

接口只声明行为，不关心谁实现：

```go
type UserRepository interface {
	FindByID(ctx context.Context, id int64) (*User, error)
	Save(ctx context.Context, u *User) error
}
```

任何类型只要**方法签名完全匹配**，就自动实现了这个接口，不需要 `implements` 关键字：

```go
type memoryRepo struct{ data map[int64]*User }

func (r *memoryRepo) FindByID(ctx context.Context, id int64) (*User, error) {
	u, ok := r.data[id]
	if !ok {
		return nil, fmt.Errorf("user %d not found", id)
	}
	return u, nil
}

func (r *memoryRepo) Save(ctx context.Context, u *User) error {
	r.data[u.ID] = u
	return nil
}

var _ UserRepository = (*memoryRepo)(nil) // 编译期断言实现关系
```

最后一行不产生运行时开销，但一旦接口或方法改了，编译立刻失败。

**为什么隐式实现很重要？** 它解耦了「接口定义方」与「实现方」：你可以在自己的包定义 `UserRepository`，而实现来自数据库包，双方不需要互相 import。Hertz 的很多扩展点都依赖这种能力。

`interface{}` 等价于 `any`（Go 1.18 起的别名），不要滥用，它等于放弃类型检查。

## 四、类型断言与 type switch

从接口中取回具体类型：

```go
var v any = "hertz"

s, ok := v.(string) // 安全写法：comma-ok
if !ok {
	fmt.Println("不是字符串")
} else {
	fmt.Println("字符串:", s)
}

switch x := v.(type) { // 判断多种类型
case string:
	fmt.Println("string:", x)
case int:
	fmt.Println("int:", x)
case nil:
	fmt.Println("nil")
default:
	fmt.Printf("unknown: %T\n", x)
}
```

`v.(int)` 这种不带 ok 的断言，类型不符会 panic。`case nil` 只能匹配「接口值为 nil」，匹配不到「接口里装着一个 nil 指针」的情况。

## 五、组合与嵌入

Go 不支持继承，推荐组合。嵌入会把内部类型的字段和方法「提升」到外层：

```go
type BaseModel struct {
	ID        int64
	CreatedAt time.Time
}

type Article struct {
	BaseModel // 嵌入，字段名默认是 BaseModel
	Title     string
}

a := Article{Title: "hello"}
a.ID = 1                    // 直接访问提升字段
fmt.Println(a.BaseModel.ID) // 也可以显式访问
```

外层与内层同名字段时外层优先。如果只是想「拥有一个组件」，用命名字段更清晰：

```go
type UserService struct {
	repo UserRepository // 组合：明确表达依赖
	log  Logger
}
```

Hertz 的服务结构体通常是这种形式：`service` 持有 `repo`、`cache`、`logger`，通过构造函数注入。

## 六、实战：面向接口的 Handler

把上一篇的函数式 Handler 改成接口式，更接近 Hertz 的设计：

```go
type Request struct{ Path string }

type Response struct {
	Code int
	Body string
}

type Handler interface {
	Serve(ctx context.Context, req *Request) (*Response, error)
}

type HandlerFunc func(ctx context.Context, req *Request) (*Response, error)

func (f HandlerFunc) Serve(ctx context.Context, req *Request) (*Response, error) {
	return f(ctx, req)
}

func main() {
	var h Handler = HandlerFunc(func(ctx context.Context, req *Request) (*Response, error) {
		return &Response{Code: 200, Body: "hello, hertz"}, nil
	})
	resp, _ := h.Serve(context.Background(), &Request{Path: "/hello"})
	fmt.Println(resp.Code, resp.Body)
}
```

`HandlerFunc` 是标准库 `http.HandlerFunc` 的同款技巧：把函数适配成接口。学完这篇，你已经能看懂 Hertz 为什么用 `app.GET(path, handler)` 这样的 API。

## 七、经典陷阱：nil 接口

```go
type MyError struct{}

func (e *MyError) Error() string { return "my error" }

func main() {
	var p *MyError = nil
	var err error = p
	fmt.Println(err == nil) // false！
}
```

`err` 是接口值，包含「类型 + 值」两部分：类型是 `*MyError`、值是 nil，所以接口本身不是 nil。函数返回 `error` 时如果写 `return e`（`e` 是 nil 指针），调用方的 `if err != nil` 会误判为有错误，正确做法是显式 `return nil`。

## 常见坑

1. **指针接收者方法导致接口不满足**：`*T` 有方法但 `T` 没有，把值赋给接口会编译失败。统一用指针接收者通常最省心。
2. **nil 接口不等于 nil 指针**：见上一节，返回 `error` 时尤其危险。
3. **拷贝含 `sync.Mutex` 的结构体**：`go vet` 会报警，锁会失效。
4. **嵌入导致方法冲突**：两个嵌入类型有同名方法时，外层调用会编译错误，必须显式指定。
5. **用 `any` 代替明确类型**：丢了编译期检查，运行时靠断言，容易 panic。
6. **结构体字面量按位置初始化**：字段一改就错位，团队规范一般要求具名字段。

## 小结

结构体打包数据，方法绑定行为，接口描述契约，嵌入实现复用。这套组合是 Hertz 代码的基础：`Engine`、`Context`、`Handler` 都是结构体 + 方法 + 接口。下一篇 [05-错误处理与panic-recover](05-错误处理与panic-recover.md) 补齐「出错时怎么办」。
