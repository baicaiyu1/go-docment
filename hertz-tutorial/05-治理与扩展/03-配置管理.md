# 配置管理
> 一句话定位：为 hz 生成的 Hertz 项目补上一套“可分层、可校验、可热更”的配置方案。
## 本篇目标
- 认清边界：Hertz 与 hz 都不提供配置文件加载
- 设计 `conf/` 目录与多环境覆盖
- 用 YAML 加载结构体，并支持环境变量覆盖
- 做启动期校验、密钥管理与有限热加载
- 把配置接入 hz 生成项目的启动流程
## 前置知识
- 已完成 [02-Hertz入门/04-项目结构与代码生成布局](../02-Hertz入门/04-项目结构与代码生成布局.md)
- 了解 Go struct tag 与 12-Factor 的“配置与代码分离”
## 一、先划清边界
Hertz 只提供启动选项（`server.Option`、`client.Option`），不负责配置文件解析、环境隔离与热加载；`hz` 脚手架也不会生成 `conf/`。下面是工程约定：
```text
project/
├── main.go
├── conf/
│   ├── config.yaml        # 默认，可提交
│   ├── config.dev.yaml    # 开发覆盖
│   └── config.prod.yaml   # 生产覆盖（不含密钥）
└── pkg/config/            # 结构体 + 加载 + 校验
```
`pkg/` 是自定义目录，hz 不生成也不会覆盖，适合放基础设施代码。
## 二、配置结构与 YAML
```yaml
app:
  name: order-service
  env: dev
server:
  addr: 0.0.0.0:8888
  read_timeout: 5s
  exit_wait_time: 10s
log:
  level: info
  file: logs/app.log
mysql:
  dsn: root:root@tcp(127.0.0.1:3306)/order?parseTime=true
  max_open: 100
  max_idle: 20
registry:
  type: consul
  address: 127.0.0.1:8500
  service_name: order-service
  weight: 10
```
```go
type Config struct {
	App      AppConfig      `yaml:"app"`
	Server   ServerConfig   `yaml:"server"`
	Log      LogConfig      `yaml:"log"`
	MySQL    MySQLConfig    `yaml:"mysql"`
	Registry RegistryConfig `yaml:"registry"`
}

type AppConfig struct {
	Name string `yaml:"name"`
	Env  string `yaml:"env"`
}

type ServerConfig struct {
	Addr         string        `yaml:"addr"`
	ReadTimeout  time.Duration `yaml:"read_timeout"`
	ExitWaitTime time.Duration `yaml:"exit_wait_time"`
}

type LogConfig struct {
	Level string `yaml:"level"`
	File  string `yaml:"file"`
}

type MySQLConfig struct {
	DSN     string `yaml:"dsn"`
	MaxOpen int    `yaml:"max_open"`
	MaxIdle int    `yaml:"max_idle"`
}

type RegistryConfig struct {
	Type        string `yaml:"type"`
	Address     string `yaml:"address"`
	ServiceName string `yaml:"service_name"`
	Weight      int    `yaml:"weight"`
}
```
`time.Duration` 能直接解析 `5s`、`500ms`，避免到处写 `* time.Second`。
## 三、加载与多环境合并
```bash
go get gopkg.in/yaml.v3
```
```go
func Load(env string) (*Config, error) {
	cfg := &Config{}
	if err := mergeFile(cfg, "conf/config.yaml"); err != nil {
		return nil, err
	}
	if env != "" {
		path := fmt.Sprintf("conf/config.%s.yaml", env)
		if _, err := os.Stat(path); err == nil {
			if err := mergeFile(cfg, path); err != nil {
				return nil, err
			}
		}
	}
	applyEnv(cfg)
	return cfg, nil
}

func mergeFile(cfg *Config, path string) error {
	b, err := os.ReadFile(path)
	if err != nil {
		return fmt.Errorf("read %s: %w", path, err)
	}
	if err := yaml.Unmarshal(b, cfg); err != nil {
		return fmt.Errorf("parse %s: %w", path, err)
	}
	return nil
}
```
YAML 反序列化是“字段覆盖”，切片不会深度合并。TOML 只需换成 `BurntSushi/toml` 的 `toml.DecodeFile` 并把 tag 改为 `toml`。
## 四、环境变量优先级
优先级：默认值 < `config.yaml` < `config.{env}.yaml` < 环境变量 < 命令行参数。
```go
func applyEnv(cfg *Config) {
	if v := os.Getenv("APP_ENV"); v != "" {
		cfg.App.Env = v
	}
	if v := os.Getenv("SERVER_ADDR"); v != "" {
		cfg.Server.Addr = v
	}
	if v := os.Getenv("MYSQL_DSN"); v != "" {
		cfg.MySQL.DSN = v
	}
	if v := os.Getenv("LOG_LEVEL"); v != "" {
		cfg.Log.Level = v
	}
}
```
显式映射 5~10 个关键变量，比隐式映射更可控。开发设置：
```powershell
$env:APP_ENV = "dev"; $env:SERVER_ADDR = "127.0.0.1:9000"; go run .
```
```bash
export APP_ENV=dev SERVER_ADDR=127.0.0.1:9000; go run .
```
## 五、启动期校验
```go
func (c *Config) Validate() error {
	var errs []string
	if c.App.Name == "" {
		errs = append(errs, "app.name is required")
	}
	if c.App.Env != "dev" && c.App.Env != "test" && c.App.Env != "prod" {
		errs = append(errs, "app.env must be dev/test/prod")
	}
	if _, _, err := net.SplitHostPort(c.Server.Addr); err != nil {
		errs = append(errs, "server.addr invalid")
	}
	if strings.Contains(c.MySQL.DSN, "root:root") && c.App.Env == "prod" {
		errs = append(errs, "default mysql dsn is not allowed in prod")
	}
	if c.MySQL.MaxIdle > c.MySQL.MaxOpen {
		errs = append(errs, "mysql.max_idle must <= max_open")
	}
	if len(errs) > 0 {
		return errors.New("invalid config:\n  - " + strings.Join(errs, "\n  - "))
	}
	return nil
}
```
配置错误必须在启动时暴露；可选地再 Ping 一次 MySQL/Redis，避免带病上线。
## 六、密钥管理
三条底线：密钥不进 Git（生产文件只放占位）；密钥不进日志（只打印非敏感字段）；最小权限（各服务独立账号，禁用统一 root）。
```yaml
env:
  - name: MYSQL_DSN
    valueFrom:
      secretKeyRef:
        name: order-service-secret
        key: mysql-dsn
```
本地可用 `.env` + godotenv，但必须加入 `.gitignore`；生产禁止 `.env` 文件。
## 七、热加载的边界
大部分配置不需要热加载。改地址、DSN、超时应走发布流程。只建议对限流阈值、降级开关、日志级别、灰度白名单热更：
```go
var current atomic.Pointer[Config]

func Watch(path string) error {
	w, err := fsnotify.NewWatcher()
	if err != nil {
		return err
	}
	if err := w.Add(path); err != nil {
		return err
	}
	go func() {
		for range w.Events {
			cfg, err := Load(os.Getenv("APP_ENV"))
			if err != nil || cfg.Validate() != nil {
				hlog.Errorf("reload failed, keep old: %v", err)
				continue
			}
			current.Store(cfg)
		}
	}()
	return nil
}
```
要点：原子替换、校验失败保留旧值、依赖组件提供 `Reload`。配置中心同理，只是把文件监听换成订阅。
## 八、接入 hz 项目
```go
func main() {
	cfg, err := config.Load(os.Getenv("APP_ENV"))
	if err != nil || cfg.Validate() != nil {
		panic(err)
	}
	initLogger(cfg.Log)

	h := server.Default(
		server.WithHostPorts(cfg.Server.Addr),
		server.WithReadTimeout(cfg.Server.ReadTimeout),
		server.WithExitWaitTime(cfg.Server.ExitWaitTime),
	)
	register(h) // 保持 hz 生成的注册入口
	h.Spin()
}
```
不要修改 `biz/router/register.go` 与 `*_gen.go`，配置只在 `main.go` 与 `pkg/` 中使用。
## 常见坑
1. 真实密码写进 `config.yaml` 并提交：历史记录永久留存，必须立即轮换。
2. YAML 用 Tab 缩进会直接解析失败；只允许空格。
3. `read_timeout: 5` 会被当成 5ns，必须写 `5s`。
4. 多环境文件不会深度合并，列表字段被整体覆盖。
5. `APP_ENV=prd` 拼错会静默使用默认配置，生产连到测试库。
6. 热加载不校验，一个错字段让全实例配置归零。
7. 启动日志不打印 env/version，排障时不知道加载了哪份配置。
## 小结
- Hertz 只管启动选项，配置体系要自己搭
- `conf/` + 多环境 + 环境变量，是最通用的三层结构
- 启动校验能挡住大多数配置事故
- 密钥只走 Secret/环境变量，仓库与日志都不能出现明文
- 热加载只用于少量动态开关，校验失败必须保留旧值
