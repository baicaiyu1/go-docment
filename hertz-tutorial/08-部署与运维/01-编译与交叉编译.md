# 编译与交叉编译
> 一句话定位：用一条可复现的构建命令，产出带版本信息、体积可控、能跑在目标平台上的二进制。

## 本篇目标

- 掌握 `go build` 的关键参数：`-trimpath`、`-ldflags`、`CGO_ENABLED`
- 用 `-X` 注入版本、提交号、构建时间，并通过 `/version` 暴露
- 完成 Linux / Windows / macOS 的交叉编译
- 写出 bash 与 PowerShell 构建脚本，保证构建可复现、产物可校验

## 前置知识

- 已读 [08-部署与运维/02-Docker镜像与多阶段构建](02-Docker镜像与多阶段构建.md) 之前的构建基础
- 了解 Go Module、`cmd/<service>` 入口与 Git tag

## 一、基础构建

```bash
go env GOOS GOARCH GOVERSION
mkdir -p bin && go build -trimpath -o bin/userapi ./cmd/userapi
```

```powershell
go env GOOS GOARCH GOVERSION
New-Item -ItemType Directory -Force -Path bin | Out-Null
go build -trimpath -o bin/userapi.exe ./cmd/userapi
```

`go build` 默认把源码绝对路径、VCS 信息写进二进制；生产构建建议加 `-trimpath`，避免泄漏构建机目录结构。

## 二、ldflags 注入版本信息

只在**字符串变量**上生效，且必须写完整导入路径。先定义版本包：

```go
package version

import "runtime"

var (
	Version   = "dev"
	Commit    = "none"
	BuildTime = "unknown"
)

func Info() map[string]string {
	return map[string]string{
		"version": Version, "commit": Commit, "build_time": BuildTime, "go": runtime.Version(),
	}
}
```

注册 `/version` 接口：

```go
h.GET("/version", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, version.Info())
})
```

构建时注入：

```bash
VERSION=$(git describe --tags --always --dirty)
COMMIT=$(git rev-parse --short HEAD)
BUILD_TIME=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
mkdir -p bin
CGO_ENABLED=0 go build -trimpath -buildvcs=false \
  -ldflags "-s -w -X hertz_demo/internal/version.Version=${VERSION} -X hertz_demo/internal/version.Commit=${COMMIT} -X hertz_demo/internal/version.BuildTime=${BUILD_TIME}" \
  -o bin/userapi ./cmd/userapi
```

```powershell
$VERSION = git describe --tags --always --dirty
$COMMIT = git rev-parse --short HEAD
$BUILD_TIME = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
New-Item -ItemType Directory -Force -Path bin | Out-Null
$env:CGO_ENABLED = "0"
go build -trimpath -buildvcs=false `
  -ldflags "-s -w -X hertz_demo/internal/version.Version=$VERSION -X hertz_demo/internal/version.Commit=$COMMIT -X hertz_demo/internal/version.BuildTime=$BUILD_TIME" `
  -o bin/userapi ./cmd/userapi
```

## 三、构建参数速查

| 参数 | 作用 | 生产建议 |
| --- | --- | --- |
| `-trimpath` | 去掉本地绝对路径 | 必加 |
| `-buildvcs=false` | 不写 VCS 信息，构建更可控 | 需可复现时加 |
| `-ldflags "-s -w"` | 去符号表与 DWARF，减小体积 | 必加 |
| `-ldflags "-X pkg.Var=v"` | 注入字符串变量 | 版本信息必加 |
| `CGO_ENABLED=0` | 纯静态二进制，便于 scratch/distroless | 必加 |
| `-race` | 竞态检测 | 仅测试，禁止生产 |

需要更小体积可加 `-tags netgo,osusergo`，但不建议再上 UPX：压缩后的二进制易被杀毒软件误报，且启动时需解压。

## 四、交叉编译

| 目标平台 | GOOS | GOARCH | 产物后缀 |
| --- | --- | --- | --- |
| Linux x86_64 | `linux` | `amd64` | 无 |
| Linux ARM64 | `linux` | `arm64` | 无 |
| Windows x86_64 | `windows` | `amd64` | `.exe` |
| macOS Apple Silicon | `darwin` | `arm64` | 无 |

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o bin/userapi-linux-arm64 ./cmd/userapi
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -o bin/userapi-windows-amd64.exe ./cmd/userapi
```

```powershell
$env:CGO_ENABLED = "0"; $env:GOOS = "linux"; $env:GOARCH = "arm64"
go build -trimpath -o bin/userapi-linux-arm64 ./cmd/userapi
$env:GOOS = "windows"; $env:GOARCH = "amd64"
go build -trimpath -o bin/userapi-windows-amd64.exe ./cmd/userapi
Remove-Item Env:GOOS, Env:GOARCH, Env:CGO_ENABLED
```

只要依赖了 `CGO`（如 sqlite、某些加密库），交叉编译就会失败；这类服务应改用纯 Go 驱动，或在目标架构的容器里构建。

## 五、构建脚本

`scripts/build.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

MODULE=hertz_demo
VERSION=$(git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT=$(git rev-parse --short HEAD 2>/dev/null || echo none)
BUILD_TIME=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
OUT=bin/userapi

mkdir -p bin
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build \
  -trimpath -buildvcs=false \
  -ldflags "-s -w -X ${MODULE}/internal/version.Version=${VERSION} -X ${MODULE}/internal/version.Commit=${COMMIT} -X ${MODULE}/internal/version.BuildTime=${BUILD_TIME}" \
  -o "$OUT" ./cmd/userapi
sha256sum "$OUT" > "$OUT.sha256"
go version -m "$OUT"
```

`scripts/build.ps1`：

```powershell
$ErrorActionPreference = "Stop"
$Module = "hertz_demo"
$Version = git describe --tags --always --dirty 2>$null
if (-not $Version) { $Version = "dev" }
$Commit = git rev-parse --short HEAD 2>$null
if (-not $Commit) { $Commit = "none" }
$BuildTime = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
$Out = "bin/userapi.exe"

New-Item -ItemType Directory -Force -Path bin | Out-Null
$env:CGO_ENABLED = "0"; $env:GOOS = "linux"; $env:GOARCH = "amd64"
go build -trimpath -buildvcs=false `
  -ldflags "-s -w -X $Module/internal/version.Version=$Version -X $Module/internal/version.Commit=$Commit -X $Module/internal/version.BuildTime=$BuildTime" `
  -o $Out ./cmd/userapi
Get-FileHash $Out -Algorithm SHA256 | Out-File "$Out.sha256"
```

## 七、`/version` 与构建信息

```text
$ curl -s localhost:8888/version
{"build_time":"2026-11-23T03:20:00Z","commit":"a1b2c3d","go":"go1.25.0","version":"v1.4.0"}
```

排障时先比对 `/version` 与发布记录：版本对不上，先怀疑镜像 tag 或流水线缓存，而不是业务代码。

## 八、构建可复现性

- `go.mod` 固定 `go 1.25.0`，并设置 `GOTOOLCHAIN=local`，禁止构建机偷偷升级工具链
- 时间注入使用 Git 提交时间，而不是 `date now`，同一 commit 才能得到同一哈希
- 固定基础镜像（如 `golang:1.25-bookworm`）与构建参数，构建后用 `sha256sum` 对比
- 保留 `-buildvcs=false` 时，版本信息完全由 ldflags 决定，构建结果不随 `.git` 变化

```bash
SOURCE_DATE_EPOCH=$(git log -1 --format=%ct)
BUILD_TIME=$(date -u -d "@${SOURCE_DATE_EPOCH}" +"%Y-%m-%dT%H:%M:%SZ")
```

```powershell
$epoch = [int](git log -1 --format=%ct)
$BUILD_TIME = [DateTimeOffset]::FromUnixTimeSeconds($epoch).UtcDateTime.ToString("yyyy-MM-ddTHH:mm:ssZ")
```

## 常见坑

1. **`-X` 路径写错**：必须写 `module/internal/version.Version`，写 `main.version` 不生效；`-X` 也只支持字符串变量。
2. **交叉编译忘记 `CGO_ENABLED=0`**：链接 libc 失败，或在目标机报 `not found`。
3. **PowerShell 环境污染**：`$env:GOOS` 不清理，后续本地调试也会产出 Linux 二进制。
4. **版本号带 `-dirty`**：CI 里工作区不干净时应直接失败，而不是发布一个语义不明的版本。
5. **注入本地时区时间**：多节点构建结果不一致；统一使用 UTC。
6. **生产开 `-race`**：性能下降数倍，且需要 CGO，不能作为发布产物。

## 小结

- `-trimpath -s -w` + `CGO_ENABLED=0` 是生产构建的基本盘
- 版本、提交号、构建时间用 `-X` 注入，并由 `/version` 对外暴露
- 交叉编译靠 `GOOS/GOARCH`，纯 Go 依赖才能稳定跨平台
- 可复现构建 = 固定工具链 + 固定参数 + 固定时间源 + 哈希校验

## 练习

1. 给 `/version` 增加 `runtime.GOOS/GOARCH` 字段，并交叉编译验证输出。
2. 用 `SOURCE_DATE_EPOCH` 连续构建两次，确认 `sha256` 完全一致。
3. 故意把 `-X` 路径写成 `main.version`，观察 `/version` 仍是 `dev` 并解释原因。
