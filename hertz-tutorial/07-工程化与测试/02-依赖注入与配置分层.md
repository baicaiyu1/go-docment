# 依赖注入与配置分层
> 一句话定位：用显式依赖和分层配置，把“到处 new、到处读环境变量”的服务收敛成可测试、可替换、可优雅启停的应用。

## 本篇目标

- 理解全局变量持有依赖的代价，掌握构造函数注入
- 掌握 wire/fx 的定位与取舍，以及 server/db/redis/log 四层配置
- 用 App 结构体统一管理初始化顺序、启动与优雅退出

## 前置知识

- 已读 [07-工程化与测试/01-项目分层与目录规范](01-项目分层与目录规范.md)
- 熟悉 `database/sql`、Hertz 的 `server.Default` 与优雅退出（[03-基本特性/07-优雅退出](../03-基本特性/07-优雅退出.md)）

## 一、从全局变量到构造函数注入

```go
var db *sql.DB // 反例：包级全局，谁都能改

func GetUser(id int64) (*User, error) { /* 直接使用全局 db，无法替换实现 */ }
```

问题很实际：测试必须连真实库、无法替换实现、两个测试互相污染、初始化顺序靠 `init()` 隐式保证、同一个包无法创建两个实例。

正例：依赖作为参数显式传入，由组合根（`main`）负责组装：

```go
type UserService struct{ repo repository.UserRepository }

func NewUserService(repo repository.UserRepository) *UserService { return &UserService{repo: repo} }
```

三条原则：**依赖显式传入、接口定义在消费方、只有 main 认识所有具体实现**。

## 二、构造函数注入的组装顺序

```text
配置 → 日志 → MySQL / Redis → repository → service → handler → router → Hertz → App.Run
```

- 每一层只接收自己真正需要的依赖，不要传一个巨大的 `AppContext`；构造函数不产生副作用
- 初始化失败立即返回错误并退出；关闭顺序与初始化相反，先停 HTTP 再关连接池

## 三、wire 与 fx：要不要用

**wire（编译期生成）**：依赖多、想保持显式装配时使用。`wire.Build` 只是声明，生成代码可读、无反射：

```go
//go:build wireinject

package main

import "github.com/google/wire"

func InitApp(cfg *config.Config) (*App, error) {
	panic(wire.Build(provideDB, repository.ProviderSet, service.ProviderSet,
		handler.ProviderSet, newHertz, newApp))
}
```

安装并生成（PowerShell 与 bash 命令相同）：`go install github.com/google/wire/cmd/wire@latest && wire ./cmd/userapi`。

**fx（运行时容器）**：自带生命周期钩子，适合大型服务，但依赖反射、错误在运行期才暴露（`fx.New(fx.Provide(...), fx.Invoke(runServer)).Run()`）。

| 方案 | 优点 | 代价 | 适用 |
| --- | --- | --- | --- |
| 手写构造函数 | 零依赖、最好调试 | 依赖多时 main 很长 | 依赖 < 20 个 |
| wire | 编译期检查、生成代码可读 | 多一步代码生成 | 中大型团队 |
| fx | 生命周期、模块化 | 反射、启动期报错 | 平台型大服务 |

建议：先用构造函数，`main.go` 超过 100 行再引入 wire；fx 只在团队已有经验时使用。

## 四、配置结构体分层

用 `yaml` 标签分四层，自定义 `Duration` 支持 `5s` 写法（yaml 默认无法把字符串解析成 `time.Duration`）：

```go
package config

// import：fmt、os、strconv、time、gopkg.in/yaml.v3

type Duration time.Duration

func (d *Duration) UnmarshalYAML(n *yaml.Node) error {
	var s string
	if err := n.Decode(&s); err != nil { return err }
	v, err := time.ParseDuration(s)
	if err != nil { return err }
	*d = Duration(v)
	return nil
}

type Config struct {
	Server Server `yaml:"server"`
	DB     DB     `yaml:"db"`
	Redis  Redis  `yaml:"redis"`
	Log    Log    `yaml:"log"`
}
type Server struct {
	Addr            string   `yaml:"addr"`
	ReadTimeout     Duration `yaml:"read_timeout"`
	ShutdownTimeout Duration `yaml:"shutdown_timeout"`
}
type DB struct {
	DSN          string   `yaml:"dsn"`
	MaxOpenConns int      `yaml:"max_open_conns"`
	ConnLifetime Duration `yaml:"conn_max_lifetime"`
}
type Redis struct {
	Addr     string `yaml:"addr"`
	Password string `yaml:"password"`
}
type Log struct{ Level string `yaml:"level"` }

func Load(path string) (*Config, error) {
	cfg := &Config{}
	b, err := os.ReadFile(path)
	if err != nil { return nil, fmt.Errorf("read config %s: %w", path, err) }
	if err := yaml.Unmarshal(b, cfg); err != nil { return nil, fmt.Errorf("parse config: %w", err) }
	cfg.applyEnv()
	return cfg, nil
}
```

配置文件（可直接使用，生产需给全，缺失必填项应在启动时校验）：

```yaml
server:
  addr: ":8888"
  read_timeout: 5s
  shutdown_timeout: 15s
db:
  dsn: "app:app@tcp(127.0.0.1:3306)/app?parseTime=true&loc=Local"
  max_open_conns: 50
  conn_max_lifetime: 30m
redis:
  addr: "127.0.0.1:6379"
  password: ""
log:
  level: info
```

## 五、环境变量覆盖与优先级

优先级固定为 **环境变量 > 配置文件 > 默认值**；启动日志打印最终生效的关键配置（密码脱敏）：

```go
func (c *Config) applyEnv() {
	if v, ok := os.LookupEnv("APP_SERVER_ADDR"); ok { c.Server.Addr = v }
	if v, ok := os.LookupEnv("APP_DB_DSN"); ok { c.DB.DSN = v }
	if v, ok := os.LookupEnv("APP_REDIS_ADDR"); ok { c.Redis.Addr = v }
	if v, ok := os.LookupEnv("APP_LOG_LEVEL"); ok { c.Log.Level = v }
	if v, ok := os.LookupEnv("APP_DB_MAX_OPEN_CONNS"); ok {
		if n, err := strconv.Atoi(v); err == nil { c.DB.MaxOpenConns = n }
	}
}
```

| 变量 | 覆盖字段 | 生产建议 |
| --- | --- | --- |
| `APP_SERVER_ADDR` | `server.addr` | K8s 中固定 `:8888` |
| `APP_DB_DSN` | `db.dsn` | 只从 Secret 注入，禁止进 Git |

## 六、初始化顺序与失败处理

```text
Load config → Init logger → Open MySQL（Ping）→ repository → service → handler → hertz → App.Run → 信号 → Shutdown
```

- 每一步失败都返回 `error`，由 `main` 统一 `log.Fatalf`，不要 `panic` 后继续
- 不要在 `init()` 里连数据库：测试 import 包就会拨号，CI 直接失败
- 启动耗时操作放 `Run` 之前并设超时；关闭时先停 HTTP，再关连接池

## 七、App 结构体封装启停

Hertz 的 `Spin()` 会自动处理信号，但不会帮你关闭 DB；用 `Engine.Run()` + `Engine.Shutdown()` 精确控制收尾：

```go
type App struct {
	cfg *config.Config
	h   *server.Hertz
	db  *sql.DB
}

func NewApp(cfg *config.Config, h *server.Hertz, db *sql.DB) *App { return &App{cfg, h, db} }

func (a *App) Run(ctx context.Context) error {
	errCh := make(chan error, 1)
	go func() { errCh <- a.h.Engine.Run() }()
	select {
	case err := <-errCh:
		return err
	case <-ctx.Done():
	}
	sctx, cancel := context.WithTimeout(context.Background(), time.Duration(a.cfg.Server.ShutdownTimeout))
	defer cancel()
	if err := a.h.Engine.Shutdown(sctx); err != nil { return fmt.Errorf("shutdown http: %w", err) }
	if a.db != nil { _ = a.db.Close() }
	return nil
}

func buildApp(cfg *config.Config) (*App, error) {
	db, err := sql.Open("mysql", cfg.DB.DSN)
	if err != nil { return nil, fmt.Errorf("open mysql: %w", err) }
	db.SetMaxOpenConns(cfg.DB.MaxOpenConns)
	db.SetConnMaxLifetime(time.Duration(cfg.DB.ConnLifetime))
	svc := service.NewUserService(repository.NewMySQLUserRepository(db))
	h := server.Default(server.WithHostPorts(cfg.Server.Addr))
	h.GET("/users/:id", handler.NewUserHandler(svc).Get)
	return NewApp(cfg, h, db), nil
}

func main() {
	ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
	defer stop()
	cfg, err := config.Load("configs/config.yaml")
	if err != nil { log.Fatalf("load config: %v", err) }
	app, err := buildApp(cfg)
	if err != nil { log.Fatalf("build app: %v", err) }
	if err := app.Run(ctx); err != nil { log.Fatalf("run: %v", err) }
}
```

## 常见坑

1. **把 `*sql.DB` 放全局变量**：测试之间共享连接、无法关闭，换实现要改全包。
2. **yaml 直接写 `5s` 到 `time.Duration`**：会解析失败；必须用自定义 `Duration` 或改用整数秒。
3. **在 `init()` 里连接 DB**：任何 import 都产生副作用，单测和 CLI 工具被拖累。
4. **Shutdown 超时大于 K8s 的 `terminationGracePeriodSeconds`**：进程被 SIGKILL，连接与日志来不及收尾。
5. **环境变量覆盖只写在文档没实现**：K8s 注入了配置却完全不生效。

## 小结

- 依赖通过构造函数显式传入，组合根只有 `main`，测试才好替换
- 小项目手写装配即可；依赖膨胀后再考虑 wire（编译期）或 fx（生命周期）
- 配置按 server/db/redis/log 分层，YAML + 环境变量覆盖；App 负责初始化、启动、优雅退出与资源回收
