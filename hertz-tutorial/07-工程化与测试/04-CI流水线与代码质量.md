# CI流水线与代码质量
> 一句话定位：把格式、静态检查、测试、构建和发版固化成流水线，让“能合并”等价于“质量达标”。

## 本篇目标

- 设计 lint → test → build → release 的流水线阶段
- 配好 gofmt / go vet / staticcheck / golangci-lint，并统一本地与 CI
- 写出可直接使用的 GitHub Actions / GitLab CI，建立版本、PR 清单与 pre-commit 规范

## 前置知识

- 已读 [07-工程化与测试/03-单元测试与集成测试](03-单元测试与集成测试.md)
- 会使用 Git、GitHub Actions 或 GitLab CI 的基础语法与 `go test`

## 一、流水线阶段设计

```text
fmt → vet/staticcheck/lint → test(-race, coverage) → build → release
```

- lint 与 test 并行跑，build 依赖两者都成功；失败不产出构建物
- 发布只允许来自受保护分支的 tag；缓存依赖与构建缓存，但不缓存测试结果
- 所有工具版本固定，避免“昨天能过今天报错”的漂移

## 二、本地质量基线

先写 Makefile，CI 与本地调用同一套命令：

```makefile
GO      ?= go
VERSION ?= $(shell git describe --tags --always --dirty)
LDFLAGS := -s -w -X hertz_demo/internal/version.Version=$(VERSION)

.PHONY: fmt vet lint test build
fmt:
	gofmt -w .
vet:
	$(GO) vet ./...
lint:
	golangci-lint run ./...
test:
	$(GO) test -race -shuffle=on -covermode=atomic -coverprofile=coverage.out ./...
build:
	@mkdir -p bin && CGO_ENABLED=0 $(GO) build -trimpath -ldflags "$(LDFLAGS)" -o bin/userapi ./cmd/userapi
```

检查格式时只列不改，CI 里严禁 `gofmt -w`：

```bash
test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }
```

```powershell
$files = gofmt -l .
if ($files) { $files; exit 1 }
```

静态检查工具（PowerShell 命令相同）：

```bash
go install honnef.co/go/tools/cmd/staticcheck@latest
staticcheck ./...
go vet ./...
```

## 三、golangci-lint 配置

项目根目录放 `.golangci.yml`（v2 语法；v1.x 需去掉 `version` 并改用 `linters.disable-all: true`）：

```yaml
version: "2"
run:
  timeout: 5m
linters:
  default: standard
  enable:
    - bodyclose
    - errorlint
    - gocritic
    - misspell
    - revive
  exclusions:
    rules:
      - path: _test\.go
        linters: [errcheck]
formatters:
  enable:
    - gofmt
    - goimports
```

只对新增代码报错可以避免历史债务阻塞 PR：`golangci-lint run --new-from-rev=origin/main ./...`。

## 四、GitHub Actions

```yaml
name: ci
on:
  push: {branches: [main]}
  pull_request:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: {go-version-file: go.mod, cache: true}
      - run: go vet ./...
      - run: go install honnef.co/go/tools/cmd/staticcheck@latest && staticcheck ./...
      - uses: golangci/golangci-lint-action@v7
        with: {version: v2.5}
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: {go-version-file: go.mod, cache: true}
      - run: go test -race -shuffle=on -covermode=atomic -coverprofile=coverage.out ./...
      - uses: actions/upload-artifact@v4
        with: {name: coverage, path: coverage.out}
      - uses: codecov/codecov-action@v5
        with: {files: coverage.out, fail_ci_if_error: true}
  build:
    needs: [lint, test]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: {go-version-file: go.mod, cache: true}
      - run: CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -X hertz_demo/internal/version.Version=${GITHUB_REF_NAME}" -o bin/userapi ./cmd/userapi
      - uses: actions/upload-artifact@v4
        with: {name: userapi, path: bin/userapi}
```

## 五、GitLab CI

```yaml
stages: [lint, test, build]
default:
  image: golang:1.25
  cache:
    key: "$CI_COMMIT_REF_SLUG"
    paths: [.cache/go/, .cache/go-build/]
variables:
  GOPATH: "$CI_PROJECT_DIR/.cache/go"
  GOCACHE: "$CI_PROJECT_DIR/.cache/go-build"
lint:
  stage: lint
  script:
    - go vet ./...
    - go install honnef.co/go/tools/cmd/staticcheck@latest
    - staticcheck ./...
test:
  stage: test
  script:
    - go test -race -shuffle=on -covermode=atomic -coverprofile=coverage.out ./...
    - go tool cover -func=coverage.out
  coverage: '/total:\s+\(statements\)\s+(\d+\.\d+)%/'
build:
  stage: build
  script:
    - CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o bin/userapi ./cmd/userapi
  artifacts:
    paths: [bin/userapi]
```

集成测试需要 Docker 时，GitLab job 加 `services: [docker:27-dind]` 并设置 `DOCKER_HOST`；GitHub Actions 的 ubuntu runner 自带 Docker。

## 六、语义化版本与 CHANGELOG

- 版本规则：`feat` → minor，`fix/perf` → patch，`BREAKING CHANGE` → major
- 提交信息用约定式：`feat(user): add batch query`
- 打 tag 并生成变更日志：

```bash
git tag -a v1.4.0 -m "release v1.4.0"
git push origin v1.4.0
git-chglog -o CHANGELOG.md
```

PowerShell 命令相同。

构建时把 tag 注入二进制（见 [08-部署与运维/01-编译与交叉编译](../08-部署与运维/01-编译与交叉编译.md)），保证 `/version` 与 tag 一致。

## 七、PR 清单与 pre-commit

PR 描述里直接放清单（GitHub 可渲染为复选框）：

```markdown
- [ ] 通过 `make fmt vet lint test`
- [ ] 新增/修改逻辑有对应单测，覆盖率不低于门槛
- [ ] 涉及接口变更已更新 IDL 与文档
- [ ] 无明文密钥、无调试日志、无 TODO
- [ ] 已验证回滚方案（配置/镜像 tag）
```

pre-commit 钩子只做快检查，避免开发者用 `--no-verify` 绕过：

```bash
#!/usr/bin/env bash
set -euo pipefail
files=$(git diff --cached --name-only --diff-filter=ACM -- '*.go')
[ -z "$files" ] && exit 0
if [ -n "$(gofmt -l $files)" ]; then gofmt -l $files; exit 1; fi
go vet ./...
golangci-lint run --new-from-rev=HEAD ./...
```

```bash
chmod +x .githooks/pre-commit
git config core.hooksPath .githooks
```

```powershell
git config core.hooksPath .githooks
```

## 常见坑

1. **CI 里执行 `gofmt -w`**：工作区被改但检查仍通过，格式问题永远进主干。
2. **缓存 key 不含 `go.sum`**：依赖升级后仍用旧缓存，出现“本地能跑 CI 不能跑”。
3. **工具版本漂移**：golangci-lint 升级新增规则，历史代码突然全红；必须锁版本。
4. **覆盖率统计未加 `-covermode=atomic`**：与 `-race` 同时用时数据不准确。
5. **只在 PR 跑 lint、不设为必需检查**：红灯也能合并；pre-commit 跑全量测试则会被 `--no-verify` 绕过。

## 小结

- 流水线固定为 lint → test → build → release，失败不产出构建物
- 本地 Makefile 与 CI 共用同一套命令，格式检查只列不改
- GitHub Actions / GitLab CI 都要固定 Go 与工具版本、缓存依赖、上传覆盖率
- 版本由 tag + 约定式提交驱动，PR 清单与 pre-commit 把问题挡在合并前

## 练习

1. 给示例仓库加 `.golangci.yml` 与 Makefile，确保 `make lint test` 本地通过。
2. 把 GitHub Actions 的 build job 改为仅在 tag 上运行，并把产物命名为 `userapi-<tag>`。
3. 写一个 pre-commit 钩子，要求新增的 `.go` 文件必须有对应 `_test.go`。
