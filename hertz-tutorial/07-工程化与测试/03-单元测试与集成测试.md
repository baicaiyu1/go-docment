# 单元测试与集成测试
> 一句话定位：用“大量毫秒级单测 + 少量真实依赖集成测试”的组合，给 Hertz 服务建立可信的回归防线。

## 本篇目标

- 掌握 Hertz `ut` 包做 handler 单测的正确姿势
- 用 gomock + testify 隔离 service 的外部依赖
- 在随机端口上跑真实 HTTP 集成测试，并用 testcontainers 起真实数据库
- 建立覆盖率门槛，在 CI 中稳定执行 `-race` 测试

## 前置知识

- 已读 [07-工程化与测试/01-项目分层与目录规范](01-项目分层与目录规范.md) 与 [02-依赖注入与配置分层](02-依赖注入与配置分层.md)
- 熟悉 `go test`、表驱动测试与 `testing.T` 的基本用法

## 一、测试金字塔与边界

```text
        E2E（少量）     真实环境、全链路、最慢
      集成测试（适量）  真实端口 + 真实 DB（testcontainers）
    单元测试（大量）    纯内存、毫秒级、可并行
```

- 单测只验证“本层逻辑”：handler 验证状态码与响应体，service 验证业务分支
- 集成测试验证装配：路由、中间件、序列化、DB 方言一起工作是否正常
- 一条用例只断言一个行为，测试名写清场景：`TestGetUser_NotFound`
- 能用 fake/mock 就别连库；连库的测试必须能一键跳过（`testing.Short()`）

## 二、handler 单测：使用 `ut` 包

`ut.PerformRequest` 直接把请求喂给 `h.Engine`，不占端口、速度接近纯函数调用：

```go
package handler_test

import (
	"context"
	"net/http"
	"strings"
	"testing"

	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/test/assert"
	"github.com/cloudwego/hertz/pkg/common/ut"

	"hertz_demo/internal/handler"
	"hertz_demo/internal/model"
	"hertz_demo/internal/service"
)

type stubSvc struct{}

func (stubSvc) Get(ctx context.Context, id int64) (*model.User, error) {
	if id == 1 { return &model.User{ID: 1, Name: "alice"}, nil }
	return nil, service.ErrUserNotFound
}

func TestUserHandler_Get(t *testing.T) {
	h := server.Default()
	h.GET("/users/:id", handler.NewUserHandler(stubSvc{}).Get)
	w := ut.PerformRequest(h.Engine, http.MethodGet, "/users/1", nil)
	assert.DeepEqual(t, http.StatusOK, w.Code)
	if !strings.Contains(w.Body.String(), `"alice"`) {
		t.Fatalf("unexpected body: %s", w.Body.String())
	}
}
```

需要带 body 时用 `ut.Body{Body: strings.NewReader(...), Len: n}`；`w.Code` 默认就是 200，断言状态码不会踩空。

## 三、service 层 mock：gomock + testify

在 service 测试里替换 repository，验证“找不到”“参数非法”等分支：

```go
//go:generate mockgen -source=../repository/user.go -destination=../mocks/user_mock.go -package=mocks

package service_test

import (
	"context"
	"testing"

	"github.com/stretchr/testify/require"
	"go.uber.org/mock/gomock"

	"hertz_demo/internal/mocks"
	"hertz_demo/internal/model"
	"hertz_demo/internal/service"
)

func TestUserService_Get(t *testing.T) {
	ctrl := gomock.NewController(t) // 测试结束自动清理
	repo := mocks.NewMockUserRepository(ctrl)
	repo.EXPECT().FindByID(gomock.Any(), int64(1)).
		Return(&model.User{ID: 1, Name: "alice"}, nil).Times(1)
	got, err := service.NewUserService(repo).Get(context.Background(), 1)
	require.NoError(t, err)
	require.Equal(t, "alice", got.Name)
}
```

生成 mock（PowerShell 与 bash 命令相同）：

```bash
go install go.uber.org/mock/mockgen@latest
mockgen -source=internal/repository/user.go -destination=internal/mocks/user_mock.go -package=mocks
```

不要给每个方法都写 mock；只 mock 跨进程/跨存储边界。断言用 `require`（失败即停），`assert` 适合收集多个非致命断言。

## 四、集成测试：真实端口

用 `net.Listen("tcp", "127.0.0.1:0")` 拿随机端口，避免 CI 端口冲突；再用 `server.WithListener` 注入：

```go
package integration_test

import (
	"context"
	"net"
	"net/http"
	"testing"
	"time"

	"github.com/cloudwego/hertz/pkg/app/server"
)

func TestUserAPI(t *testing.T) {
	if testing.Short() { t.Skip("skip integration test in -short mode") }
	ln, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil { t.Fatal(err) }
	h := server.Default(server.WithListener(ln))
	registerRoutes(t, h) // 项目内真实路由注册
	go func() { _ = h.Engine.Run() }()
	t.Cleanup(func() {
		ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
		defer cancel()
		_ = h.Engine.Shutdown(ctx)
	})
	base := "http://" + ln.Addr().String()
	waitReady(t, base+"/healthz")
	resp, err := http.Get(base + "/users/1")
	if err != nil { t.Fatal(err) }
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK { t.Fatalf("got %d", resp.StatusCode) }
}

func waitReady(t *testing.T, url string) {
	t.Helper()
	for deadline := time.Now().Add(5 * time.Second); time.Now().Before(deadline); time.Sleep(50 * time.Millisecond) {
		resp, err := http.Get(url)
		if err == nil { resp.Body.Close(); return }
	}
	t.Fatal("server not ready")
}
```

真实端口测试要覆盖：健康检查、鉴权中间件、JSON 字段名、404/405 行为。

## 五、testcontainers：真实依赖按需启动

```go
req := testcontainers.ContainerRequest{
	Image:        "mysql:8.4",
	ExposedPorts: []string{"3306/tcp"},
	Env:          map[string]string{"MYSQL_ROOT_PASSWORD": "root", "MYSQL_DATABASE": "app"},
	WaitingFor:   wait.ForListeningPort("3306/tcp").WithStartupTimeout(60 * time.Second),
}
ctr, err := testcontainers.GenericContainer(ctx, testcontainers.GenericContainerRequest{
	ContainerRequest: req, Started: true,
})
```

取端口拼 DSN：`host, _ := ctr.Host(ctx)`、`port, _ := ctr.MappedPort(ctx, "3306/tcp")`。CI 需要 Docker；本地无 Docker 时用 `testing.Short()` 跳过。也可以用 `testcontainers-go/modules/mysql` 少写样板代码。

## 六、覆盖率门槛与 CI

```bash
go test ./... -race -shuffle=on -covermode=atomic -coverprofile=coverage.out
go tool cover -func=coverage.out | tail -1
```

```powershell
go test ./... -race -shuffle=on -covermode=atomic -coverprofile=coverage.out
go tool cover -func=coverage.out | Select-Object -Last 1
```

覆盖率低于门槛就让流水线失败（按核心包统计，而不是全仓一个数字）：

```bash
total=$(go tool cover -func=coverage.out | tail -1 | awk '{print $3}' | tr -d '%')
if awk "BEGIN {exit !($total < 70)}"; then echo "coverage $total < 70"; exit 1; fi
```

```powershell
$line = go tool cover -func=coverage.out | Select-Object -Last 1
$total = [double]($line -replace '.*\s(\d+\.\d+)%.*', '$1')
if ($total -lt 70) { Write-Error "coverage $total < 70"; exit 1 }
```

CI 里统一用 Linux runner 跑 `-race`（Windows 需要 CGO 工具链），并用 `-shuffle=on` 暴露测试间依赖。

## 七、并发测试与 `-race`

- 表驱动用例内使用 `t.Run` + `t.Parallel()`，共享只读 fixture；不要共享可变全局
- 时间、随机数、UUID 通过接口注入，测试中固定，避免偶发失败
- 断言前先 `t.Cleanup` 关闭 server、容器、临时文件
- `-race` 会显著变慢，但每个 PR 必须跑；本地提交前至少跑一次改动的包

## 常见坑

1. **只测 happy path**：分支、错误码、空结果没覆盖，线上第一个异常就翻车。
2. **测试共享全局变量**：`-shuffle` 或并行时随机失败，且无法稳定复现。
3. **集成测试写死端口**：本地能过、CI 冲突；必须用 `:0` 随机端口。
4. **mock 了不存在的交互**：`EXPECT` 与实际调用不一致，测试通过但线上逻辑没执行。
5. **忘记 `-race`**：数据竞争在压测时才暴露，修复成本高几十倍。

## 小结

- 大量纯内存单测保证逻辑正确，少量真实端口/容器测试保证装配正确
- `ut.PerformRequest` 是 Hertz handler 测试的首选，不占端口、可断言状态码与 body
- service 用 gomock 隔离 repository，只 mock 边界，不 mock 内部实现
- 覆盖率设门槛、CI 固定跑 `-race -shuffle`，让回归问题在合并前暴露
