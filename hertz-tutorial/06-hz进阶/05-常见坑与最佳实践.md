# 常见坑与最佳实践
> 一句话定位：把 hz 使用中最容易反复踩的坑集中复盘，并给出一套团队可直接执行的协作规范。
## 本篇目标
- 复盘 7 类高频事故：覆盖、漂移、路由冲突、Windows、依赖、版本、协作
- 每个坑给出“现象 → 根因 → 修复 → 预防”
- 建立“IDL 单一事实来源”的工作流
- 拿到一份可落地的 Code Review 清单
- 用最小成本在 CI 里拦住常见错误
## 前置知识
- 已读完 [06-hz进阶](01-hz命令全景.md) 前四篇
- 有至少一次 `hz new` + `hz update` 的实操经历
- 了解 Git 基本操作
## 一、生成代码被手改覆盖
**现象**：某次 `hz update` 后，自己写的逻辑消失，编译通过但接口返回空数据。

**根因**：改了生成物：

- `biz/model/**`
- `biz/router/{ns}/{idl}.go`
- `router_gen.go`
- `.hz`

**修复**：

```bash
git diff --stat
git checkout -- biz/model biz/router router_gen.go
# 重新把逻辑写回 handler 或 pkg/
```
**预防**：

| 文件 | 策略 |
| --- | --- |
| `biz/model/**` | 只读，扩展方法放 `pkg/` 或用别名包装 |
| `biz/router/{ns}/{idl}.go` | 只读，路由中间件写 `middleware.go` |
| `router_gen.go` | 只读 |
| `biz/handler/**` | 可写，update 只追加新函数 |

团队可以在 `.gitattributes` 或 CI 中加检查，但最有效的是在目录放 `README` 说明“生成目录勿改”。
## 二、IDL 与代码不同步
**现象**：

- 代码里有接口，IDL 里没有，下一次生成后接口 404
- 两个人各自 update，生成结果不同，diff 巨大

**根因**：把生成代码当成事实来源，或 IDL 改动未提交。

**修复**：

1. 以 IDL 为准，把缺失的接口补回 IDL
2. 重新 `hz update`
3. 对比 diff，确认只多不少

**预防**：

- IDL 与生成代码必须同一个 PR 提交
- CI 增加“重新生成后 git diff 为空”的检查（见第六节）
- 禁止直接改 handler 的 `@router` 注释来新增路由
## 三、路由冲突
**现象**：启动直接 panic，日志类似 `conflict route` / `panic: path already registered`。

**常见原因**：

| 原因 | 例子 |
| --- | --- |
| 两个 rpc 用了同一路径 | `/user/:id` 被 GET 与 PUT 各注册一次（同方法同路径） |
| 路径参数名不同 | `/user/:id` 与 `/user/:uid` 同时存在 |
| 静态段与参数段冲突 | `/user/list` 与 `/user/:id` 在某些实现下顺序敏感 |
| 多个 IDL 生成到同一 router 文件 | 复制 IDL 时忘了改路径 |
| 手写路由与生成路由重复 | `hz new` 后又在 main.go 里注册同名路由 |

**修复**：

```bash
# 全局搜索重复路径
```

在 `biz/router` 与 `main.go` 中搜索冲突路径，统一命名。参数名一旦对外发布就不要改。
**预防**：

- 路由规范：`/{version}/{resource}/:id`
- 同一资源的不同动作使用不同 HTTP 方法
- 新增接口前全局 grep 路径
## 四、Windows 路径、编码与 symlink
| 现象 | 根因 | 解决 |
| --- | --- | --- |
| `A required privilege is not held by the client` | 无 symlink 权限 | 开启 Windows 开发者模式，或管理员终端 |
| 中文路径下生成失败 | 工具链对非 ASCII 路径支持差 | 项目放 `D:\code\...` |
| IDL 报语法错误但文件看着正常 | UTF-8 BOM / GBK 编码 | 用 UTF-8 无 BOM 保存 |
| import 路径解析失败 | 用了反斜杠 | IDL 内统一正斜杠 |
| 生成文件每行都变 | CRLF/LF 混用 | `.gitattributes` 统一 `* text=auto eol=lf` |
| `protoc not found` | PATH 未配置或终端未重启 | 加入 PATH 后重开终端 |
| 命令行参数带引号解析异常 | PowerShell 转义规则 | 用单引号或改用 bash/WSL |

`.gitattributes` 示例：

```gitattributes
* text=auto eol=lf
*.bat text eol=crlf
*.ps1 text eol=crlf
```
## 五、`go mod tidy` 失败
**现象**：

- `missing go.sum entry`
- `410 Gone` / `connection reset`（拉不到依赖）
- `ambiguous import`
- `module github.com/apache/thrift@v0.13.0 ...`

**常见根因与处理**：

| 根因 | 处理 |
| --- | --- |
| 国内网络访问 proxy.golang.org 失败 | 配置 `GOPROXY=https://goproxy.cn,direct` |
| `GOFLAGS=-mod=vendor` 与生成物不一致 | 先删 vendor 再 tidy，或补齐 vendor |
| Thrift 版本冲突 | 按官方文档 `go mod edit -replace` |
| 私有仓库无权限 | 配置 `GOPRIVATE`、`GONOSUMDB`、SSH |
| 依赖路径大小写不一致 | Go 模块路径大小写敏感，统一小写 |

```bash
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOSUMDB=sum.golang.google.cn
go mod tidy -v
```
```powershell
go env -w GOPROXY=https://goproxy.cn,direct
go mod tidy -v
```
## 六、hz 与 Hertz 版本不匹配
**现象**：

- 生成代码引用不存在的 API（编译失败）
- 运行时行为与文档不一致
- 升级 hz 后生成的 router 结构变化

**根因**：hz 与 hertz、thriftgo/protoc 插件版本错位。

**处理**：

```bash
hz -v
go list -m github.com/cloudwego/hertz
go list -m all | grep -E "hertz|thriftgo"
```

```powershell
hz -v
go list -m github.com/cloudwego/hertz
go list -m all | Select-String -Pattern "hertz|thriftgo"
```
策略：

1. 项目 `go.mod` 固定 hertz 版本
2. 团队统一 hz 版本（写进 `tools.go` 或文档）
3. 升级时一起升级并跑全量测试
4. CI 里打印 `hz -v` 与 hertz 版本，便于排查
## 七、团队协作规范
### 7.1 IDL 是单一事实来源
```text
IDL 变更 → review → 生成代码 → 业务实现 → 测试 → 合并
```
禁止：

- 先改代码再补 IDL
- 手动编辑生成目录
- 在 handler 里改 `@router` 注释
### 7.2 分支与冲突
- IDL 文件冲突优先由“接口 owner”裁决
- 生成物冲突不要手工合并，重新生成
- 大改动拆成“IDL PR + 实现 PR”，降低 review 难度
### 7.3 Code Review 清单
| 检查项 | 关注点 |
| --- | --- |
| IDL | 字段编号是否复用、是否新增 required、路径是否冲突 |
| 注解 | `api.path` 与 `:param` 是否一致、tag 是否符合前端约定 |
| 生成物 | 是否只包含预期新增、有无格式噪音 |
| handler | 是否处理了 `BindAndValidate` 错误、是否统一错误结构 |
| 兼容性 | 老客户端是否还能调用、字段下线是否有过渡 |
| 版本 | hz/hertz 是否同步、go.mod 是否意外升级 |
| 安全 | 是否打印敏感信息、是否校验权限 |
### 7.4 可提交生成代码吗
两种流派：

| 流派 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 提交生成物 | IDL + 生成代码都进 Git | 新人 clone 即可跑 | diff 噪音、易手改 |
| 不提交生成物 | CI/本地生成 | 仓库干净 | 环境要求高、IDE 索引缺失 |

建议：中小团队提交生成物，但配 CI 校验“重新生成后无 diff”。
## 八、CI 里的最小检查
```yaml
# .github/workflows/hz-check.yml（示意）
name: hz-check
on: [pull_request]
jobs:
  gen:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: "1.25"
      - run: go install github.com/cloudwego/hertz/cmd/hz@v0.9.8
      - run: hz update -idl idl/user.thrift
      - run: git diff --exit-code
      - run: go build ./...
      - run: go test ./...
```

关键点：

- 固定 hz 版本，避免 CI 与本地不一致
- `git diff --exit-code` 能同时抓住“忘了生成”和“手改了生成物”
- Windows 项目可在 CI 增加一个 windows runner 的构建任务

本地等价检查（提交前）：

```bash
hz update -idl idl/user.thrift && git diff --exit-code && go build ./...
```

```powershell
hz update -idl idl/user.thrift
if (git diff --exit-code) { go build ./... } else { Write-Error "generated code is out of date" }
```
## 常见坑
1. **用 `hz new -f` 修问题**：这是“格式化硬盘式修复”，handler 业务代码全部丢失。
2. **update 参数与 new 不一致**：多出 `my_model`、`my_handler` 目录，引用分裂。
3. **两个 IDL 定义同名 service**：生成文件互相覆盖，只有一个生效。
4. **IDL 用 Tab 缩进**：Thrift 对空白较宽容，但混用会导致部分解析器报错，统一 4 空格。
5. **生成代码进了 `.gitignore`**：新人拉代码无法编译，CI 也没生成，构建直接红。
6. **升级 Go 版本后没更新 CI**：本地能编译，CI 用旧版本报语法错误。
7. **把 `hz` 装成 `@latest` 且不锁版本**：今天和明天的生成结果不同，review 无法复现。
8. **路由靠“记得”而不是规范**：接口一多必然冲突，路径规范要写进团队文档。
## 小结
- 最高频的事故是“手改生成物”和“IDL 漂移”，靠目录约定 + CI 双重防护
- 路由冲突要在设计阶段用命名规范解决，而不是事后 grep
- Windows 的坑集中在 symlink、PATH、编码、换行四件事
- 版本必须锁：hz、hertz、Go、protoc 四者要对齐
- 团队协作的核心是：IDL 单一事实来源 + 生成物可复现 + Review 有清单
## 练习
1. 故意手改 `biz/router` 下生成文件，执行 update 复现覆盖，并用 Git 恢复。
2. 在 CI 中加 `git diff --exit-code`，制造一次“忘记生成”的 PR 验证能拦住。
3. 写一份属于你团队的 hz Code Review 清单（不少于 10 条）。
4. 在 Windows 上从零配置 protoc + 开发者模式，记录完整步骤给新人。
