# 学习路线图

> 一张能照着走的地图：从「完全没写过 Go」到「能独立写企业级 Hertz 服务」，需要经过哪四个阶段、每个阶段学什么、怎么判断自己真的学会了。

## 本篇目标

- 说清整套教程的四个阶段，以及每个阶段要解决的核心问题
- 拿到一份可以逐日执行的 21 天入门计划，知道今天该打开哪个文件
- 学会用「能复述、能改写、能创造」三层标准验证自己，而不是靠感觉
- 提前识别零基础学 Go 最常见的五种放弃原因，并知道对应解法
- 掌握本教程的使用方法：双平台命令、代码约定、章前章后如何衔接

## 前置知识

- 会安装软件、打开终端（Windows 的 PowerShell，macOS 的 Terminal）
- 电脑剩余磁盘空间 ≥ 5 GB，能正常访问互联网
- 不需要任何编程基础；有 Python / Java / JavaScript 经验会更快，但要注意 Go 的思维差异
- 一个最重要的心态：**教程里的代码必须自己敲一遍**

## 一、终点画像：学完你能做什么

学完这套教程，你应当具备以下能力，而不是「知道 Hertz 有路由」：

1. 用 `go mod` 管理依赖，看懂 `go.mod` / `go.sum`，在国内网络环境下稳定拉包
2. 读懂并写出结构体、接口、错误包装、goroutine 与 `context`，能解释每段代码为什么这么写
3. 用 `hz` 生成项目骨架，编写路由、中间件、参数绑定、统一错误响应
4. 做出一个带日志、链路追踪、配置管理、优雅退出、单元测试的可部署服务
5. 把它打成 Docker 镜像，部署到 Kubernetes，并通过压测定位瓶颈

终点不是「背 API」，而是**看到一段 Hertz 代码，你能判断它对不对、为什么这么设计**。

## 四、怎么验证「我真的学会了」

读完一篇文章不等于学会。用三层验证法：

1. **能复述**：合上教程，用自己的话解释这个概念解决什么问题。例如「为什么 Go 的接口是隐式实现」。
2. **能改写**：把示例改一个需求还能跑通。例如把示例里的 `/user` 改成 `/orders`，字段换掉，错误分支补上。
3. **能创造**：在没有示例的情况下，从零写出一个同类功能。这是唯一算「学会」的标准。

配套的检查动作：

```bash
# Linux/macOS：每完成一篇，都至少让代码跑起来
go vet ./...
go test ./...
```

```powershell
# Windows PowerShell：同上
go vet ./...
go test ./...
```

如果 `go vet` 和 `go test` 都干净，说明你至少没有留下明显错误，这比「看起来懂了」可靠得多。

## 五、常见放弃原因与对策

| 放弃原因 | 典型表现 | 对策 |
| --- | --- | --- |
| 环境装不上 | GOPROXY、PATH、权限报错后卡两天 | 严格按 [02](02-Go-安装与环境配置.md)、[03](03-Go-Module与国内代理.md) 的排查清单走，先把 `go version` 跑通再学语法 |
| 只看不敲 | 视频/文档刷得很快，一写就空白 | 每篇的「练习」必须动手；不许复制粘贴，手敲能暴露理解漏洞 |
| 语法焦虑 | 想把 Go 语言学成专家再学框架 | Go 语法很小，本部分学完足够；剩下的边用边补 |
| 被并发吓退 | 看到 goroutine、channel 就跳过 | 先掌握 `context` 超时取消这一种模式，足够覆盖 80% Web 场景 |
| 缺少正反馈 | 学了两周还是命令行黑框 | D17 用 net/http 写出第一个 HTTP 接口，D21 跑通 Hertz，都是可见的里程碑 |

## 六、本教程怎么用

**目录即学习顺序。** 文件名前的编号就是推荐顺序，不要跳读 `01-Go语言基础`。

**双平台命令。** 涉及命令的地方都会同时给 PowerShell 与 bash：

```powershell
# Windows PowerShell
New-Item -ItemType Directory -Force -Path "$HOME\hertz-lab" | Out-Null
Set-Location "$HOME\hertz-lab"
```

```bash
# Linux / macOS
mkdir -p ~/hertz-lab
cd ~/hertz-lab
```

**代码约定。** 所有 Go 示例都用 Go 1.25 语法，模块名统一为 `hertz-lab`。你可以每篇新建一个目录，也可以用一个仓库按子目录组织，后者更推荐，因为 [08-包管理与项目结构](../01-Go语言基础/08-包管理与项目结构.md) 会用到多包结构。

**章节衔接。** 每篇末尾的「小结」会说明下一篇要解决什么；如果读下一篇时卡住，回到上一篇的小结与练习复习，通常能补上缺口。

**官方文档。** 每篇最后给出官方链接。教程负责「讲明白」，官方文档负责「查准确」，两者配合使用。

## 常见坑

1. **一上来就装 Hertz 或 hz**：没有 Go 环境和模块基础，`go install` 一定失败，且报错信息你读不懂。先把 `go version` 跑通。
2. **把教程当小说读**：Go 的很多行为（切片共享底层数组、defer 执行时机）只有亲手踩过才记得住。
3. **只看中文资料**：遇到报错时，用报错原文去搜（英文关键词），命中率远高于翻译后的描述。
4. **每天换一个学习资源**：不同教程的目录和示例不一致，来回切换会导致知识碎片化。选定这套，按顺序走完。
5. **追求「学完再练」**：正确顺序是「学一点、练一点、立刻用」，练习不是考试，是学习手段。
