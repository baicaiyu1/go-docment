## 一、Go 的安装到底装了什么

Go 的安装本质是把三样东西放到一个目录：

1. **工具链**：`go`、`gofmt`、`go vet`、链接器等可执行文件
2. **标准库源码**：`net/http`、`context`、`fmt` 的源码，供编译与跳转阅读
3. **运行时**：goroutine 调度与 GC，会被链接进你的二进制

这个目录就是 `GOROOT`。所以 Go 安装很「干净」：删目录即卸载。理解这点后就不会混淆：**GOROOT 是 Go 自己的家，GOPATH 是你的代码与依赖的家**。

## 二、Windows 安装

**方式 A：winget（推荐）**

```powershell
winget install --id GoLang.Go -e
```

**方式 B：官网 MSI**

1. 打开 <https://go.dev/dl/>，下载 `go1.25.x.windows-amd64.msi`
2. 双击安装，默认路径 `C:\Program Files\Go`
3. 安装器会自动把 `C:\Program Files\Go\bin` 写入用户 PATH

安装后**必须新开 PowerShell 窗口**，旧窗口读不到新 PATH：

```powershell
go version
```

应输出 `go version go1.25.x windows/amd64`。

## 三、macOS 与 Linux 安装

macOS 推荐 Homebrew：

```bash
brew install go
go version
```

Linux 用官方压缩包，不要用 `apt install golang`（版本过旧，与 Hertz 要求不匹配）：

```bash
wget https://go.dev/dl/go1.25.0.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go1.25.0.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.profile
source ~/.profile
go version
```

Apple Silicon 上确认输出为 `darwin/arm64`，而不是 `darwin/amd64`（Rosetta 下性能有损失）。

## 四、验证安装：三个必看命令

```powershell
go version
go env GOROOT GOPATH GOBIN
go env GOOS GOARCH
```

```bash
go version
go env GOROOT GOPATH GOBIN
go env GOOS GOARCH
```

预期：

- `GOROOT`：Go 安装目录，如 `C:\Program Files\Go`
- `GOPATH`：工作区目录，默认 `C:\Users\<用户名>\go` 或 `~/go`
- `GOBIN`：默认为空，表示二进制装到 `GOPATH/bin`
- `GOOS/GOARCH`：当前系统与架构，如 `windows` / `amd64`

## 五、GOROOT / GOPATH / GOBIN

| 变量 | 含义 | 是否手动设 | 典型值 |
| --- | --- | --- | --- |
| `GOROOT` | Go 安装目录 | 不需要 | `C:\Program Files\Go` |
| `GOPATH` | 工作区：模块缓存、编译产物、安装的二进制 | 建议显式设置 | `D:\golang` |
| `GOBIN` | `go install` 的落点，默认 `GOPATH/bin` | 可选 | `D:\golang\bin` |

`GOPATH` 内部结构：

```text
D:\golang
├── bin      # go install 生成的可执行文件
└── pkg
    └── mod  # 模块缓存 GOMODCACHE
```

**为什么建议显式设置？** 默认 `GOPATH` 在用户目录下，Windows 中文用户名路径可能让部分周边工具（旧版 Delve、cgo 场景）异常。放到纯英文目录可避开大量玄学问题：

```powershell
go env -w GOPATH=D:\golang
```

```bash
go env -w GOPATH=$HOME/golang
```

改完记得把 `GOPATH/bin` 加入 PATH，否则 `go install` 装的工具找不到。

## 六、go env 与 PATH

用 `go env -w` 修改会写入 Go 的配置文件，**优先级高于系统环境变量**，且不污染全局：

```powershell
go env -w GOPATH=D:\golang
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOSUMDB=sum.golang.google.cn
```

```bash
go env -w GOPATH=$HOME/golang
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOSUMDB=sum.golang.google.cn
```

取消用 `go env -u KEY`。Windows 追加 PATH：

```powershell
$old = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$old;D:\golang\bin", "User")
# 关闭并重开 PowerShell 后生效
where.exe go
```

Linux / macOS：

```bash
echo 'export PATH=$PATH:$(go env GOPATH)/bin' >> ~/.zshrc
source ~/.zshrc
which go
```

判断 PATH 是否生效：`where go` / `which go` 有输出、路径正确、**新开的终端**里能直接执行。

## 七、Windows 中文用户名路径排查

典型症状：`go build` 报路径含 `???`、Delve 启动失败、`go install` 后命令找不到、终端中文乱码。按顺序排查：

1. **确认 GOPATH 是否含中文**

```powershell
go env GOPATH
# 若含中文，改到英文目录
go env -w GOPATH=D:\golang
```

2. **确认终端编码为 UTF-8**

```powershell
chcp
# 65001 即 UTF-8；不是则临时切换
chcp 65001
```

3. **确认临时目录也是英文**（部分工具用 `%TEMP%` 生成中间文件）

```powershell
New-Item -ItemType Directory -Force -Path "D:\tmp" | Out-Null
$env:TMP = "D:\tmp"
$env:TEMP = "D:\tmp"
```

4. **升级 Go 与 VS Code Go 插件**：Go 1.20 之后对非 ASCII 路径支持已明显改善，很多老问题源于旧版本。

> 经验法则：能避开中文路径就避开，GOPATH、项目、临时目录都放 `D:\` 下的英文目录。

## 八、VS Code Go 插件

1. 安装 VS Code，扩展面板搜索 `Go`，安装官方插件（Go Team at Google）
2. 打开任意 `.go` 文件，点提示中的 `Install All`；或命令面板执行 `Go: Install/Update Tools`
3. 核心工具：`gopls`（语言服务器）、`dlv`（调试器）、`staticcheck`（静态检查）

推荐设置：

```json
{
  "go.useLanguageServer": true,
  "go.formatTool": "gofmt",
  "go.lintTool": "staticcheck",
  "[go]": {
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": { "source.organizeImports": "explicit" }
  }
}
```

保存时自动格式化并整理 import，能消灭大量低级错误。

## 常见坑

1. **装完不重开终端**：PATH 在进程启动时读取，旧窗口永远看不到新路径。
2. **混用系统环境变量与 `go env -w`**：值不同时 `go env -w` 优先，统一用它避免困惑。
3. **把业务代码放进 `GOROOT`**：升级 Go 时会被覆盖或删除。
4. **手动设置 `GOROOT`**：安装器已设好，改错会让 `go` 找不到标准库。
5. **中文用户名下坚持用默认 GOPATH**：能跑，但出问题时极难定位。
