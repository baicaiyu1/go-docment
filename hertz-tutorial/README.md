## 二、学习路线（五个阶段）

```
阶段一 打地基      Go 环境 → Go 语法 → 标准库 net/http → 第一个 Hertz 服务
阶段二 会使用      路由 / Context / 绑定校验 / 响应 / 中间件 / 错误处理 / 测试
阶段三 能上生产    TLS / 客户端 / 重试 / 可观测性 / 限流 / hz 进阶
阶段四 数据与中间件 MySQL+ORM / Redis 缓存 / 消息队列（企业服务的地基）
阶段五 微服务落地  Kitex RPC + Nacos 注册配置 + 分布式事务 + 完整电商项目
```

## 三、贯穿项目：mall-lite

所有数据层、缓存、消息、微服务章节都围绕同一个项目展开，避免知识点各自为战：

```
客户端 ──HTTP──▶ Hertz 网关/BFF（JWT 鉴权、限流、聚合、SSE）
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
 user-service   product-service  order-service      ← Kitex RPC 服务
 (Kitex)         (Kitex)          (Kitex)
      │              │              │
      └──────┬───────┴──────┬───────┘
             ▼              ▼
          MySQL 8        Redis 7        Kafka 3.x
        (GORM/ent)    (缓存/锁/排行)   (订单事件/库存异步扣减)
             │
             ▼
     Nacos（注册中心 + 配置中心）
     Prometheus + Grafana + OpenTelemetry（可观测）
     Docker + Kubernetes（部署）
```

**下单主链路**：Hertz 网关 → order-service → product-service（预扣库存）→ MySQL 本地事务 → 投递订单事件到 Kafka → 异步扣减/通知 → 最终一致。

**查询主链路**：Hertz 网关 → Redis 缓存命中直接返回 → 未命中回源 MySQL 并回填缓存。

## 七、学习建议

1. **每篇文章都动手敲一遍**，不要只看。Hertz 的很多行为需要跑起来才能理解。
2. **先跑通再深入**：遇到不会的 API，先看示例跑通，再回头读原理。
3. **每章末尾有练习**，做完再进入下一章。
4. 企业级部分不要跳过工程化与测试章节，这是写出可维护服务的关键。
