# 快速开始：第一个 Hertz 服务

> 一句话定位：不依赖任何代码生成工具，从空目录手写一个最小可运行的 Hertz 服务，并用 curl 完成第一次接口验证。

## 本篇目标

- 从全新目录开始，完成 `go mod init`、依赖拉取、编写 `main.go`、运行、验证的完整闭环。
- 理解 `server.Default()`、`h.GET`、`app.RequestContext`、`c.JSON`、`h.Spin()` 的最小组合。
- 掌握 Windows PowerShell 与 Linux bash 在命令、curl、路径上的差异。
- 学会排查端口占用、依赖下载失败、404 等入门高频问题。

## 前置知识

- 已完成 Go 安装，`go version` 能输出版本。
- 知道 Go Module 的基本命令。
- 读过 `01-Go语言基础/09-标准库net-http入门`，对 HTTP 请求响应有直观认识。

## 准备目录与模块

建议不要在已有 `.hz` 项目里做本节实验，新建一个独立目录。

Windows PowerShell：

```powershell
cd C:\Users\你的用户名\Desktop\code
mkdir hertz-quickstart
cd hertz-quickstart
go mod init hertz-quickstart
go get github.com/cloudwego/hertz@v0.10.6
```

Linux / macOS bash：

```bash
cd ~/code
mkdir -p hertz-quickstart
cd hertz-quickstart
go mod init hertz-quickstart
go get github.com/cloudwego/hertz@v0.10.6
```

此时目录里只有一个 `go.mod`（可能还有 `go.sum`）。模块名 `hertz-quickstart` 只是示例，实际项目建议用可发布的路径，例如 `github.com/yourname/hertz-quickstart`。

## 编写 main.go

在项目根目录新建 `main.go`，内容如下，这是一份可以直接运行的完整代码：

```go
package main

import (
	"context"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

func main() {
	// Default 会注册 Recovery 中间件；WithHostPorts 指定监听地址与端口
	h := server.Default(server.WithHostPorts("127.0.0.1:8080"))

	// 最经典的 ping-pong
	h.GET("/ping", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{"message": "pong"})
	})

	// 带路径参数的示例，提前感受 Param 的用法
	h.GET("/hello/:name", func(ctx context.Context, c *app.RequestContext) {
		name := c.Param("name")
		c.String(consts.StatusOK, "hello, %s", name)
	})

	// Spin 阻塞运行，并在收到退出信号时优雅退出
	h.Spin()
}
```

几个要点：

- 第一个参数 `ctx context.Context` 是请求级上下文，用于超时、取消、跨中间件传值。
- 第二个参数 `c *app.RequestContext` 是 Hertz 的请求上下文，封装了请求、响应、参数、错误链。
- `utils.H` 是 `map[string]interface{}` 的简写，等价于 `map[string]interface{}{"message": "pong"}`。
- `consts.StatusOK` 就是 `200`，用常量比魔法数字更清晰。

## 验证接口

Windows PowerShell 注意：`curl` 在 PowerShell 中是 `Invoke-WebRequest` 的别名，参数行为与 Linux curl 不同，建议显式使用 `curl.exe`。

```powershell
curl.exe -i http://127.0.0.1:8080/ping
curl.exe -i http://127.0.0.1:8080/hello/hertz
curl.exe -i http://127.0.0.1:8080/not-exist
```

Linux / macOS bash：

```bash
curl -i http://127.0.0.1:8080/ping
curl -i http://127.0.0.1:8080/hello/hertz
curl -i http://127.0.0.1:8080/not-exist
```

预期结果：

- `/ping` 返回 `200`，Body 为 `{"message":"pong"}`。
- `/hello/hertz` 返回 `200`，Body 为 `hello, hertz`。
- `/not-exist` 返回 `404`，Body 通常是 `404 page not found`。

## PowerShell 与 bash 的差异

| 事项 | PowerShell | bash |
| --- | --- | --- |
| curl | 用 `curl.exe`，避免别名 | 直接用 `curl` |
| 环境变量 | `$env:GOPROXY` | `$GOPROXY` |
| 设置环境变量 | `$env:GOBIN="D:\Go\bin"` | `export GOBIN=~/go/bin` |
| 路径分隔符 | 可用 `\`，也支持 `/` | 用 `/` |
| 命令串联 | `;` 或分行 | `;`、`&&`、分行 |
| 停止服务 | `Ctrl+C` | `Ctrl+C` |

如果一定要在 PowerShell 用原生 `curl` 参数，记住 `curl.exe`；如果只用 PowerShell 风格，可以用：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8080/ping -Method Get
```

## 不用 hz 的最小服务解析

本节刻意不引入 `hz`，是为了把框架的最小骨架看清楚：

1. `server.Default(...)` 创建 `*server.Hertz`，它内部包含路由引擎、配置和信号处理。
2. `h.GET(path, handler)` 把 handler 注册到路由树；Hertz 还提供 `POST`、`PUT`、`DELETE`、`Any`、`Handle` 等。
3. handler 拿到 `*app.RequestContext` 后，通过 `c.JSON`、`c.String` 等写响应。
4. `h.Spin()` 启动监听，并在收到 `SIGINT`、`SIGTERM`、`SIGHUP` 时执行优雅退出。

等价的“标准库写法”大致是 `http.HandleFunc` + `http.ListenAndServe`，但 Hertz 把路由、上下文、中间件、优雅退出都封装好了。

## 修改端口与热重启

把 `WithHostPorts("127.0.0.1:8080")` 改成 `":9000"` 即可监听所有网卡的 9000 端口。修改后必须重新 `go run .`，Go 没有内置热重载；开发期可以用 `air` 等第三方工具，但生产环境不依赖热重载。

端口被占用时：

Windows PowerShell：

```powershell
netstat -ano | findstr :8080
taskkill /PID <上一步看到的PID> /F
```

Linux / macOS bash：

```bash
lsof -i :8080
kill -9 <上一步看到的PID>
```

## 常见坑

1. **没有 `go mod init` 就 `go run .`**：会报 `go.mod file not found`，先在项目根目录初始化模块。
2. **PowerShell 里 `curl -i` 报参数错误**：PowerShell 把 `curl` 映射成了 `Invoke-WebRequest`，改用 `curl.exe`。
3. **端口被占用**：启动日志会提示 `bind: Only one usage of each socket address`，用上面的命令找出并结束占用进程。
4. **改了端口仍访问 8080**：确认保存文件并重新运行，`go run .` 不会自动重载。
5. **访问 `/hello/` 得到 404**：参数路由 `:name` 只匹配单个非空路径段，`/hello/` 不匹配，这是预期行为。
6. **在项目外运行**：`go run .` 的 `.` 是当前目录，必须在 `main.go` 所在目录执行，或使用 `go run main.go`。

## 小结

- 一个最小 Hertz 服务只需要四步：建模块、写 handler、注册路由、`Spin`。
- `server.Default()` 适合入门与大多数服务；需要完全自定义时用 `server.New()`。
- Windows 上把 `curl` 换成 `curl.exe`，能避免大量“命令行为不一致”的困惑。
- 下一节引入 hz，把“手写骨架”升级为“可维护的工程骨架”。
