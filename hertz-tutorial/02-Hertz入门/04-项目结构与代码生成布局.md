# 项目结构与代码生成布局

> 一句话定位：看懂 hz 生成目录里每个文件的职责，明确“生成代码”和“手写业务代码”的边界，是后续所有工程化工作的前提。

## 本篇目标

- 逐项理解 `main.go`、`router.go`、`router_gen.go`、`biz/router`、`biz/handler`、`biz/model`、`idl` 的职责。
- 分清哪些文件可以改、哪些文件会被 `hz update` 覆盖。
- 掌握一次请求从 `main.go` 到业务 handler 的完整调用链。
- 学会在不破坏生成代码的前提下新增手写路由。

## 前置知识

- 已用 `hz new` 生成并跑通过一个项目（见 `03-hz代码生成工具安装与使用`）。
- 了解 Go 的 `package`、`import` 与模块路径。
- 知道 Hertz 的 `HandlerFunc` 签名是 `func(context.Context, *app.RequestContext)`。

## 生成目录总览

以下是无 IDL 时 `hz new` 的典型结构，后面的注释就是本节要讲的重点：

```text
.
├── .hz                          # hz 项目标记，勿删
├── biz
│   ├── handler                  # 业务 handler
│   │   └── ping.go              # 示例 ping handler
│   └── router
│       └── register.go          # 生成路由的汇总入口，勿改
├── go.mod
├── main.go                      # 程序入口
├── router.go                    # 手写自定义路由
├── router_gen.go                # 路由注册总入口，勿改
├── build.sh                     # 编译脚本（Windows 默认不生成）
└── script
    └── bootstrap.sh             # 运行脚本（Windows 默认不生成）
```

用命令查看实际结构：

Windows PowerShell：

```powershell
tree /F
```

Linux / macOS bash：

```bash
find . -maxdepth 3 -not -path './.git/*' | sort
```

## 逐项解释

### main.go

程序入口，创建 Hertz 实例并启动：

```go
func main() {
	h := server.Default()
	register(h) // 定义在 router_gen.go
	h.Spin()
}
```

`server.Default()` 自带 Recovery；可以在这里加端口、超时等参数，但不建议大改结构。

### router_gen.go

路由注册总入口，把两类路由串起来，文件头带 `DO NOT EDIT`：

```go
func register(r *server.Hertz) {
	router.GeneratedRegister(r) // IDL 生成的路由
	customizedRegister(r)       // router.go 中的手写路由
}
```

### router.go

留给用户写非 IDL 路由，`customizedRegister` 是推荐的手写入口。不要为了省事去改 `router_gen.go`。

### biz/router/register.go

汇总所有 IDL 路由注册函数，含 `//INSERT_POINT: DO NOT DELETE THIS LINE!` 标记；`hz update` 在标记处插入新调用，手工改动会被覆盖。

### biz/router/&lt;命名空间&gt;/&lt;服务&gt;.go

由 IDL 生成，把每个 method 映射到 handler 并挂载路由组中间件，每次 `hz update` 重新生成。

### biz/router/&lt;命名空间&gt;/middleware.go

每个生成的路由组默认带一个中间件函数。你可以在函数体里加逻辑；`hz update` 会保留已有内容，并在尾部追加新的中间件模板。

### biz/handler

业务实现目录：

- `ping.go`：示例 handler，只为验证项目能跑通。
- 有 IDL 时会出现 `biz/handler/<命名空间>/<服务>.go`，每个 IDL method 对应一个函数，`hz update` 只追加新方法，不覆盖已有方法体。

典型 handler 长这样：

```go
package handler

import (
	"context"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

// Ping .
func Ping(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{
		"message": "pong",
	})
}
```

### biz/model

IDL 结构体与序列化代码。由 thriftgo / protoc 生成，`hz update` 会重新生成。**不要在这里写业务代码**，否则更新时丢失。

### idl

存放 `.thrift` 或 `.proto` 文件，位置可以自定义。它是接口定义的唯一事实来源，生成代码都从它推导。

### .hz

hz 的项目标记：

- 有它，`hz new` 会拒绝重复初始化。
- 没它，`hz update` 会拒绝执行。
- 不要删、不要改。

### build.sh 与 script/bootstrap.sh

- `build.sh`：编译脚本，产物默认输出到 `output/`。
- `script/bootstrap.sh`：运行脚本，设置环境变量并启动二进制。
- Windows 默认不生成这两个文件，直接 `go build` / `go run .` 即可。

### go.mod

模块定义与依赖。`hz new --module` 决定模块名；后续所有 import 都基于它。如果手工改模块名，必须全局替换 import 路径。

## 生成代码与手写代码的边界

| 文件 / 目录 | 谁维护 | 能否修改 | 说明 |
| --- | --- | --- | --- |
| `main.go` | hz 生成一次 | 可少量修改 | 加启动参数可以，别大改结构 |
| `router_gen.go` | hz | ❌ 不要改 | 会被覆盖 |
| `biz/router/register.go` | hz | ❌ 不要改 | `INSERT_POINT` 由工具维护 |
| `biz/router/<svc>/*.go` | hz | ❌ 不要改 | 每次 update 重新生成 |
| `biz/router/<svc>/middleware.go` | hz + 你 | ✅ 可改 | update 保留已有内容 |
| `biz/model/**` | thriftgo / protoc | ❌ 不要改 | 更新即覆盖 |
| `biz/handler/**` | 你 | ✅ 可改 | update 只追加新方法 |
| `router.go` | 你 | ✅ 可改 | 手写路由入口 |
| `idl/**` | 你 | ✅ 可改 | 接口定义 |
| `.hz` | hz | ❌ 不要动 | 项目标记 |
| `build.sh` / `script/**` | hz 生成一次 | ✅ 可改 | 按部署需要调整 |

一句话记忆：**带 `_gen`、`DO NOT EDIT`、`model` 的不要动；`handler`、`router.go`、`middleware.go` 是你的地盘。**

## 一次请求的调用链

以 `GET /ping` 为例：

```text
main.go
  └── register(h)                      // router_gen.go
        ├── router.GeneratedRegister(r) // biz/router/register.go（IDL 路由）
        └── customizedRegister(r)       // router.go（手写路由）
              └── r.GET("/ping", handler.Ping)
                    └── recovery → 自定义中间件 → handler.Ping
                          └── c.JSON(200, ...)
```

理解这条链后，遇到“接口 404”时就能按顺序排查：路由有没有注册、注册在哪个函数、函数有没有被调用。

## 新增一个手写路由

需求：新增 `GET /api/v1/health` 健康检查。

第一步，在 `biz/handler` 下新建 `health.go`：

```go
func Health(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{"status": "ok"})
}
```

第二步，在 `router.go` 的 `customizedRegister` 中注册：

```go
func customizedRegister(r *server.Hertz) {
	r.GET("/api/v1/health", handler.Health)
}
```

第三步，重新运行并验证：

```powershell
go run .
curl.exe -i http://127.0.0.1:8888/api/v1/health
```

```bash
go run .
curl -i http://127.0.0.1:8888/api/v1/health
```

不要改 `router_gen.go`，否则下次生成或团队合并时容易冲突。

## 常见坑

1. **在 `router_gen.go` 里加路由**：文件头写着 `DO NOT EDIT`，重新生成就没了。手写路由放 `router.go`。
2. **在 `biz/model` 里写业务方法**：`hz update` 会重新生成，方法丢失。业务逻辑放 `biz/handler` 或独立的 service 包。
3. **删掉 `.hz` 后执行 `hz update`**：工具会认为这不是 hz 项目。也不要把它加进 `.gitignore`。
4. **改了 `--module` 却没改 import**：所有 `hertz-tutorial/demo/...` 都要同步替换，否则编译失败。
5. **以为 `ping.go` 是框架必备**：它只是示例，可以在确认无用后删除，同时删掉 `router.go` 里的注册。
6. **Windows 找不到 `build.sh`**：这是预期行为，Windows 用 `go build` 或 `go run .`。
7. **在子目录执行 hz 命令**：`hz update` 需要在项目根目录（`.hz` 所在目录）执行。

## 小结

- hz 项目是“生成代码 + 手写代码”的混合体，边界比文件数量更重要。
- `router_gen.go`、`biz/router/register.go`、`biz/model` 归工具管；`router.go`、`biz/handler` 归你管。
- 新增接口优先改 `router.go`，有 IDL 时用 `hz update` 追加，不要手工改生成文件。
- 下一节深入 `Engine`，把 `server.Default()` 背后的启动参数逐一拆开。

## 练习

1. 画出你的项目从 `main.go` 到 `handler.Ping` 的调用链，标出每个文件的包名。
2. 新增 `GET /api/v1/version`，返回 `{"version":"v0.10.6"}`，并说明为什么放在 `router.go` 而不是 `router_gen.go`。
3. 故意修改一次 `biz/router/register.go`，再执行 `hz update`，观察改动是否被覆盖（实验前先备份）。
