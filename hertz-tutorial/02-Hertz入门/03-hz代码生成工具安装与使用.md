# hz 代码生成工具安装与使用

> 一句话定位：hz 是 Hertz 官方的代码生成命令行工具，负责从 IDL 或模板生成可运行的工程骨架，并支持后续增量更新。

## 本篇目标

- 用 `go install` 安装与 Hertz v0.10.6 配套的 hz，并正确配置 `GOBIN` / `PATH`。
- 学会排查 Windows 中文用户名导致的路径乱码、命令找不到等问题。
- 用 `hz new` 生成一个完整项目，跑通 `/ping`。
- 理解 `.hz` 标记文件的作用，以及 `hz update` 与 `hz new` 的边界。

## 前置知识

- Go 已安装，`go env GOPATH` 有输出。
- 完成 `02-快速开始-第一个服务`，知道手写 Hertz 服务的最小结构。
- 了解 Go Module 与 `$GOPATH/bin` 的含义。

## hz 是什么

hz 是 Hertz 的命令行工具，主要做两件事：

- **脚手架**：`hz new` 从零生成一个分层项目（main、router、biz、handler 等）。
- **增量生成**：`hz update` 根据 Thrift / Protobuf IDL 更新 model、router，并在 handler 文件尾部追加新方法，保留你已写的业务代码。

它本身是一个 Go 二进制文件，安装后位于 `GOBIN`（默认是 `$GOPATH/bin`）。

## 安装 hz

官方推荐用 `go install`。教程基线是 hz v0.9.8，学习阶段建议锁版本，避免 `@latest` 带来的 API 漂移。

Windows PowerShell：

```powershell
go install github.com/cloudwego/hertz/cmd/hz@v0.9.8
# 如果想跟随最新版，可改用：
# go install github.com/cloudwego/hertz/cmd/hz@latest
```

Linux / macOS bash：

```bash
go install github.com/cloudwego/hertz/cmd/hz@v0.9.8
# 如果想跟随最新版，可改用：
# go install github.com/cloudwego/hertz/cmd/hz@latest
```

安装完成后，二进制文件在：

- Windows：`%GOPATH%\bin\hz.exe`
- Linux / macOS：`$(go env GOPATH)/bin/hz`

但这个目录默认不一定在 `PATH` 中，所以经常出现“装了却找不到命令”的情况。

## 配置 GOBIN 与 PATH

### Windows

先查看路径：

```powershell
go env GOPATH GOBIN
```

如果没有设置 `GOBIN`，默认使用 `%GOPATH%\bin`。如果该路径包含中文用户名，例如 `C:\Users\宋鹏飞\go\bin`，部分旧版终端、脚本或工具链会出现乱码，典型表现是命令提示里出现 `C:\Users\?????\go\bin`，或者 `go install` 后生成到错误目录。

推荐把 `GOBIN` 设到一个纯英文、无空格的目录：

```powershell
mkdir D:\Go\bin -Force
go env -w GOBIN=D:\Go\bin
go env GOBIN
```

把 `D:\Go\bin` 加入当前用户的 `PATH`（设置后需要新开终端）：

```powershell
[Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "User") + ";D:\Go\bin",
  "User"
)
```

然后新开一个 PowerShell 窗口验证：

```powershell
Get-Command hz
where.exe hz
```

`where.exe` 应该输出 `D:\Go\bin\hz.exe`。

### Linux / macOS

```bash
# 假设 GOPATH 为 ~/go
export PATH="$PATH:$(go env GOPATH)/bin"
# 永久生效，写入 shell 配置
echo 'export PATH=$PATH:$(go env GOPATH)/bin' >> ~/.bashrc
source ~/.bashrc
which hz
```

如果使用 zsh，把 `~/.bashrc` 换成 `~/.zshrc`。

## Windows 中文用户名乱码排查

按这个顺序排查：

1. **确认 hz 到底装到了哪里**：运行 `go env GOBIN GOPATH`，再去资源管理器里看该目录是否存在 `hz.exe`。
2. **确认命令搜索路径**：`where.exe hz`。如果输出为空，说明目录不在 `PATH`。
3. **确认是否旧终端残留**：改完环境变量后，必须关闭旧 PowerShell 窗口重新打开。
4. **确认编码**：PowerShell 5 对中文路径的显示可能乱码，但文件本身可能存在。执行 `Test-Path "C:\Users\宋鹏飞\go\bin\hz.exe"` 比肉眼看提示更可靠。
5. **彻底规避**：使用上面的 `go env -w GOBIN=D:\Go\bin`，把二进制放到纯英文路径。
6. **仍失败时**：直接运行绝对路径 `& "D:\Go\bin\hz.exe" --version`，能运行说明只是 `PATH` 问题，不是安装失败。

## 验证 hz

```powershell
hz --version
hz -v
hz help
```

```bash
hz --version
hz -v
hz help
```

不同版本的 hz 对 `--version` / `-v` 的支持略有差异，两者任选其一即可；`hz help` 会列出全部子命令。看到 `hz version v0.9.8` 之类的输出就说明安装成功。

> 注意：hz 在部分平台会为自身创建软链接。Windows 上创建符号链接需要“开发者模式”或管理员权限，若安装时报权限错误，开启开发者模式后重试。

## 用 hz new 生成项目

在空目录或工作区根目录执行。`--module` 指定 Go module 名；老版本也接受单横线写法 `-module`。

Windows PowerShell：

```powershell
cd C:\Users\你的用户名\Desktop\code
mkdir hertz-hz-demo
cd hertz-hz-demo
hz new --module hertz-tutorial/demo
go mod tidy
go run .
```

Linux / macOS bash：

```bash
cd ~/code
mkdir -p hertz-hz-demo
cd hertz-hz-demo
hz new --module hertz-tutorial/demo
go mod tidy
go run .
```

`hz new` 会在当前目录生成脚手架。若想直接指定目录名，也可以先建目录再进入执行。

启动后验证：

```powershell
curl.exe -i http://127.0.0.1:8888/ping
```

```bash
curl -i http://127.0.0.1:8888/ping
```

返回 `{"message":"pong"}` 说明生成项目已跑通。hz 默认端口是 `8888`，不是手写示例里的 `8080`。

生成后的最小目录大致如下（无 IDL 的情况）：

```text
.
├── .hz
├── biz
│   ├── handler
│   │   └── ping.go
│   └── router
│       └── register.go
├── go.mod
├── main.go
├── router.go
├── router_gen.go
├── build.sh
└── script
    └── bootstrap.sh
```

Windows 下默认不生成 `build.sh` 与 `script/bootstrap.sh`，直接用 `go build` 即可。

## .hz 标记文件与 hz update

`.hz` 是 hz 用来判断“这里是不是一个 hz 项目”的标记文件：

- 目录里有 `.hz`，再执行 `hz new` 会报错，提示项目已存在。
- 目录里没有 `.hz`，执行 `hz update` 会报错，提示不是 hz 项目。
- 不要删除、不要提交空目录时漏掉它。

`hz update` 的典型用法是配合 IDL：

```bash
hz update -idl idl/user.thrift
```

它的行为是：

- 重新生成 `biz/model`、`biz/router/<svc>` 等由 IDL 决定的代码。
- 在 `biz/handler/<svc>` 中**保留已有方法**，只追加新增方法。
- 不会帮你实现业务逻辑，也不会覆盖你写的 handler 方法体。

没有 IDL 的手写项目不需要 `hz update`，直接改 `router.go` 与 `biz/handler` 即可。

## 常见坑

1. **`go install` 成功但 `hz` 命令不存在**：`GOBIN` 不在 `PATH`，或改完环境变量没重开终端。用 `where.exe hz` 确认。
2. **中文用户名导致路径乱码**：不要只改显示编码，直接把 `GOBIN` 换到 `D:\Go\bin` 这类纯英文目录。
3. **在已有项目里重复 `hz new`**：因为 `.hz` 已存在而失败；新增接口应该改 `router.go` 或用 `hz update`。
4. **`hz update` 提示不是 hz 项目**：缺少 `.hz` 文件，确认你在项目根目录执行。
5. **`@latest` 与教程不一致**：学习阶段锁 `v0.9.8`；升级前先看官方版本说明。
6. **Windows 符号链接权限错误**：开启开发者模式或以管理员身份安装，再重试。
7. **生成项目端口是 8888**：不要照着手写示例访问 8080。

## 小结

- hz 的价值是“工程骨架 + IDL 增量生成”，不是运行时的依赖。
- 安装的关键不是 `go install`，而是让 `GOBIN` 可写、在 `PATH` 中、路径不含中文。
- `hz new` 只做一次初始化，后续新增接口靠手写路由或 `hz update`。
- 下一节会逐个解释 hz 生成的目录与文件，明确哪些能改、哪些不能改。

## 练习

1. 安装 hz 后用 `hz --version` 与 `hz help` 查看版本和子命令，记录 `hz new` 的全部参数。
2. 用 `hz new --module example.com/demo` 生成项目，跑通 `/ping`，再故意执行一次 `hz new` 观察报错。
3. 把 `GOBIN` 改到一个新目录，重新安装 hz，并验证新旧终端中 `where.exe hz` 的差异。
