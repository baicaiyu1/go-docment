# 参数绑定与校验（03.1）：FastAPI + Pydantic 对照版

> 一句话定位：如果你已经会用 FastAPI 的 Pydantic 模型，那么 Hertz 的绑定校验可以理解为——把 Pydantic 的字段声明拆成 `struct + tag`，把自动 422 换成自己写的错误映射，把 `Depends` 换成中间件或闭包注入。

## 为什么单独写这一篇

你已经熟悉 FastAPI 的这套写法：

```python
class CreateUserReq(BaseModel):
    name: str = Field(min_length=2, max_length=20)
    age: int = Field(ge=0, le=130)
    email: EmailStr
```

它背后的心智模型是「类型即契约」：类型写出来，FastAPI 自动解析、自动校验、自动返回 422、自动生成文档。

Hertz 不这么做。Hertz 的契约写在 struct tag 上，而且**默认校验器根本不认 `validate` 标签**。如果直接把 FastAPI 的习惯搬过来，最常见的结局是：接口能跑，但参数从来没被校验过。

这篇不重复讲 API 列表，而是用同一批接口，在 FastAPI 和 Hertz 各写一遍，逐项对照，帮你把已有的 Pydantic 经验迁移过来。

## 本篇目标

- 建立 FastAPI/Pydantic 与 Hertz 绑定校验的一一映射。
- 能独立写出带校验、带统一错误响应的 Hertz 接口。
- 知道哪些 Pydantic 行为在 Hertz 里没有，需要自己补。
- 避开从 FastAPI 迁移过来最容易踩的坑。

## 前置知识

- 已完成 `03-参数绑定与校验`，知道 Hertz 的 `BindAndValidate` 和 tag 优先级。
- 用过 FastAPI，写过 `BaseModel`、`Field`、`Depends`。
- 了解 Go 结构体 tag 与零值概念。

## 先记住 8 个差异

| 维度 | FastAPI + Pydantic | Hertz |
| --- | --- | --- |
| 契约声明 | `BaseModel` 字段类型 | `struct` + tag |
| 校验时机 | 进入函数前自动执行 | 必须显式调用 `BindAndValidate` |
| 校验规则 | Pydantic 规则默认生效 | 默认只认 `vd`，`validate` 需注入 validator |
| 失败状态码 | 默认 422 | 自己决定，常见 400 或 422 |
| 失败响应 | `detail` 数组，结构化 | 自己拼，通常只有一个 `message` |
| 类型转换 | 默认宽松，`"18"` 可转 `18` | JSON 严格，字符串转数字直接报错 |
| 未知字段 | `extra="forbid"` 可拒绝 | `BindAndValidate` 默认忽略；纯 JSON 接口可用 `BindJSON` 严格模式 |
| 输出模型 | `response_model` 自动过滤 | 自己定义 DTO，自己防泄漏 |

记住这张表，后面的内容都是它的展开。

## 一、同一个接口，两种写法

需求：创建用户，`name` 2–20 字，`age` 0–130，`email` 合法，`role` 只能是 `admin` 或 `user`，`tags` 最多 5 个且每个非空。

### FastAPI 写法

```python
from typing import Literal

from fastapi import FastAPI
from pydantic import BaseModel, ConfigDict, EmailStr, Field

app = FastAPI()


class CreateUserReq(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    name: str = Field(min_length=2, max_length=20)
    age: int = Field(ge=0, le=130)
    email: EmailStr
    role: Literal["admin", "user"] = "user"
    tags: list[str] = Field(default_factory=list, max_length=5)


@app.post("/api/v1/users", status_code=201)
def create_user(req: CreateUserReq):
    return {"data": req.model_dump()}
```

`email-validator` 需要额外安装：

```bash
pip install email-validator
```

### Hertz 写法

先安装 validator：

```bash
go get github.com/go-playground/validator/v10
```

```go
package main

import (
	"context"
	"errors"
	"reflect"
	"strings"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
	"github.com/go-playground/validator/v10"
)

type CreateUserReq struct {
	Name  string   `json:"name" validate:"required,min=2,max=20"`
	Age   *int     `json:"age" validate:"required,gte=0,lte=130"`
	Email string   `json:"email" validate:"required,email"`
	Role  string   `json:"role" default:"user" validate:"oneof=admin user"`
	Tags  []string `json:"tags" validate:"max=5,dive,min=1"`
}

func newValidator() *validator.Validate {
	vd := validator.New(validator.WithRequiredStructEnabled())
	// 错误里的字段名用 json 名，和前端契约保持一致
	vd.RegisterTagNameFunc(func(fld reflect.StructField) string {
		name := strings.SplitN(fld.Tag.Get("json"), ",", 2)[0]
		if name == "" || name == "-" {
			return fld.Name
		}
		return name
	})
	return vd
}

func writeBindError(c *app.RequestContext, err error) {
	var ve validator.ValidationErrors
	if errors.As(err, &ve) {
		fields := make(map[string]string, len(ve))
		for _, fe := range ve {
			rule := fe.Tag()
			if param := fe.Param(); param != "" {
				rule += "=" + param
			}
			name := fe.Field()
			// 嵌套字段用 Namespace 保留层级，例如 address.city
			if ns := fe.Namespace(); strings.Contains(ns, ".") {
				name = ns[strings.Index(ns, ".")+1:]
			}
			fields[name] = rule
		}
		c.AbortWithStatusJSON(consts.StatusUnprocessableEntity, utils.H{
			"code":    422,
			"message": "参数校验失败",
			"fields":  fields,
		})
		return
	}
	c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{
		"code":    400,
		"message": "参数格式错误",
		"detail":  err.Error(),
	})
}

func main() {
	vd := newValidator()
	h := server.Default(
		server.WithHostPorts("127.0.0.1:8080"),
		server.WithCustomValidatorFunc(func(_ *protocol.Request, req any) error {
			return vd.Struct(req)
		}),
	)

	h.POST("/api/v1/users", func(ctx context.Context, c *app.RequestContext) {
		var req CreateUserReq
		if err := c.BindAndValidate(&req); err != nil {
			writeBindError(c, err)
			return
		}
		c.JSON(consts.StatusCreated, utils.H{"data": req})
	})

	h.Spin()
}
```

### 对照拆解

1. **模型声明**
   Pydantic 的字段类型和约束写在类型注解里；Hertz 写在 tag 里，字段类型只负责存储。
2. **校验入口**
   FastAPI 在进入函数前自动校验；Hertz 必须在 handler 里显式 `BindAndValidate`，漏写就完全不校验。
3. **默认值**
   Pydantic 用 `= "user"`；Hertz 用 `default:"user"`，这是独立的 tag，不写在 `json` 里。
4. **必填**
   Pydantic 不写默认值就是必填；Hertz 用 `validate:"required"` 表达必填。注意 `required` 判断的是非零值，`age=0` 会被误判，所以示例用 `*int` 表示「必须传、0 合法」。也可以用 `json:"age,required"` 做绑定层必填，但失败会走绑定错误（通常是 400），而不是校验错误（422）。
5. **失败返回**
   FastAPI 自动 422；Hertz 要自己决定状态码和 JSON 结构，示例里为了对齐 FastAPI 用了 422。
6. **字段名**
   Pydantic 的错误 `loc` 用字段名；Hertz 默认用 Go 字段名（`Name`），所以上面注册了 `RegisterTagNameFunc` 改成 json 名。

## 二、参数来源对照

| 来源 | FastAPI | Hertz |
| --- | --- | --- |
| Path | `user_id: int = Path(..., ge=1)` | `ID int64`，tag `path:"id" validate:"gt=0"`，路由 `:id` |
| Query | `page: int = Query(1, ge=1)` | `Page int`，tag `query:"page" default:"1" validate:"gte=1"` |
| Header | `x_token: str = Header(...)` | `Token string`，tag `header:"X-Token" validate:"required"` |
| Cookie | `sid: str = Cookie(...)` | `SID string`，tag `cookie:"sid" validate:"required"` |
| JSON Body | 函数参数直接收 `BaseModel` | tag `json:"name"` |
| Form | `name: str = Form(...)` | tag `form:"name"` |
| File | `file: UploadFile = File(...)` | `File *multipart.FileHeader`，tag `form:"file"` |
| 原始 Body | `await request.body()` | `raw_body` tag（少用） |
| 默认值 | `page: int = 1` | `default:"1"` |
| 别名 | `Field(alias="userName")` | tag 名本身就是别名，如 `json:"userName"` |
| 必填 | 不写默认值 / `Field(...)` | `validate:"required"` |
| 显式必填（绑定层） | 无对应写法 | `json:"name,required"` |

### 2.1 Path 参数

FastAPI：

```python
@app.get("/api/v1/users/{user_id}")
def get_user(user_id: int = Path(..., ge=1)):
    ...
```

Hertz：

```go
type GetUserReq struct {
	ID int64 `path:"id" validate:"required,gt=0"`
}

h.GET("/api/v1/users/:id", func(ctx context.Context, c *app.RequestContext) {
	var req GetUserReq
	if err := c.BindAndValidate(&req); err != nil {
		writeBindError(c, err)
		return
	}
	c.JSON(consts.StatusOK, utils.H{"id": req.ID})
})
```

要点：

- Hertz 的 path 参数名来自路由 `:id`，tag 里写 `path:"id"`。
- 类型转换在绑定阶段完成，`/users/abc` 会绑定失败，不会变成 0。
- 也可以 `c.Param("id")` 手动取字符串，但那样就没有类型校验了。

### 2.2 Query 参数

FastAPI：

```python
@app.get("/api/v1/users")
def list_users(
    page: int = Query(1, ge=1),
    size: int = Query(10, ge=1, le=100),
    q: str | None = None,
    tags: list[str] = Query(default=[]),
):
    ...
```

Hertz：

```go
type ListUsersReq struct {
	Page int      `query:"page" default:"1" validate:"gte=1"`
	Size int      `query:"size" default:"10" validate:"gte=1,lte=100"`
	Q    *string  `query:"q"`
	Tags []string `query:"tag"`
}
```

要点：

- `default` 在字段缺省时生效，显式传 `page=` 空值时不会覆盖。
- `?tag=a&tag=b` 可以直接绑定到 `[]string`。
- `Q *string` 用来区分「没传」和「传了空串」，这是 Go 里替代 `str | None` 的常用手段。
- `?size=abc` 在 FastAPI 里是 422；Hertz 的 `BindQuery` 会返回绑定错误，需要自己映射成 400/422。

### 2.3 Header 与 Cookie

FastAPI：

```python
@app.get("/api/v1/me")
def me(
    x_token: str = Header(...),
    sid: str | None = Cookie(default=None),
):
    ...
```

Hertz：

```go
type MeReq struct {
	Token string `header:"X-Token" validate:"required"`
	SID   string `cookie:"sid"`
}

h.GET("/api/v1/me", func(ctx context.Context, c *app.RequestContext) {
	var req MeReq
	if err := c.BindAndValidate(&req); err != nil {
		writeBindError(c, err)
		return
	}
	// 也可以手动取：string(c.GetHeader("X-Token"))、string(c.Cookie("sid"))
})
```

注意 FastAPI 的 `x_token` 默认会把下划线转成连字符，Hertz 的 tag 要写真实 header 名 `X-Token`。

### 2.4 JSON Body 与 Form

FastAPI 通过参数声明区分来源：

```python
@app.post("/api/v1/login")
def login(username: str = Form(...), password: str = Form(...)):
    ...
```

Hertz 通过 tag 区分：

```go
type LoginReq struct {
	Username string `form:"username" validate:"required"`
	Password string `form:"password" validate:"required,min=6"`
}
```

FastAPI 使用 `Form`、`File`、`UploadFile` 需要额外安装 `python-multipart`：

```bash
pip install python-multipart
```

如果同一个字段同时写了 `form` 和 `json`，按 Hertz 的优先级 `path > form > query > cookie > header > json > raw_body`，form 优先。不要在一个字段上写多个来源 tag，容易产生难以排查的覆盖问题。

## 三、校验规则对照

| 规则 | Pydantic | go-playground/validator |
| --- | --- | --- |
| 必填 | 不写默认值 | `required` |
| 字符串长度 | `min_length=2, max_length=20` | `min=2,max=20` |
| 数值范围 | `ge=0, le=130` | `gte=0,lte=130` |
| 大于/小于 | `gt=0, lt=100` | `gt=0,lt=100` |
| 邮箱 | `EmailStr` | `email` |
| 枚举 | `Literal["admin", "user"]` | `oneof=admin user` |
| 正则 | `Field(pattern=r"...")` | 需自定义注册 |
| 列表长度 | `Field(max_length=5)` | `max=5` |
| 列表元素 | `list[Annotated[str, Field(min_length=1)]]` | `dive,min=1` |
| 嵌套对象 | 嵌套 `BaseModel` | 嵌套 struct，默认递归校验 |
| 跨字段 | `model_validator` | `eqfield=Password` 等 |
| 可选 | `Optional[str] = None` | `omitempty` 或指针 |
| 跳过字段 | 不声明该字段 | `validate:"-"` |

### 3.1 必填与零值陷阱

这是从 Pydantic 遷移过来最反直觉的一点。

FastAPI 里：

```python
class Req(BaseModel):
    age: int
    agree: bool
```

`age=0`、`agree=false` 都是合法值，因为「字段存在」就算通过。

Hertz 里：

```go
type Req struct {
	Age   int  `json:"age" validate:"required"`
	Agree bool `json:"agree" validate:"required"`
}
```

`required` 判断的是「非零值」，所以 `age=0`、`agree=false` 都会被判为缺失。

正确写法：

```go
type Req struct {
	Age   *int  `json:"age" validate:"required,gte=0,lte=130"`
	Agree *bool `json:"agree" validate:"required"`
}
```

记住：**`required` 不等于「字段存在」，而是「值不为零」。**

### 3.2 字符串空格

FastAPI 可以配置自动去空格：

```python
model_config = ConfigDict(str_strip_whitespace=True)
```

Hertz 不会自动 trim。`"  "` 的长度是 2，能通过 `min=2`，但它显然不是一个合法名字。

两种处理方式：

1. 在业务层显式 `strings.TrimSpace`，再判断。
2. 自定义 `ValidatorFunc`，在 `vd.Struct` 之前统一归一化字符串字段。

不要指望框架帮你做这件事。

### 3.3 正则：Pydantic 一行，Hertz 要注册

FastAPI：

```python
username: str = Field(pattern=r"^[a-z0-9_]{3,16}$")
```

Hertz 需要注册自定义规则：

```go
var usernameRE = regexp.MustCompile(`^[a-z0-9_]{3,16}$`)

vd.RegisterValidation("username", func(fl validator.FieldLevel) bool {
	return usernameRE.MatchString(fl.Field().String())
})
```

然后：

```go
Username string `json:"username" validate:"required,username"`
```

### 3.4 嵌套与切片

FastAPI：

```python
class Address(BaseModel):
    city: str = Field(min_length=1)
    zip: str = Field(pattern=r"^\d{6}$")


class CreateUserReq(BaseModel):
    name: str
    address: Address
    tags: list[str] = Field(max_length=5)
```

Hertz：

```go
type Address struct {
	City string `json:"city" validate:"required"`
	Zip  string `json:"zip" validate:"required,len=6,numeric"`
}

type CreateUserReq struct {
	Name    string   `json:"name" validate:"required"`
	Address Address  `json:"address"`
	Tags    []string `json:"tags" validate:"max=5,dive,min=1"`
}
```

- 嵌套 struct 默认递归校验，不需要额外配置。
- 切片元素校验用 `dive`，`dive` 后面的规则作用在元素上。

### 3.5 跨字段：密码确认

FastAPI：

```python
class RegisterReq(BaseModel):
    password: str = Field(min_length=6)
    confirm: str

    @model_validator(mode="after")
    def check_password(self):
        if self.password != self.confirm:
            raise ValueError("两次密码不一致")
        return self
```

Hertz 直接用 `eqfield`：

```go
type RegisterReq struct {
	Password string `json:"password" validate:"required,min=6"`
	Confirm  string `json:"confirm" validate:"required,eqfield=Password"`
}
```

错误里 `confirm` 的规则会是 `eqfield=Password`，前端可以据此提示「两次密码不一致」。

## 四、统一错误响应（Hertz 必做）

### FastAPI 默认长什么样

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "name"],
      "msg": "String should have at least 2 characters",
      "input": "a"
    }
  ]
}
```

状态码 422。

如果想统一成业务结构，加一个异常处理器：

```python
from fastapi import Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse


@app.exception_handler(RequestValidationError)
async def validation_handler(request: Request, exc: RequestValidationError):
    fields = {}
    for err in exc.errors():
        loc = [str(item) for item in err["loc"] if item not in ("body", "query", "path")]
        fields[".".join(loc)] = err["msg"]
    return JSONResponse(
        status_code=422,
        content={"code": 422, "message": "参数校验失败", "fields": fields},
    )
```

### Hertz 对应写法

Hertz 没有内置的「校验失败响应」，需要自己写。上面示例里的 `writeBindError` 就是最小版本：

```json
{
  "code": 422,
  "message": "参数校验失败",
  "fields": {
    "name": "min=2",
    "email": "email"
  }
}
```

三个建议：

1. **区分两类错误**：`validator.ValidationErrors` 是校验不通过，返回 422；其他错误（JSON 语法错误、类型不匹配）返回 400。
2. **字段名用 json 名**：注册 `RegisterTagNameFunc`，否则前端收到的是 `Name`、`Email`。
3. **规则要可读**：只返回 `min` 不够，最好带上参数，如 `min=2`。

## 五、响应模型：response_model vs 手写 DTO

FastAPI 的 `response_model` 会做两件事：按模型序列化、过滤掉模型外的字段。

```python
class UserOut(BaseModel):
    id: int
    name: str
    email: EmailStr


@app.get("/api/v1/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    return user  # ORM 对象里就算有 password，也不会被输出
```

Hertz 没有这个能力，`c.JSON` 会把传入结构体的所有导出字段都序列化。所以要么定义独立 DTO，要么用 `json:"-"` 排除敏感字段：

```go
type UserOut struct {
	ID    int64  `json:"id"`
	Name  string `json:"name"`
	Email string `json:"email"`
}

h.GET("/api/v1/users/:id", func(ctx context.Context, c *app.RequestContext) {
	// 查询后只往 DTO 里放允许返回的字段
	c.JSON(consts.StatusOK, UserOut{
		ID:    user.ID,
		Name:  user.Name,
		Email: user.Email,
	})
})
```

不要把数据库模型直接丢给 `c.JSON`。这是从 FastAPI 迁移过来最容易造成的安全事故。

## 六、依赖注入：Depends vs 中间件/闭包

FastAPI 的 `Depends` 是组合式的：

```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()


def get_current_user(token: str = Depends(oauth2_scheme), db=Depends(get_db)) -> User:
    ...


@app.get("/api/v1/me", response_model=UserOut)
def me(user: User = Depends(get_current_user)):
    return user
```

Hertz 没有依赖注入容器，常见做法是两层：

1. **认证放中间件**，把用户信息写进请求上下文。
2. **业务依赖用闭包注入**，handler 是工厂函数。

```go
func Auth() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		token := string(c.GetHeader("Authorization"))
		uid, err := parseToken(token)
		if err != nil {
			c.AbortWithStatusJSON(consts.StatusUnauthorized, utils.H{
				"code": 401, "message": "未登录",
			})
			return
		}
		c.Set("uid", uid)
		c.Next(ctx)
	}
}

func NewMeHandler(userSvc *UserService) app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		raw, ok := c.Get("uid")
		if !ok {
			c.AbortWithStatusJSON(consts.StatusUnauthorized, utils.H{"code": 401, "message": "未登录"})
			return
		}
		user, err := userSvc.Get(ctx, raw.(int64))
		if err != nil {
			c.AbortWithStatusJSON(consts.StatusInternalServerError, utils.H{"code": 500, "message": "查询失败"})
			return
		}
		c.JSON(consts.StatusOK, UserOut{ID: user.ID, Name: user.Name, Email: user.Email})
	}
}

h.GET("/api/v1/me", Auth(), NewMeHandler(userSvc))
```

两个必须注意的点：

- `c.Set/Get` 存的是**当前请求**的数据，不要在 handler 里把 `*app.RequestContext` 传给 service 或 goroutine，它会被池化复用。
- 传给 service 的应该是 `context.Context`，不是 `*app.RequestContext`。

## 七、文件上传对照

FastAPI：

```python
@app.post("/api/v1/avatar")
async def upload_avatar(file: UploadFile = File(...)):
    content = await file.read()
    if len(content) > 2 * 1024 * 1024:
        raise HTTPException(status_code=413, detail="文件过大")
    ...
```

Hertz：

```go
import (
	"io"
	"mime/multipart"
	"os"
	"path/filepath"
)

type UploadReq struct {
	File *multipart.FileHeader `form:"file" validate:"required"`
}

h.POST("/api/v1/avatar", func(ctx context.Context, c *app.RequestContext) {
	var req UploadReq
	if err := c.BindAndValidate(&req); err != nil {
		writeBindError(c, err)
		return
	}
	if req.File.Size > 2*1024*1024 {
		c.AbortWithStatusJSON(consts.StatusRequestEntityTooLarge, utils.H{"code": 413, "message": "文件过大"})
		return
	}

	src, err := req.File.Open()
	if err != nil {
		c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{"code": 400, "message": "文件读取失败"})
		return
	}
	defer src.Close()

	name := filepath.Base(req.File.Filename) // 防止路径穿越
	dst, err := os.Create(filepath.Join("uploads", name))
	if err != nil {
		c.AbortWithStatusJSON(consts.StatusInternalServerError, utils.H{"code": 500, "message": "保存失败"})
		return
	}
	defer dst.Close()

	if _, err := io.Copy(dst, src); err != nil {
		c.AbortWithStatusJSON(consts.StatusInternalServerError, utils.H{"code": 500, "message": "保存失败"})
		return
	}
	c.JSON(consts.StatusOK, utils.H{"name": name, "size": req.File.Size})
})
```

两边都要做的安全校验：

- 文件大小上限（不能只靠前端）。
- 扩展名白名单。
- 读取文件头判断真实 MIME，不要只信 `Content-Type`。
- 重命名保存，不直接用用户文件名。
- 图片再走一次内容安全检测。

## 八、类型系统差异（最容易踩）

| 场景 | FastAPI + Pydantic | Hertz |
| --- | --- | --- |
| JSON 里传 `"18"` 给 `int` | 默认宽松模式会转成 18 | 报类型错误 |
| Query 里传 `?age=18` | 正常转 int | 正常转 int |
| 传 `null` | `None`，可用 `Optional` 表达 | 指针为 nil，或零值 |
| 布尔 | `true` / `"true"` 可转 | JSON 只认 `true`，query 认 `true/false/1/0` |
| 时间 | 自动解析多种 ISO 8601 | `time.Time` 按 RFC3339 解析 |
| 金额 | `Decimal` | 建议 `int64` 存分，或字符串 |
| 未知字段 | `extra="forbid"` 拒绝 | 默认忽略，纯 JSON 接口需改用 `BindJSON` |

### 8.1 让 Hertz 拒绝未知字段

对应 Pydantic 的 `extra="forbid"`，但要注意：`EnableDecoderDisallowUnknownFields` 只作用于专门的 `BindJSON` 路径，`BindAndValidate` 走的是 tag 绑定，默认仍然忽略未知字段。

纯 JSON 接口可以这样写：

```go
import "github.com/cloudwego/hertz/pkg/app/server/binding"

h := server.Default(
	server.WithHostPorts("127.0.0.1:8080"),
	server.WithBindConfig(&binding.BindConfig{
		EnableDecoderDisallowUnknownFields: true,
	}),
	server.WithCustomValidatorFunc(func(_ *protocol.Request, req any) error {
		return vd.Struct(req)
	}),
)

h.POST("/api/v1/users", func(ctx context.Context, c *app.RequestContext) {
	var req CreateUserReq
	if err := c.BindJSON(&req); err != nil { // 严格：多传字段会报错
		c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{
			"code": 400, "message": "请求体格式错误", "detail": err.Error(),
		})
		return
	}
	if err := c.Validate(&req); err != nil { // 手动补上校验
		writeBindError(c, err)
		return
	}
	c.JSON(consts.StatusCreated, utils.H{"data": req})
})
```

代价是 `BindJSON` 只读 Body，不再自动绑定 path/query/header。如果接口同时需要 path 或 query 参数，要么分别调用 `BindPath`、`BindQuery`，要么接受 tag 绑定忽略未知字段的行为。

query/form 的未知参数本来就会被忽略，没有对应的「拒绝」开关。

### 8.2 时间字段

FastAPI：

```python
from datetime import datetime

class Req(BaseModel):
    start_at: datetime
```

请求传 `2026-01-01T10:00:00+08:00` 即可。

Hertz：

```go
import "time"

type Req struct {
	StartAt time.Time `json:"start_at" validate:"required"`
}
```

`time.Time` 按 RFC3339 解析，也就是 `2026-01-01T10:00:00+08:00` 这种格式。前端如果传 `2026-01-01 10:00:00`，会绑定失败。契约要在前端就统一。

## 九、迁移速查表

| FastAPI | Hertz |
| --- | --- |
| `class Req(BaseModel)` | `type Req struct` |
| `name: str` | `Name string`，tag `json:"name"` |
| `name: str = Field(min_length=2)` | `Name string`，tag `json:"name" validate:"min=2"` |
| `age: int = Field(ge=0)` | `Age int`，tag `json:"age" validate:"gte=0"` |
| `email: EmailStr` | `Email string`，tag `json:"email" validate:"email"` |
| `role: Literal["a", "b"]` | `Role string`，tag `json:"role" validate:"oneof=a b"` |
| `page: int = 1` | `Page int`，tag `query:"page" default:"1"` |
| `q: Optional[str] = None` | `Q *string`，tag `query:"q"` |
| `tags: list[str]` | `Tags []string`，tag `query:"tag"` |
| `file: UploadFile` | `File *multipart.FileHeader`，tag `form:"file"` |
| `Depends(get_current_user)` | 认证中间件 + `c.Set("uid", ...)` |
| `Depends(get_db)` | service 构造函数注入，或 handler 闭包 |
| `response_model=UserOut` | 手写 `UserOut` DTO |
| `HTTPException(400, "...")` | `c.AbortWithStatusJSON(400, ...)` |
| 自动 422 | 自己写 `writeBindError` |
| 自动 OpenAPI | hz 注解 + 代码生成 |

## 十、常见坑（FastAPI 视角）

1. **写了 `validate` 却没注入 validator**
   Hertz 默认校验器只认 `vd` 标签，`validate` 不会生效。必须用 `server.WithCustomValidatorFunc` 注入 go-playground。
2. **以为 `BindAndValidate` 会自动调用**
   FastAPI 是自动的，Hertz 不是。handler 里不写就不校验。
3. **`required` 当成「字段存在」**
   `int` 的 0、`bool` 的 false、`string` 的空串都会被判为缺失。用范围规则或指针。
4. **JSON 里传字符串数字**
   FastAPI 会转，Hertz 不会。`"age": "18"` 直接绑定失败，前端必须传数字。
5. **没带 `Content-Type: application/json`**
   Hertz 可能走不到 JSON 绑定分支，字段全是零值，最后被 `required` 拦下，但错误信息很迷惑。
6. **先 `c.Body()` 再 `Bind`**
   Body 已经被消费，绑定拿不到内容。和 FastAPI 的缓存机制不同，Hertz 不会帮你缓存。
7. **错误响应里出现 Go 字段名**
   默认是 `Name`，不是 `name`。注册 `RegisterTagNameFunc`。
8. **把数据库模型直接 `c.JSON`**
   FastAPI 的 `response_model` 会过滤，Hertz 不会。密码、内部字段会直接泄漏。
9. **一个字段写多个来源 tag**
   `form` 和 `json` 同时存在时 form 优先，容易出现「传了 JSON 却读到空值」。
10. **以为 `extra="forbid"` 默认存在**
    Hertz 默认忽略未知字段，需要显式开启 `EnableDecoderDisallowUnknownFields`。

## 十一、练习

### 练习 1：1:1 改写

把下面这个 FastAPI 接口用 Hertz 重写，要求：

- 校验规则一致。
- 错误响应结构一致（`code/message/fields`）。
- 状态码一致。

```python
class UpdateUserReq(BaseModel):
    name: str = Field(min_length=2, max_length=20)
    age: int = Field(ge=0, le=130)
    email: EmailStr
    tags: list[str] = Field(default_factory=list, max_length=3)
```

### 练习 2：对抗性测试

分别用 FastAPI 和 Hertz 跑下面这组请求，记录状态码和响应体，对比差异：

| 请求 | 预期观察点 |
| --- | --- |
| 缺少 `name` | 必填错误 |
| `name="a"` | 长度不足 |
| `name="  "` | FastAPI 去空格后失败，Hertz 可能通过 |
| `age=131` | 范围错误 |
| `age="18"` | FastAPI 通过，Hertz 失败 |
| `email="not-an-email"` | 邮箱格式错误 |
| `tags` 传 6 个 | 列表长度错误 |
| 多传一个 `admin=true` | FastAPI 拒绝，Hertz 默认忽略 |
| 不带 `Content-Type` | 两边表现完全不同 |

### 练习 3：自定义正则

给用户名增加 `^[a-z0-9_]{3,16}$` 规则，分别用 Pydantic 的 `pattern` 和 validator 的 `RegisterValidation` 实现。

### 练习 4：跨字段校验

实现注册接口，要求 `password` 和 `confirm` 一致，分别用 `model_validator` 和 `eqfield` 实现。

### 练习 5：文件上传

实现头像上传，限制 2MB、只允许 `jpg/png/webp`，并校验文件头，不只信扩展名。

## 十二、小结

- FastAPI 是「类型即契约 + 自动校验」；Hertz 是「tag 即契约 + 显式校验 + 手动错误映射」。
- `validate` 标签只有在注入 go-playground/validator 后才生效，这是第一优先级要记住的事。
- `required` 判断零值，不是判断字段存在；`default` 是独立 tag；JSON 不做类型宽松转换。
- 错误响应、响应模型、依赖注入、OpenAPI 在 Hertz 里都需要自己补，不要期待框架自动完成。
