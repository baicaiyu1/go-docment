# 中间件

> 一句话定位：Hertz 中间件就是 `func(context.Context, *app.RequestContext)`，通过 `Use` 挂到全局或路由组，用 `c.Next` 串成洋葱模型，用 `c.Abort` 提前终止。

## 本篇目标

- 掌握中间件签名与全局、路由组、单路由三种注册方式。
- 理解 `c.Next` 的洋葱执行顺序，以及“忘记 Next”会发生什么。
- 会用 `c.Abort` 做鉴权，并接入 CORS、RequestID。
- 会写访问日志与超时中间件，并在中间件中安全传递数据。

## 前置知识

- 已完成 `03-基本特性/01-路由` 与 `02-请求上下文Context`。
- 理解 `c.Set/Get`、`c.Next`、`c.Abort` 的语义。

## 中间件签名

```go
type HandlerFunc func(c context.Context, ctx *app.RequestContext)

func MyMiddleware() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		// 前置逻辑
		c.Next(ctx)
		// 后置逻辑
	}
}
```

具名函数比匿名函数更方便复用和测试。

## 三种注册方式

```go
h.Use(AccessLog(), RequireToken()) // 全局：必须在注册路由之前调用

api := h.Group("/api/v1", RequireToken()) // 路由组：只对组内路由生效
api.GET("/profile", profileHandler)

h.GET("/upload", RequireToken(), handleUpload) // 单路由：按声明顺序组成链
```

**`Use` 要在注册路由之前调用**，否则已注册的路由不会补挂中间件。

## 执行顺序与洋葱模型

```go
func Tag(name string) app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		fmt.Println(name, "before")
		c.Next(ctx)
		fmt.Println(name, "after")
	}
}

h.Use(Tag("A"), Tag("B"))
h.GET("/ping", func(ctx context.Context, c *app.RequestContext) {
	fmt.Println("handler")
	c.String(consts.StatusOK, "pong")
})
```

输出：`A before → B before → handler → B after → A after`。`Next` 递增下标并循环执行后续 handler，返回后继续当前中间件的后置代码；最后一个 handler 通常不再调用 `Next`。

## Next 与 Abort

```go
func RequireToken() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		if string(c.GetHeader("X-Token")) != "secret" {
			c.AbortWithStatusJSON(consts.StatusUnauthorized, utils.H{"code": 401})
			return
		}
		c.Set("auth.user_id", "u-1001")
		c.Next(ctx)
	}
}
```

- `c.Next(ctx)`：继续执行后续 handler，是链能走下去的关键。
- `c.Abort()`：后续 handler 不再执行，但**当前函数继续执行**，通常紧跟 `return`。
- `c.IsAborted()`：判断链路是否已终止。
- 同一中间件里重复 `Next` 会让后续 handler 执行多次。

## 访问日志中间件

```go
func AccessLog() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		start := time.Now()
		c.Next(ctx)
		hlog.Infof("%s %s status=%d cost=%s",
			c.Method(), c.Path(), c.Response.StatusCode(), time.Since(start))
	}
}
```

后置逻辑在 `Next` 返回后执行，此时能拿到最终状态码。

## 跨域 CORS

```go
import "github.com/hertz-contrib/cors"

h.Use(cors.New(cors.Config{
	AllowOrigins:     []string{"https://foo.com"},
	AllowMethods:     []string{"GET", "POST", "PUT", "DELETE", "OPTIONS"},
	AllowHeaders:     []string{"Origin", "Content-Type", "Authorization"},
	ExposeHeaders:    []string{"Content-Length", "X-Request-Id"},
	AllowCredentials: true,
	MaxAge:           12 * time.Hour,
}))
```

开发期可用 `cors.New(cors.Config{AllowAllOrigins: true})`，但它不能与 `AllowCredentials: true` 同时使用。

## Recovery 与 RequestID

`server.Default()` 已内置 Recovery；`server.New()` 用 `h.Use(recovery.Recovery(...))` 注册，堆栈只进日志，完整写法见 `06-错误处理`。

```go
import "github.com/hertz-contrib/requestid"

h.Use(requestid.New())

h.GET("/ping", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{"request_id": requestid.Get(c)})
})
```

请求头带 `X-Request-ID` 时沿用，否则生成新 ID，并写入响应头。

## 超时中间件

`RequestContext` 不允许并发使用，无法安全地“到点强制中断” handler。正确做法是传播 deadline，让业务与下游配合：

```go
func Timeout(d time.Duration) app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		tctx, cancel := context.WithTimeout(ctx, d)
		defer cancel()
		c.Next(tctx)
	}
}

h.GET("/slow", Timeout(500*time.Millisecond), func(ctx context.Context, c *app.RequestContext) {
	select {
	case <-time.After(2 * time.Second):
		c.JSON(consts.StatusOK, utils.H{"ok": true})
	case <-ctx.Done():
		c.AbortWithStatusJSON(consts.StatusGatewayTimeout, utils.H{"code": 504})
	}
})
```

调用 DB、HTTP Client 时也要把 `ctx` 传下去，超时后它们会返回 `context.DeadlineExceeded`。

## 中间件里取 ctx 值

中间件读写请求级数据统一用 `c.Set/Get`，key 加前缀（如 `auth.user_id`）；`MustGet` 在 key 不存在时会 panic。

## 完整示例

```go
package main

import (
	"context"
	"time"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/hlog"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
	"github.com/hertz-contrib/cors"
	"github.com/hertz-contrib/requestid"
)

func AccessLog() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		start := time.Now()
		c.Next(ctx)
		hlog.Infof("%s %s %d %s", c.Method(), c.Path(),
			c.Response.StatusCode(), time.Since(start))
	}
}

func RequireToken() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		if string(c.GetHeader("X-Token")) != "secret" {
			c.AbortWithStatusJSON(consts.StatusUnauthorized, utils.H{"code": 401})
			return
		}
		c.Set("auth.user_id", "u-1001")
		c.Next(ctx)
	}
}

func main() {
	h := server.Default(server.WithHostPorts("127.0.0.1:8080"))
	h.Use(requestid.New(), AccessLog())
	h.Use(cors.New(cors.Config{AllowAllOrigins: true}))

	api := h.Group("/api/v1", RequireToken())
	api.GET("/profile", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{
			"user_id":    c.GetString("auth.user_id"),
			"request_id": requestid.Get(c),
		})
	})

	h.Spin()
}
```

验证：

Windows PowerShell：

```powershell
go run .
curl.exe -i http://127.0.0.1:8080/api/v1/profile
curl.exe -i -H "X-Token: secret" http://127.0.0.1:8080/api/v1/profile
```

Linux / macOS bash：

```bash
go run .
curl -i http://127.0.0.1:8080/api/v1/profile
curl -i -H "X-Token: secret" http://127.0.0.1:8080/api/v1/profile
```

第一次返回 401，第二次返回 200 并带 `request_id`。

## 常见坑

1. **忘记 `c.Next(ctx)`**：链路停在当前中间件，业务 handler 不执行，可能返回空 200。
2. **注册路由后才 `Use`**：已注册的路由不会补挂中间件。
3. **`Abort` 后不 `return`**：当前函数继续执行，可能继续写响应。
4. **`Next` 之后重复写响应**：业务 handler 已写完 Body，再写会追加内容。
5. **中间件闭包共享可变状态**：计数器、map 必须加锁或用原子操作。
6. **`Default()` 又加 Recovery**：两个 Recovery 嵌套，日志重复。
7. **CORS 配置冲突**：`AllowAllOrigins` 与 `AllowCredentials` 不能同时为真。

## 小结

- 中间件是 handler 链的一环，`Next` 决定是否继续，`Abort` 决定是否终止。
- 注册顺序即执行顺序，全局 `Use` 必须在路由注册之前。
- CORS、Recovery、RequestID 优先用成熟中间件，超时靠 context 传播。
- 中间件里读写请求级数据用 `c.Set/Get`，key 要约定命名。
