# 参数绑定与校验

> 一句话定位：Hertz 通过结构体 tag 把 query、path、form、JSON 等来源绑定到 Go 结构体，再按需执行校验；理解 tag 优先级与 validator 配置是写好接口的第一步。

## 本篇目标

- 掌握 `c.Bind`、`c.BindAndValidate` 及细分绑定方法的差异。
- 理解 `path/form/query/cookie/header/json/raw_body/default` 标签与绑定优先级。
- 配置 go-playground/validator，实现 `validate:"required,email"` 等规则。
- 统一处理绑定失败返回 400，并支持嵌套结构体与文件字段。

## 前置知识

- 了解 Go 结构体 tag 与反射。
- 已完成 `03-基本特性/02-请求上下文Context`。
- 知道 `Content-Type` 对表单与 JSON 的影响。

## 绑定 API 一览

| API | 说明 |
| --- | --- |
| `c.Bind(obj)` | 按 tag 绑定，不做校验 |
| `c.BindAndValidate(obj)` | 先绑定，再执行校验 |
| `c.BindQuery/BindHeader/BindPath` | 只绑定单一来源 |
| `c.BindForm/BindJSON/BindProtobuf` | 只绑定对应格式的 Body |
| `c.BindByContentType(obj)` | 按 `Content-Type` 自动选择 |
| `c.Validate(obj)` | 只校验，不绑定 |

最常用的写法：

```go
if err := c.BindAndValidate(&req); err != nil {
	c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{"code": 400, "message": err.Error()})
	return
}
```

## 支持的 tag 与优先级

| tag | 来源 |
| --- | --- |
| `path` | 路由参数，如 `path:"id"` |
| `form` | urlencoded 或 multipart 表单 |
| `query` | Query String |
| `cookie` | Cookie |
| `header` | 请求头 |
| `json` | JSON Body |
| `raw_body` | 原始 Body |
| `default` | 默认值，独立 tag |

```text
path > form > query > cookie > header > json > raw_body
```

同一字段写了多个来源 tag 时，高优先级来源有值就优先使用；没写 tag 时也按此顺序尝试。

## 基础示例

```go
type ListUsersReq struct {
	Page int      `query:"page" default:"1"`
	Size int      `query:"size" default:"10"`
	Tags []string `query:"tag"` // ?tag=a&tag=b
}

h.GET("/api/v1/users", func(ctx context.Context, c *app.RequestContext) {
	var req ListUsersReq
	if err := c.BindAndValidate(&req); err != nil {
		c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{"code": 400, "message": err.Error()})
		return
	}
	c.JSON(consts.StatusOK, utils.H{"page": req.Page, "size": req.Size, "tags": req.Tags})
})
```

`default:"1"` 只在字段缺省时生效；显式传 `page=` 空值时不会覆盖。

## 路径参数与 JSON 混合绑定

```go
type UpdateUserReq struct {
	ID    string `path:"id" validate:"required"`
	Name  string `json:"name" validate:"required,min=2,max=20"`
	Email string `json:"email" validate:"omitempty,email"`
}

h.PUT("/api/v1/users/:id", func(ctx context.Context, c *app.RequestContext) {
	var req UpdateUserReq
	if err := c.BindAndValidate(&req); err != nil {
		c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{"code": 400, "message": err.Error()})
		return
	}
	c.JSON(consts.StatusOK, utils.H{"id": req.ID, "name": req.Name})
})
```

Hertz 会先绑定 `path`，再处理 JSON Body，最终得到完整结构体。

## required 与 default

- `json:"name,required"`：绑定阶段该来源必须提供。
- `validate:"required"`：校验阶段字段不能为零值。
- `default:"1"`：绑定阶段缺省时填入。

推荐把必填规则集中到 `validate`，错误信息更好统一。

## 配置 go-playground/validator

Hertz 自带的默认校验器使用 `vd` 标签（tagexpr），**不会执行 `validate` 标签**。要使用 `validate:"required,email"`，必须显式注入：

```go
vd := validator.New(validator.WithRequiredStructEnabled())

h := server.Default(
	server.WithHostPorts("127.0.0.1:8080"),
	server.WithCustomValidatorFunc(func(_ *protocol.Request, req any) error {
		return vd.Struct(req)
	}),
)
```

依赖：

```powershell
go get github.com/go-playground/validator/v10
```

```bash
go get github.com/go-playground/validator/v10
```

常用规则：`required`、`min/max`、`email`、`gte/lte`、`oneof=admin user`、`omitempty`、`dive`。

## 嵌套结构体与切片

```go
type Address struct {
	City string `json:"city" validate:"required"`
	Zip  string `json:"zip" validate:"required,len=6"`
}

type CreateUserReq struct {
	Name    string   `json:"name" validate:"required,min=2,max=20"`
	Age     int      `json:"age" validate:"gte=0,lte=130"`
	Email   string   `json:"email" validate:"required,email"`
	Tags    []string `json:"tags" validate:"max=5,dive,min=1"`
	Address Address  `json:"address"`
}
```

validator 默认递归校验嵌套结构体；`dive` 表示进入切片元素继续校验。

文件字段用 `form:"file"` 绑定为 `*multipart.FileHeader`，保存与安全校验见 `08-静态资源与文件上传`。Hertz 没有 Gin 的 `FailedBind` 便捷方法，绑定失败统一 `AbortWithStatusJSON(400, ...)`。

## 完整示例

```go
package main

import (
	"context"
	"fmt"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
	"github.com/go-playground/validator/v10"
)

type CreateUserReq struct {
	Name  string `json:"name" validate:"required,min=2,max=20"`
	Age   int    `json:"age" validate:"gte=0,lte=130"`
	Email string `json:"email" validate:"required,email"`
}

func main() {
	vd := validator.New(validator.WithRequiredStructEnabled())
	h := server.Default(
		server.WithHostPorts("127.0.0.1:8080"),
		server.WithCustomValidatorFunc(func(_ *protocol.Request, req any) error {
			return vd.Struct(req)
		}),
	)

	h.POST("/api/v1/users", func(ctx context.Context, c *app.RequestContext) {
		var req CreateUserReq
		if err := c.BindAndValidate(&req); err != nil {
			c.AbortWithStatusJSON(consts.StatusBadRequest, utils.H{"code": 400, "message": err.Error()})
			return
		}
		c.JSON(consts.StatusCreated, utils.H{"data": req})
	})

	h.Spin()
}
```

Invoke-RestMethod -Uri http://127.0.0.1:8080/api/v1/users -Method Post `
  -ContentType "application/json" -Body '{"name":"tom","age":18,"email":"tom@example.com"}'
```

curl -i -X POST http://127.0.0.1:8080/api/v1/users \

  -d '{"name":"tom","age":18,"email":"tom@example.com"}'
```

把 `email` 改成非法值，确认返回 400 与校验错误信息。

## 常见坑

1. **写了 `validate` 却没注入 validator**：默认校验器用 `vd` 标签，`validate` 不会生效。
2. **tag 拼写错误**：`queary`、`jsom`、`valiadte` 不会报错，只会静默绑定失败。
3. **JSON 请求没带 `Content-Type: application/json`**：可能走不到 JSON 分支，字段全为零值。
4. **先 `c.Body()` 再 `Bind`**：Body 已被消费，绑定拿不到内容。
5. **string 传数字**：JSON 里 `"age":"18"` 会报类型错误，前端应传数字。
6. **文件字段写成 `[]byte`**：必须用 `*multipart.FileHeader`。

## 小结

- 绑定靠 tag，优先级是 path > form > query > cookie > header > json > raw_body。
- `BindAndValidate` = 绑定 + 校验；`validate` 规则需要 go-playground validator 才生效。
- 嵌套结构体递归校验，切片用 `dive`，文件用 `*multipart.FileHeader`。
- 绑定失败统一 400，并封装成稳定的错误结构。
