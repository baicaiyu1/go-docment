# 响应与渲染

> 一句话定位：Hertz 用一组 `c.Xxx` 方法完成字符串、JSON、XML、二进制、HTML、重定向和自定义格式的输出，选择哪种方法决定了 Content-Type 与响应体形态。

## 本篇目标

- 掌握 `c.String`、`c.JSON`、`c.XML`、`c.Data`、`c.Redirect`、`c.Status` 的用法。
- 理解状态码、响应头、Content-Type 的设置顺序与组合方式。
- 会用 `c.HTML` 渲染模板，用 `c.Render` 实现自定义渲染器。
- 避开“重复写响应”“JSON 转义 HTML”“模板路径错误”等问题。

## 前置知识

- 了解 HTTP 状态码与 `Content-Type`。
- 已完成 `03-基本特性/02-请求上下文Context`。
- 写过简单的 Go `html/template` 模板。

## 常用响应 API

| 方法 | 作用 | 默认 Content-Type |
| --- | --- | --- |
| `c.String(code, format, args...)` | 格式化文本 | `text/plain; charset=utf-8` |
| `c.JSON(code, obj)` | JSON 序列化 | `application/json; charset=utf-8` |
| `c.PureJSON(code, obj)` | 不转义 HTML 字符的 JSON | 同上 |
| `c.IndentedJSON(code, obj)` | 带缩进的 JSON | 同上 |
| `c.XML(code, obj)` | XML 序列化 | `application/xml; charset=utf-8` |
| `c.Data(code, contentType, data)` | 原始字节 | 由调用方指定 |
| `c.HTML(code, name, obj)` | 模板渲染 | `text/html; charset=utf-8` |
| `c.Redirect(code, uri)` | 重定向 | 无 |
| `c.Status(code)` | 只设置状态码 | 无 |
| `c.Render(code, render)` | 自定义渲染器 | 由渲染器决定 |

## 文本与 JSON

```go
h.GET("/text", func(ctx context.Context, c *app.RequestContext) {
	c.String(consts.StatusOK, "hello, %s", "hertz")
})

h.GET("/json", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{
		"code": 0, "data": utils.H{"name": "tom", "age": 18},
	})
})
```

`c.JSON` 默认转义 `<`、`>`、`&`，避免 XSS。需要保留原字符时：

```go
c.PureJSON(consts.StatusOK, utils.H{"html": "<p>Hello</p>"})
```

## 状态码组合

```go
c.JSON(consts.StatusCreated, utils.H{"id": 1001})                     // 201
c.JSON(consts.StatusBadRequest, utils.H{"code": 40001})               // 400
c.JSON(consts.StatusNotFound, utils.H{"code": 40401})                 // 404
c.Status(consts.StatusNoContent)                                      // 204，不能带 Body
```

`204 No Content` 调用后不要再写响应体。

## 二进制、响应头与 Cookie

```go
h.GET("/bin", func(ctx context.Context, c *app.RequestContext) {
	c.Header("X-Service", "user-service")
	c.SetContentType("application/octet-stream")
	c.SetCookie("visited", "1", 3600, "/", "localhost",
		protocol.CookieSameSiteLaxMode, false, true)
	c.Data(consts.StatusOK, "application/octet-stream", []byte{0x01, 0x02})
})
```

`c.Header`、`c.SetContentType` 必须在写 Body 之前调用；Body 一旦写出，响应头可能已经发送。文件下载用 `c.File` / `c.FileAttachment`，见 08 篇。

## XML 渲染

```go
type UserXML struct {
	XMLName xml.Name `xml:"user"`
	ID      int      `xml:"id"`
	Name    string   `xml:"name"`
}

h.GET("/xml", func(ctx context.Context, c *app.RequestContext) {
	c.XML(consts.StatusOK, UserXML{ID: 1, Name: "tom"})
})
```

输出 `<user><id>1</id><name>tom</name></user>`；字段需要 `xml` tag。

## HTML 模板渲染

模板 `templates/index.tmpl`：

```html
<h1>{{.title}}</h1>
<p>Hello, {{.name}}</p>
```

加载与渲染：

```go
h.LoadHTMLGlob("templates/*")
// 或 h.LoadHTMLFiles("templates/index.tmpl")

h.GET("/index", func(ctx context.Context, c *app.RequestContext) {
	c.HTML(consts.StatusOK, "index.tmpl", utils.H{"title": "Hertz", "name": "tom"})
})
```

- 自定义分隔符：`h.Delims("{[{", "}]}")`。
- 自定义函数：`h.SetFuncMap(template.FuncMap{"upper": strings.ToUpper})`。
- 模板路径相对于**进程工作目录**，不是源码目录。

## 自定义渲染器

实现 `render.Render` 的 `Render` 与 `WriteContentType` 两个方法即可扩展任意格式，以 YAML 为例：

```go
type YAML struct{ Data interface{} }

func (r YAML) Render(resp *protocol.Response) error {
	resp.Header.SetContentType("application/yaml; charset=utf-8")
	b, err := yaml.Marshal(r.Data)
	if err != nil {
		return err
	}
	resp.AppendBody(b)
	return nil
}

func (r YAML) WriteContentType(resp *protocol.Response) {
	resp.Header.SetContentType("application/yaml; charset=utf-8")
}

// h.GET("/yaml", func(ctx context.Context, c *app.RequestContext) {
// 	c.Render(consts.StatusOK, YAML{Data: utils.H{"name": "tom"}})
// })
```

依赖 `gopkg.in/yaml.v3`，用 `go get gopkg.in/yaml.v3` 安装。

## 重定向

```go
h.GET("/old", func(ctx context.Context, c *app.RequestContext) {
	c.Redirect(consts.StatusFound, []byte("/new"))
	return // Redirect 不会终止当前函数
})
```

`302` 临时跳转、`301` 永久跳转、`307/308` 保留请求方法。

## 完整示例

```go
package main

import (
	"context"
	"encoding/xml"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

type UserXML struct {
	XMLName xml.Name `xml:"user"`
	ID      int      `xml:"id"`
	Name    string   `xml:"name"`
}

func main() {
	h := server.Default(server.WithHostPorts("127.0.0.1:8080"))

	h.GET("/api/v1/users/:id", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{"code": 0, "data": utils.H{"id": c.Param("id")}})
	})
	h.GET("/api/v1/users/:id/xml", func(ctx context.Context, c *app.RequestContext) {
		c.XML(consts.StatusOK, UserXML{ID: 1, Name: "tom"})
	})

	h.LoadHTMLGlob("templates/*")
	h.GET("/index", func(ctx context.Context, c *app.RequestContext) {
		c.HTML(consts.StatusOK, "index.tmpl", utils.H{"title": "Hertz", "name": "tom"})
	})
	h.GET("/old", func(ctx context.Context, c *app.RequestContext) {
		c.Redirect(consts.StatusFound, []byte("/index"))
	})

	h.Spin()
}
```

## 常见坑

1. **一个 handler 调用多次响应方法**：`c.JSON` 后再 `c.String` 会追加 Body 或产生非法响应。
2. **写 Body 后设置 Header**：响应头可能已发送，设置无效。
3. **`c.String` 内容含 `%`**：会被当格式符，需转义为 `%%` 或改用 `c.Data`。
4. **JSON 里的 HTML 被转义**：默认安全行为，需要原样输出时用 `c.PureJSON`。
5. **模板按源码目录找**：实际相对工作目录，部署时要确认启动目录。
6. **`c.Redirect` 后忘记 `return`**：后续代码继续执行，可能又写一次响应。

## 小结

- 响应方法决定 Content-Type 与 Body 形态，按场景选择 `String/JSON/XML/Data/HTML/Render`。
- 201、204、400、404 要按业务正确使用，204 不能带 Body。
- HTML 渲染依赖模板加载路径；自定义格式通过实现 `render.Render` 扩展。
- 响应只能写一次，Header 必须在 Body 之前设置。
