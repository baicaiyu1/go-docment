# 路由

> 一句话定位：Hertz 的路由由“方法 + 路径模式”决定，支持静态、命名参数、通配参数与路由组，匹配优先级固定为静态 > 命名参数 > 通配。

## 本篇目标

- 掌握 `GET/POST/PUT/DELETE/Any/Handle` 的注册方式与差异。
- 理解静态路由、`:name` 参数路由、`*path` 通配路由的匹配规则。
- 会用 `Group` 组织版本化路由，并给路由组挂中间件。
- 会处理 404/405、命名路由与尾斜杠重定向，并避开参数冲突。

## 前置知识

- 已跑通 Hertz 服务，知道 `HandlerFunc` 的签名。
- 了解 HTTP Method、URL Path、Query String。
- 读过 `02-Hertz入门/05-Engine详解与启动参数`。

## 注册路由的方法

| 方法 | 说明 |
| --- | --- |
| `GET/POST/PUT/DELETE/PATCH/HEAD/OPTIONS` | 注册对应 HTTP Method |
| `Any(path, handlers...)` | 为所有内置标准方法注册同一 handler |
| `Handle(method, path, handlers...)` | 手动指定 Method，可注册自定义方法 |
| `StaticFile/Static/StaticFS` | 注册静态文件路由（见 08 篇） |

```go
h := server.Default(server.WithHostPorts("127.0.0.1:8080"))
h.GET("/ping", ping)
h.POST("/users", createUser)
h.PUT("/users/:id", updateUser)
h.DELETE("/users/:id", deleteUser)
h.Any("/health", health)
h.Handle("LOAD", "/load", load)
```

`Any` 只覆盖内置标准方法，不会自动接管你自定义的 `LOAD`。

## 静态路由

路径完全固定的路由优先级最高：

```go
h.GET("/users/me", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{"user": "me"})
})
```

即使同时存在 `"/users/:id"`，访问 `/users/me` 也一定命中静态路由。

## 命名参数路由

`:name` 只匹配单个非空路径段：

```go
h.GET("/users/:uid/orders/:oid", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{"uid": c.Param("uid"), "oid": c.Param("oid")})
})
```

| 请求路径 | 是否匹配 |
| --- | --- |
| `/users/123/orders/9` | 匹配 |
| `/users/123/orders` | 不匹配 |
| `/users//orders/9` | 不匹配（参数不能为空） |
| `/users/123/orders/9/detail` | 不匹配 |

## 通配参数路由

`*path` 匹配剩余全部内容（含 `/`），只能放在路径末尾：

```go
h.GET("/files/*filepath", func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{"filepath": c.Param("filepath")})
})
```

| 请求路径 | `c.Param("filepath")` |
| --- | --- |
| `/files/a.txt` | `/a.txt` |
| `/files/dir/a.txt` | `/dir/a.txt` |
| `/files/` | `/` |
| `/files` | 不匹配 |

通配参数通常以 `/` 开头，拼接本地路径时要先处理。

## 路由优先级

```text
静态路由  >  命名参数路由  >  通配参数路由
```

```go
h.GET("/users/me", meHandler)
h.GET("/users/:id", userHandler)
h.GET("/users/*rest", restHandler)
```

- `/users/me` → `meHandler`
- `/users/123` → `userHandler`
- `/users/123/profile` → `restHandler`

优先级由路由树结构决定，不依赖注册顺序。

## 路由组 Group

```go
v1 := h.Group("/api/v1")
{
	v1.GET("/users", listUsers)
	v1.POST("/users", createUser)
	v1.GET("/users/:id", getUser)
}

admin := h.Group("/admin", authMiddleware)
admin.GET("/stats", statsHandler)
```

`Group` 的第二个参数是可变参数 `...app.HandlerFunc`，也可以之后 `admin.Use(authMiddleware)`。路径建议不带末尾 `/`，避免与重定向规则纠缠。

同一路径可挂多个 handler，按声明顺序执行，用 `c.Next(ctx)` 串联，详见 `05-中间件`。

所有路由必须在 `Spin()` / `Run()` 之前注册；启动后再注册不保证生效，需要动态路由时用“通配路由 + 内部查表”。

## 404 与 405

```go
h := server.Default(
	server.WithHostPorts(":8080"),
	server.WithHandleMethodNotAllowed(true),
)
h.POST("/ping", ping)
h.NoRoute(func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusNotFound, utils.H{"code": 404})
})
h.NoMethod(func(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusMethodNotAllowed, utils.H{"code": 405})
})
```

- 默认路径不存在返回 404。
- 开启 `WithHandleMethodNotAllowed(true)` 后，路径存在但方法不匹配才会走 `NoMethod` 返回 405。

## 命名路由与尾斜杠

匿名函数注册时 `c.HandlerName()` 是编译器生成名，不利于监控。带名称的注册方法：

```go
h.GETEX("/ping", pingHandler, "ping_handler")
// 对应还有 POSTEX/PUTEX/DELETEEX/AnyEX/HandleEX
```

```go
for _, r := range h.Routes() {
	hlog.Infof("%s %s -> %s", r.Method, r.Path, r.Handler)
}
```

`RouteInfo` 含 `Method`、`Path`、`Handler`、`HandlerFunc`。另外 `WithRedirectTrailingSlash` 默认开启：`/foo` 与 `/foo/` 会自动重定向，`GET` 用 301，其他方法用 307。

## 完整示例

```go
package main

import (
	"context"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

func main() {
	h := server.Default(
		server.WithHostPorts("127.0.0.1:8080"),
		server.WithHandleMethodNotAllowed(true),
	)

	v1 := h.Group("/api/v1")
	v1.GET("/users/me", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{"user": "me"})
	})
	v1.GET("/users/:id", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{"id": c.Param("id")})
	})
	v1.GET("/files/*filepath", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, utils.H{"filepath": c.Param("filepath")})
	})

	h.NoRoute(func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusNotFound, utils.H{"code": 404})
	})
	h.NoMethod(func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusMethodNotAllowed, utils.H{"code": 405})
	})

	h.Spin()
}
```


## 常见坑

1. **同一位置混用不同参数名**：`/users/:id` 与 `/users/:name` 不是两条独立路由，取值会异常，务必统一命名。
2. **通配符不在末尾**：`/files/*path/edit` 会在注册时 panic。
3. **重复注册同一方法同一路径**：会 panic `handlers are already registered for path`。
4. **路由组路径少了 `/`**：`h.Group("api/v1")` 不符合要求，应以 `/` 开头。
5. **以为 `Any` 能匹配自定义方法**：自定义方法要用 `Handle/HandleEX`。
6. **`NoMethod` 不生效**：忘记开启 `WithHandleMethodNotAllowed(true)`。

## 小结

- 路由由 Method 与路径模式组成，静态、命名参数、通配各有明确边界。
- 路由组用于统一前缀和中间件，是版本化 API 的基础。
- 一个路由可以挂多个 handler，用 `c.Next` 串成链。
- 路由必须在启动前注册；404/405 与命名路由是生产可观测性的一部分。
