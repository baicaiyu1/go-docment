# 18-常量与实用工具
> 少写魔法字符串、少造轮子：Hertz 的 `consts`、`utils` 与配置默认值速查。

## 本篇目标

- 掌握 `pkg/protocol/consts` 中方法、状态码、MIME、Header 常量的用法。
- 熟悉 `pkg/common/utils` 中 `H`、环境变量、路径、IP、拷贝等常用工具。
- 能读懂 server 配置项的默认值，知道去哪里查完整参考。
- 知道 Hertz 版本号在哪里获取、版本说明去哪里看。
- 避开常量拼写、Header 规范化、MIME 带 charset 等细节坑。

## 前置知识

- 已能编写基本 Hertz Handler 与路由。
- 了解 Go 常量、`map[string]interface{}`、`net` 包基础。
- 知道 HTTP 方法、状态码、Content-Type 的基本语义。

## 1. HTTP 常量：pkg/protocol/consts

```go
import (
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)
```

### 1.1 请求方法

```go
const (
	MethodGet     = "GET"
	MethodHead    = "HEAD"
	MethodPost    = "POST"
	MethodPut     = "PUT"
	MethodPatch   = "PATCH"
	MethodDelete  = "DELETE"
	MethodConnect = "CONNECT"
	MethodOptions = "OPTIONS"
	MethodTrace   = "TRACE"
)
```

用法：

```go
h.Handle(consts.MethodPost, "/v1/orders", createOrder)
if string(c.Method()) == consts.MethodGet {
	// ...
}
```

### 1.2 状态码

```go
c.JSON(consts.StatusOK, utils.H{"ok": true})                       // 200
c.String(consts.StatusBadRequest, "invalid param")                 // 400
c.String(consts.StatusNotFound, "not found")                       // 404
c.String(consts.StatusTooManyRequests, "rate limited")            // 429
c.String(consts.StatusInternalServerError, "internal error")      // 500
c.String(consts.StatusBadGateway, "bad gateway")                  // 502
```

状态码常量覆盖了 RFC 7231 等规范中的常见值；需要状态码对应的默认文本时，可用 `consts.StatusMessage(code int) string`。

### 1.3 MIME 与 Content-Type

```go
c.Response.Header.SetContentType(consts.MIMEApplicationJSON)        // application/json
c.Response.Header.SetContentType(consts.MIMEApplicationJSONUTF8)    // application/json; charset=utf-8
c.Response.Header.SetContentType(consts.MIMETextPlainUTF8)          // text/plain; charset=utf-8
c.Response.Header.SetContentType(consts.MIMEApplicationOctetStream) // 下载
```

常用常量：

| 常量 | 值 |
| --- | --- |
| `MIMEApplicationJSON` | `application/json` |
| `MIMEApplicationJSONUTF8` | `application/json; charset=utf-8` |
| `MIMEApplicationHTMLForm` | `application/x-www-form-urlencoded` |
| `MIMEMultipartPOSTForm` | `multipart/form-data` |
| `MIMEApplicationOctetStream` | `application/octet-stream` |
| `MIMETextHTML` | `text/html` |
| `MIMETextPlainUTF8` | `text/plain; charset=utf-8` |

注意 `MIMEApplicationJSON` **不带** charset，而 `c.JSON` 实际返回的是 `application/json; charset=utf-8`。如果测试里断言 Content-Type，要确认用的是哪一个。

### 1.4 Header 常量

```go
c.Response.Header.Set(consts.HeaderContentType, consts.MIMEApplicationJSON)
c.Response.Header.Set("Cache-Control", "no-store") // 该 Header 无专用常量
c.Request.Header.Get(consts.HeaderAuthorization)
c.Request.Header.Get(consts.HeaderUserAgent)
```

常量能避免拼写错误，也方便全局搜索。部分常量还提供小写版本（如 `HeaderServerLower`），用于需要精确控制的场景。

## 2. 实用工具：pkg/common/utils

### 2.1 `utils.H`：快速构造 JSON

```go
type H map[string]interface{}

func handler(ctx context.Context, c *app.RequestContext) {
	c.JSON(consts.StatusOK, utils.H{
		"code":    0,
		"message": "ok",
		"data":    utils.H{"id": 1},
	})
}
```

适合 demo、健康检查、错误响应。正式 API 建议用 struct，获得类型安全与文档生成能力。

### 2.2 环境变量与网络

```go
import "github.com/cloudwego/hertz/pkg/common/utils"

// 读取布尔环境变量，兼容 "1" / "true" 等写法
debug, err := utils.GetBoolFromEnv("APP_DEBUG")
if err != nil {
	// 值非法
}

// 获取本机非回环 IPv4，常用于注册中心上报
ip := utils.LocalIP()

// 补全端口：AddMissingPort("example.com", true) -> "example.com:443"
addr := utils.AddMissingPort("example.com", true)
```

### 2.3 路径与字符串

```go
// 规范化 URL 路径，处理 . / .. // 等
p := utils.CleanPath("/a//b/../c") // "/a/c"

// 大小写不敏感比较（Header 名等场景）
same := utils.CaseInsensitiveCompare([]byte("Content-Type"), []byte("content-type"))

// 取函数名，便于中间件/日志标注
name := utils.NameOfFunction(myHandler)

// 内部断言，条件不满足会 panic，仅适合"不可能发生"的编程错误
utils.Assert(len(data) > 0, "data must not be empty")
```

### 2.4 高效拷贝

```go
// 零分配地把 reader 拷贝到 network.Writer（Hertz 的响应 writer 实现了该接口）
n, err := utils.CopyZeroAlloc(c.Response.BodyWriter(), src)
```

处理大文件或代理转发时，比 `io.Copy` 更贴合 Hertz 的 writer 抽象。普通业务无需关心，框架内部已大量使用。

### 2.5 其他

- `utils.ParseChunkSize` / `utils.SkipCRLF`：chunked 解析辅助，主要在协议扩展中使用；
- `utils.NewNetAddr`：快速构造 `net.Addr`；
- `utils.TLSRecordHeaderLooksLikeHTTP`：判断首包是否像 HTTP，用于协议嗅探；
- `utils.FilterContentType`：从 Content-Type 中提取 MIME 主类型。

这些偏底层，业务代码通常用不到，但读框架源码时会遇到。

## 3. Server 配置默认值速查

完整列表见官方配置参考，以下是高频项（v0.10.6 源码默认值）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `server.WithHostPorts` | `:8888` | 监听地址 |
| `server.WithNetwork` | `tcp` | 支持 `tcp` / `udp` / `unix` |
| `server.WithReadTimeout` | 3 分钟 | 读超时 |
| `server.WithWriteTimeout` | 0 | 写超时，0 表示不限制 |
| `server.WithIdleTimeout` | 3 分钟 | 空闲超时，默认与读超时一致 |
| `server.WithKeepAliveTimeout` | 1 分钟 | keep-alive 连接空闲时间 |
| `server.WithMaxRequestBodySize` | 4MB | 请求体上限 |
| `server.WithMaxHeaderBytes` | 1MB | 请求头上限 |
| `server.WithExitWaitTime` | 5 秒 | 优雅退出最长等待 |
| `server.WithStreamBody` | false | 是否流式读取请求体 |
| `server.WithHandleMethodNotAllowed` | false | 是否返回 405 |
| `server.WithSenseClientDisconnection` | false | 是否感知客户端断开 |
| `server.WithALPN` / `server.WithH2C` | false | HTTP/2 相关开关 |

生产环境几乎一定要显式设置 `ReadTimeout`、`MaxRequestBodySize`、`ExitWaitTime`，不要依赖默认值。

## 4. 版本号与版本说明

Hertz 根包暴露了版本常量：

```go
import "github.com/cloudwego/hertz"

fmt.Println(hertz.Name, hertz.Version) // Hertz v0.10.6
```

排查线上问题时，把版本打进启动日志或 `/version` 接口，能省很多沟通成本。

查版本变更的三个入口：

1. 官方文档的版本说明 / Release Notes 页面；
2. GitHub 仓库的 `changelog/` 目录（每个版本一个文件）；
3. `go list -m -versions github.com/cloudwego/hertz` 查看可用版本，`go.mod` 锁定实际版本。

升级前先读 changelog 中的 **Breaking Changes**，尤其是选项重命名、默认值调整、扩展包版本联动。

## 常见坑

1. **手写字符串 `"GET"`、`"application/json"`**：容易拼错且难以全局替换，统一用 `consts`。
2. **把 `MIMEApplicationJSON` 当成带 charset**：`c.JSON` 实际是 `application/json; charset=utf-8`，测试断言要一致。
3. **Header 名大小写焦虑**：Hertz 默认会规范化 Header 名，读取时用常量即可；特殊场景才需要 `DisableHeaderNamesNormalizing`。
4. **`utils.H` 用在正式 API**：无类型约束、字段名易错、无法生成文档；正式接口用 struct。
5. **`utils.Assert` 当业务校验**：它失败会 panic，只能用于"绝不可能发生"的内部不变量。
6. **依赖默认配置上线**：默认 4MB body、5 秒退出等待不一定符合业务，必须显式配置。
7. **升级不读 changelog**：小版本也可能调整默认值与扩展兼容性，升级前务必核对。
8. **混淆框架版本与扩展版本**：`hertz-contrib/*` 有独立版本号，排查问题要同时提供两者。

## 小结

- `consts` 提供方法、状态码、MIME、Header 常量，是消灭魔法字符串的第一选择。
- `utils` 提供 `H`、环境变量、IP、路径、零分配拷贝等工具，偏底层但关键时刻很有用。
- Server 默认值要心里有数，生产必须显式设置超时、body 上限、退出等待。
- 版本号用 `hertz.Version` 获取，变更看官方版本说明与 GitHub changelog。
- 正式 API 用 struct，不用 `utils.H`；测试断言注意 MIME 的 charset 差异。

## 练习

1. 把项目中所有手写的 `"application/json"`、`"GET"` 替换为 `consts` 常量，并确保测试通过。
2. 写一个 `/version` 接口，返回 `hertz.Name` 与 `hertz.Version`。
3. 用 `utils.GetBoolFromEnv` 实现一个开关，控制是否注册 pprof 路由。
4. 用 `utils.LocalIP` 与 `utils.AddMissingPort` 实现服务启动时打印可访问地址。
5. 对照官方配置参考，为你现有的服务补齐 `ReadTimeout`、`MaxRequestBodySize`、`ExitWaitTime` 三项配置并说明取值依据。
