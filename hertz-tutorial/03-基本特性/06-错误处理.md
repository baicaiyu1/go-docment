# 错误处理

> 一句话定位：Hertz 用 `c.Error` 把错误挂到请求错误链上，再用统一的错误处理中间件输出固定的 JSON 结构；panic 则交给 Recovery 兜底。

## 本篇目标

- 理解 Hertz 的 `Error`、`ErrorType`、`ErrorChain`。
- 会用 `c.Error(err)` 收集错误，并通过 `c.Errors` 统一读取。
- 设计“HTTP 状态码 + 业务码 + 消息”的分层错误结构。
- 实现全局错误处理中间件与 panic 恢复，避开常见误区。

## 前置知识

- 了解 Go 的 `error` 接口与 `errors.Is` / `errors.As`。
- 已完成 `03-基本特性/05-中间件`。
- 知道 HTTP 4xx / 5xx 的语义。

## Hertz 的错误模型

```go
type Error struct {
	Err  error       // 标准错误
	Type ErrorType   // 错误类型
	Meta interface{} // 错误元数据
}

const (
	ErrorTypeBind   ErrorType = 1 << iota // 绑定错误
	ErrorTypeRender                       // 渲染错误
	ErrorTypePrivate                      // 框架内部错误
	ErrorTypePublic                       // 需外部感知的错误
	ErrorTypeAny                          // 其他
)
```

创建错误：

```go
c.Error(errors.New("db timeout"))                    // 普通错误
c.Error(errors.NewPublic("user not found"))          // 公开错误
c.Error(errors.NewPrivate("cache miss"))             // 私有错误
```

`c.Error` 只把错误追加到 `c.Errors`，**不会中断 handler，也不会自动写响应**。

## ErrorChain

| 方法          | 作用                 |
| ----------- | ------------------ |
| `Errors()`  | 转成 `[]string`，适合日志 |
| `String()`  | 可读文本               |
| `Last()`    | 最后一个错误，通常是根因       |
| `ByType(t)` | 按类型筛选              |
| `JSON()`    | 转成 JSON 友好结构       |

```go
c.Error(errors.New("first"))
c.Error(errors.New("second"))
hlog.Errorf("all=%v last=%v", c.Errors.Errors(), c.Errors.Last().Err)
```

## 自定义业务错误

```go
type BizError struct {
	HTTPStatus int    // 对外 HTTP 状态码
	Code       int    // 业务错误码
	Message    string // 对外消息
}

func (e *BizError) Error() string { return e.Message }

func NewBizError(status, code int, msg string) *BizError {
	return &BizError{HTTPStatus: status, Code: code, Message: msg}
}

var (
	ErrInvalidParam = NewBizError(400, 40001, "invalid param")
	ErrUnauthorized = NewBizError(401, 40101, "unauthorized")
	ErrUserNotFound = NewBizError(404, 40401, "user not found")
)
```

错误码分层：

| 层级       | 示例                    | 说明                 |
| -------- | --------------------- | ------------------ |
| HTTP 状态码 | 400 / 401 / 404 / 500 | 传输语义               |
| 业务码      | 40001 / 40101 / 40401 | 5 位数字，前 3 位对齐 HTTP |
| 消息       | `user not found`      | 对外可读，不暴露内部细节       |
| 元数据      | `Meta`                | 字段名、追踪 ID，仅日志使用    |

## 全局错误处理中间件

handler 只负责 `c.Error(err)` 并 `return`，中间件在 `c.Next` 返回后统一写响应：

```go
func ErrorHandler() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		c.Next(ctx)
		if len(c.Errors) == 0 {
			return
		}
		err := c.Errors.Last().Err
		var biz *BizError
		if stderrors.As(err, &biz) {
			c.AbortWithStatusJSON(biz.HTTPStatus, utils.H{"code": biz.Code, "message": biz.Message})
			return
		}
		hlog.Errorf("unhandled error: %v", err)
		c.AbortWithStatusJSON(consts.StatusInternalServerError,
			utils.H{"code": 50001, "message": "internal server error"})
	}
}
```

约定：

- `c.Error` 后必须 `return`，不要再写响应。
- 错误中间件必须在业务路由之前注册。
- 内部错误只进日志，对外统一消息。

## 关于 server.WithErrorHandler

网上不少文章会写 `server.Default(server.WithErrorHandler(...))`，但 Hertz v0.10.6 的 `server` 包中并没有这个选项。本教程基线版本请使用上面的“错误处理中间件 + `c.Errors`”。升级到提供该选项的版本时，把 `ErrorHandler` 的函数体搬进去即可。

## 统一响应结构

```go
type APIResponse struct {
	Code    int    `json:"code"`
	Message string `json:"message"`
	Data    any    `json:"data,omitempty"`
	TraceID string `json:"trace_id,omitempty"`
}

func OK(c *app.RequestContext, data any) {
	c.JSON(consts.StatusOK, APIResponse{Code: 0, Message: "ok", Data: data})
}
```

成功用 `code=0`，失败用非零业务码；HTTP 状态码继续表达传输层语义。

## 错误分类处理

- **预期错误**（参数错误、未授权、资源不存在）→ `BizError`。
- **非预期错误**（DB 失败、空指针）→ `fmt.Errorf("repo.Find: %w", err)`，由中间件统一 500。
- **绑定错误** → 映射 400，不要走 500：

```go
if err := c.BindAndValidate(&req); err != nil {
	c.Error(NewBizError(400, 40001, err.Error()))
	return
}
```

用 `%w` 包装保留错误链，中间件用 `errors.As` 识别类型。

## panic 与 Recovery

panic 用于“程序不该继续”的场景；业务可预期错误不要用 panic。

`server.Default()` 自带 Recovery；`server.New()` 需要自己注册，并放在中间件链最外层：

```go
h.Use(recovery.Recovery(
	recovery.WithRecoveryHandler(func(ctx context.Context, c *app.RequestContext, err interface{}, stack []byte) {
		hlog.SystemLogger().CtxErrorf(ctx, "[Recovery] panic=%v\n%s", err, stack)
		c.AbortWithStatusJSON(consts.StatusInternalServerError,
			utils.H{"code": 50001, "message": "internal server error"})
	}),
))
```

堆栈只记录到日志，响应体保持统一结构。

## 完整示例

```go
package main

import (
	"context"
	stderrors "errors"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/middlewares/server/recovery"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/common/hlog"
	"github.com/cloudwego/hertz/pkg/common/utils"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

type BizError struct {
	HTTPStatus int
	Code       int
	Message    string
}

func (e *BizError) Error() string { return e.Message }

var ErrUserNotFound = &BizError{HTTPStatus: 404, Code: 40401, Message: "user not found"}

func ErrorHandler() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		c.Next(ctx)
		if len(c.Errors) == 0 {
			return
		}
		err := c.Errors.Last().Err
		var biz *BizError
		if stderrors.As(err, &biz) {
			c.AbortWithStatusJSON(biz.HTTPStatus, utils.H{"code": biz.Code, "message": biz.Message})
			return
		}
		hlog.Errorf("unhandled error: %v", err)
		c.AbortWithStatusJSON(consts.StatusInternalServerError,
			utils.H{"code": 50001, "message": "internal server error"})
	}
}

func main() {
	h := server.New(server.WithHostPorts("127.0.0.1:8080"))
	h.Use(
		recovery.Recovery(recovery.WithRecoveryHandler(
			func(ctx context.Context, c *app.RequestContext, err interface{}, stack []byte) {
				hlog.SystemLogger().CtxErrorf(ctx, "panic: %v\n%s", err, stack)
				c.AbortWithStatusJSON(consts.StatusInternalServerError,
					utils.H{"code": 50001, "message": "internal server error"})
			},
		)),
		ErrorHandler(),
	)

	h.GET("/users/:id", func(ctx context.Context, c *app.RequestContext) {
		if c.Param("id") == "0" {
			c.Error(ErrUserNotFound)
			return
		}
		c.JSON(consts.StatusOK, utils.H{"code": 0, "data": utils.H{"id": c.Param("id")}})
	})
	h.GET("/panic", func(ctx context.Context, c *app.RequestContext) {
		panic("boom")
	})

	h.Spin()
}
```

curl.exe -i http://127.0.0.1:8080/users/1

## 常见坑

1. **照抄 `server.WithErrorHandler`**：v0.10.6 没有该选项，编译失败；用错误处理中间件。
2. **`c.Error` 后继续写响应**：错误链不会自动中止，必须 `return`。
3. **先写响应再 `c.Error`**：中间件再写会追加 Body，响应非法。
4. **用 `==` 比较错误**：包装后的错误不是同一实例，用 `errors.As` / `errors.Is`。
5. **把内部错误返回客户端**：会泄露 SQL、路径、依赖地址。
6. **Recovery 返回堆栈**：堆栈只进日志。
7. **错误中间件注册太晚**：前面的路由不会经过它。

## 小结

- `c.Error` 收集错误，`c.Errors` 读取错误链，错误中间件统一输出。
- 业务错误用自定义结构体承载 HTTP 状态码、业务码和消息；非预期错误统一 500。
- panic 交给 Recovery，堆栈只进日志。
- v0.10.6 没有 `server.WithErrorHandler`，不要被旧文章误导。
